# Bishudeck

AI が生成した HTML スライドを、CSS も JavaScript もそのまま再現したまま
PowerPoint のように編集できるデスクトップアプリ(Tauri v2 + React + TypeScript)。

[![CI](https://github.com/TominagaTeam/bishudeck/actions/workflows/ci.yml/badge.svg)](https://github.com/TominagaTeam/bishudeck/actions/workflows/ci.yml)

![Bishudeck の編集画面。スライドの見出しを選ぶと、右のインスペクタに文字書式と位置・サイズが出る](docs/images/screenshot.png)

## できること

- **AI がつくった HTML スライドをそのまま開く** — Claude Artifacts の standalone 書き出し・
  reveal.js・impress.js・Swiper・素の HTML を取り込み、1 枚ずつのスライドに分割する。
  どう分割したかは取り込み前に確認できる
- **PowerPoint の感覚で直す** — 要素をクリックして選び、ドラッグで動かし、ダブルクリックで
  文字を打ち替える。整列・重ね順・複製・コピー & ペースト・Undo / Redo も同じ操作感で使える
- **デッキの CSS と JavaScript を壊さない** — 編集はインラインの上書きだけで行い、元の CSS には
  触らない。エディタが解釈できない要素も、触らなければそのまま残る
- **書き出すのは 1 枚の HTML** — 独自のプロジェクト形式を持たない。読み込んだものと
  同じ形で書き戻すので、書き出したファイルはブラウザでそのまま開ける
- **そのままプレゼンできる** — 再生ウィンドウで全画面表示。こちらでは JavaScript も動く

## 動かす

配布しているのはソースだけなので、手元でビルドして使う。

必要なもの: **Node.js 22 以降**、**Rust**、それと
[Tauri v2 の前提条件](https://v2.tauri.app/start/prerequisites/)
(macOS なら Xcode Command Line Tools、Windows なら MSVC ビルドツール)。

```bash
git clone https://github.com/TominagaTeam/bishudeck.git
cd bishudeck
npm install
npm run tauri build
```

`src-tauri/target/release/bundle/` に `.app` / `.dmg` / `.msi` ができる。

起動すると使い方を説明する 11 枚のガイドが開くので、そこから触りはじめられる。

## 画面の使い方(編集まわり)


- **起動するとガイドが開いている**: アプリを起動すると、使い方を説明する
  11 枚のサンプルデッキが読み込まれた状態で立ち上がる。書いてある文はすべて
  普通の要素なので、そのまま選んで動かして打ち替えられる。書き出し先は
  持たないので、触らずに閉じても何も聞かれないし、勝手に保存もされない。
  自分の HTML を取り込めば置き換わる(消す操作は要らない)。
  デッキの実体は `src/app/welcomeDeck.html`
  ([features/welcome-deck](docs/features/welcome-deck/design.md))
- **要素を選ぶ**: クリックで選択。**選べるのは 1 つずつ**(複数選択は無い)。
  スライドの余白や、スライドいっぱいに
  広がっているもの — レイアウト全体を覆うラッパー、全面に敷いた背景レイヤー
  (`position:absolute; inset:0` の空の `div`)、四辺からわずかに内側の
  ラッパー — をクリックしても「スライド大の要素」は選ばれない(選択解除)。
  中身を持つもの(画像・動画・自前の文字を持つ要素)は
  大きさに関係なく選べる。背景レイヤー自体を選びたいときはパンくずから辿る。
  パンくずにスライドそのものは並ばない(スライドはキャンバスであって
  オブジェクトではないため)。Esc で 1 階層外へ、いちばん外まで来たら選択解除
- **要素を並べる / 複製する**: ツールバーの「配置」から、スライドに対する整列
  (左揃え・左右中央 など)・重ね順(⌘] / ⌘[)・複製(⌘D)を行う。複製は元の要素のすぐ隣に
  16px ずらして入る
- **要素をコピーする / 切り取る / 貼り付ける**: ⌘C / ⌘X / ⌘V(右クリックからも)。
  **貼り付け先は「選んでいる要素の隣」** — 同じ親に入るので、grid のセルや
  `.container .card` のように**親が塗っている**箱も見た目そのままで増える。
  選択を外して貼ると、スライドの上に直接置かれる。
  位置は元のまま入り、**元がまだそこに居るときだけ** 16px ずらして重ならないようにする
  (別のスライドへ貼るときと、切り取ったものを貼るときは元の位置ちょうど)
- **パンくずでどれを指しているか確かめる**: インスペクタのパンくず(`div.inner › h2`)に
  マウスを乗せる、またはタブで移動すると、その要素がステージ上に破線の枠で出る。
  クリックする前にどの箱か分かるので、ラッパーが何重にもあるデッキでも
  当てずっぽうに選び直さずに済む。選択中の項目には出ない(すでに選択枠がある)
- **文字を直す**: 要素をダブルクリックで文字編集に入る。キャレットは
  クリックした位置に入り、その語が選択される。編集中は選択枠の見た目が変わる。
  抜けるのは ①枠の外のクリック(スライド上でも、ツールバーやパネルでもどこでも)
  ②Esc(フォーカスがアプリ側にあるとき)。抜けたあとは要素の選択が残るので、
  そのまま矢印キーで動かせる。インスペクタの「文字書式」だけは例外で、
  触っても編集は続く(フォントや色を選んでいる間に選択範囲は失われない)
- **箱に画像を入れる**: 取り込んだデッキが持っている写真枠(破線の箱に
  「写真添付エリア: …」と書いてあるもの)は、**画像ファイルをその上に落とす**か、
  **右クリックして「画像を入れる」を選ぶ**と写真が入る。インスペクタの
  「画像 › 画像を入れる」も同じことをする。写真枠に限らず、**文字も画像も持たない箱**なら
  どれでも同じように入れられる(その箱の中身が画像に置き換わる。Undo 1 回で戻る)。
  デッキ本来のドロップ機能そのものは取り込みの時点で失われている
  (動かすにはデッキを作った環境のランタイムが要る)ので、これはその代わり
- **アプリの配色を変える**: ステータスバー右端の「テーマ」で ライト(既定) / ダーク /
  システム(OS に追従)を選ぶ。**変わるのはアプリ自身の見た目だけ**で、スライド・
  選択枠・ハンドル・再生画面・書き出す HTML はどれも変わらない。選んだ配色は
  ペイン幅と同じくこの端末に残る(デッキには入らない)
- **背景を塗る / 透明にする**: インスペクタの「ボックス › 背景」で
  「透明」か「単色」を選び、色を指定する。塗りの無いボックスは「透明」が
  選ばれた状態で出る(色見本だけだと、塗っていない箱が黒く塗ってあるように
  見えてしまうため)。色を選べばそのまま「単色」に切り替わり、「透明」に
  戻しても選んだ色は覚えている。「透明」はデッキ自身の CSS が塗っている
  背景も消す(上書きとして書くため)、「解除」は上書きをやめてデッキ本来の
  見た目に戻す
- **枠線を付ける**: 要素を選んでインスペクタの「枠線」から、種類(なし / 実線 /
  破線 / 点線)・色・太さ(px)を指定する。PowerPoint の「図形の枠線」と同じ感覚で、
  付け外しは 1 回の Undo で戻る。「なし」はデッキ自身の CSS が描いている枠線も
  消す(上書きとして書くため)、「解除」は上書きをやめてデッキ本来の見た目に戻す。
  枠線が無いボックスでも、色や太さを指定すればそのまま実線が付く。
  **太さはスライダーを動かすとその場で太さが変わる**(数値入力も 1 文字ごとに
  反映される)。ドラッグや入力をまとめて 1 回の Undo で戻せる。
- **位置とサイズを数値で決める**: インスペクタの「位置とサイズ」に X / Y / 幅 / 高さ / 回転を打つと
  **1 文字打つたびにステージへ反映される**。上下の矢印(スピナー)で 1 ずつ動かしても同じ。
  打っているあいだの変更はまとめて 1 回の Undo で打つ前に戻る。
  余白・角丸・文字サイズ・枠線の太さも同じ挙動で、確定操作を待つ数値欄はもう無い
- **フォントを変える**: インスペクタの「テキスト › フォント」が要素全体、
  「文字書式 › フォント」が選択した文字だけに効く。一覧にはこの環境に
  実際に入っているフォントだけが出る。**例外は Noto Sans と Noto Sans JP で、
  この 2 つはアプリが同梱している**ので、どの環境でも必ず出る(既定は `既定(Noto Sans)`)。
  書き出した HTML を別の機械で開いたときは、その環境のシステム書体に落ちる
- **ショートカットを調べる**: ツールバー右の「ヘルプ」(⌘/、Windows は Ctrl+/ か F1)で
  一覧が開く。表記は実行環境に合わせて出るが、
  タブで Mac / Windows を切り替えて確かめられる。キーは PowerPoint に合わせてあり、
  macOS でも Ctrl は ⌘ の代わりに使える
- **ペインの幅**: キャンバスの左右にある境界をドラッグすると幅が変わる
  (スライド一覧は 160–480px、インスペクタは 240–520px)。境界のシェブロンを
  クリックするとそのペインを隠し、もう一度で戻る(ダブルクリックでも同じ)。
  幅と開閉状態は左右それぞれ次回起動時にも残る

## 保存の挙動


扱うのは HTML だけ。専用のプロジェクト形式はなく、「取り込む」で HTML を読み、
「書き出し」で HTML を書く。保存＝書き出しなので、⌘S も自動保存も同じ経路を通る。

書き出し先が決まっているデッキは、編集の手が 2 秒止まると同じ HTML へ自動保存
される。書き込みは一時ファイル経由の atomic rename なので、途中で落ちても直前の
版は残る。ステータスバーに「変更あり / 書き出し済み HH:MM」を出す。

書き出し先が未設定(取り込んだだけ)のデッキは勝手に書き出さない。取り込み元の
HTML を黙って上書きしないのも同じ理由で、書き出し先は最初の書き出しでユーザー
が決める。未書き出しのままウィンドウを閉じようとしたときだけ確認ダイアログを
出す。選べるのは「書き出して終了」「書き出さずに終了」「終了をキャンセル」の 3 つで、
Esc はキャンセルと同じ。× を押し間違えただけなら、そのまま作業に戻れる。

## ファイル形式


書き出すのは 1 枚の HTML ファイル。取り込んだ画像などは、その HTML と同じ階層の
`assets/` に並べて置かれる。

```
presentation.html   デッキ本体(元の head・body・シェルごと再現)
assets/*            取り込んだ画像等
```

### Claude Artifacts の standalone HTML

Artifacts の「standalone」書き出しは、中身が JSON で埋め込まれた自己展開型のローダー
なので、取り込み時に素の HTML へ戻してから分割する(詳細は
[features/import-pipeline](docs/features/import-pipeline/design.md))。`<deck-stage>` のデッキは
**スライド 1 枚 = `<section>` 1 個**として認識され、デッキが宣言しているステージサイズ
(1920×1080 等)もそのまま引き継ぐ。

- 埋め込みフォントは、デッキが実際に使う文字を覆う分だけ残して `data:` で HTML に同梱する
- デッキを**組み立てる**ランタイム(x-dc / React)は取り込まない。代わりに
  **描くはずだった結果を取り込み時に静的な HTML へ畳み込む** — `{{ 変数 }}` は
  コンポーネントが宣言している既定値になり、`<image-slot>` の写真枠は同じ見た目の
  プレースホルダになる。どちらもそのまま編集できる普通の要素なので、上から書き換えれば済む
- デッキを**プレゼンする**ランタイム(`<deck-stage>`)は逆に保持する。編集中は出さず
  (キャンバスは 1 枚を描き、サムネイルは左ペインが持つ)、**書き出す HTML にだけ戻す**ので、
  書き出したファイルは元の standalone と同じく 1 枚ずつ・左サムネイル・矢印キー送りで開く

### テスト

自動テストは **Vitest**(フロント / jsdom)と **`cargo test`**(Rust)の 2 つ。
E2E(smoke)は 2026-08-25 に廃止した
([ADR-0009](docs/adr/0009-drop-smoke-e2e.md))。合否は結局どれも手で触って決めていたため。

そのぶん、**実ブラウザでしか見えないもの** —— iframe 境界の実挙動・実マウスの
ジェスチャ・レイアウトの実寸・フォーカスの移動 —— は `npm run tauri dev` で
起動して手で確認する。jsdom はすべての矩形が 0 なので、そこは自動では捕まえられない。
何を見るかのチェックリストは [`docs/rules/development.md`](docs/rules/development.md) §2、
方針は [`docs/basic-design/08-test-policy.md`](docs/basic-design/08-test-policy.md)。

`samples/generic-deck.html` に動作確認用のスライド(CSS アニメーション +
カウントアップ JS)を置いてある。「HTML を取り込む」から読み込める。
うまく表示できないデッキに当たったら、その HTML をそのまま取り込んで
検出・分割・可視性・サムネイル収まりを見るのが早い。厄介なパターンは実物にしか出てこない。

### 設計の要点

判断の根拠は ADR に、詳細は各章にある。ここは索引。

| # | 要点 | 詳細 |
|---|---|---|
| 1 | **HTML そのものが正データ** — 独自 JSON モデルに変換しない。エディタが解釈できない要素・CSS・スクリプトも「触らなければ壊れない」 | [ADR-0001](docs/adr/0001-html-as-source-of-truth.md) |
| 2 | **編集モードとプレビューモードを分ける** — JS が DOM を書き換える環境で WYSIWYG 編集は原理的に成立しないため。**既定は編集モード** | [ADR-0002](docs/adr/0002-edit-preview-separation.md) / [10-security](docs/basic-design/10-security.md) |
| 3 | **すべての変更は Command 経由** — Undo/Redo だけでなく、将来のプラグイン・AI 連携・共同編集がこの 1 つの継ぎ目に乗る。要素は uid で指す | [ADR-0003](docs/adr/0003-all-edits-as-commands.md) |
| 4 | **スタイル編集はオーバーライド** — 元の CSS を書き換えず inline style として最小差分を載せる。AI 生成 HTML の flex / grid / absolute 混在レイアウトを壊さないため | [ADR-0004](docs/adr/0004-style-edits-as-overrides.md) |
| 5 | **画像のトリミングは枠と画像の 2 矩形** — PowerPoint と同じ。はみ出した部分は隠れるだけで捨てない。枠かどうかは印ではなく**形**で判定するので手書き HTML もトリミングでき、書き出しを読み直しても同じ状態に戻る | [features/image-crop](docs/features/image-crop/design.md) |
| 6 | **フォントは実在するものだけ出す** — 無い書体を選べると、ブラウザが黙って別の書体に差し替えたまま気付けないため | [editing-engine](docs/features/editing-engine/design.md) |

モードごとの構成:

| | 編集モード | プレビュー / 再生 |
| --- | --- | --- |
| iframe | `srcdoc` + `sandbox="allow-same-origin"` | `slides://` 配信 + `sandbox="allow-scripts"` |
| JavaScript | ブラウザが実行を保証しない(sandbox に `allow-scripts` なし) | 完全実行 |
| CSS | 完全適用 | 完全適用 |
| DOM 操作 | ホストから直接可能 | 不要 |

再生ウィンドウの操作は ←/→(↑/↓・PageUp/PageDown・Space も同じ)、Home / End、
Esc で終了、それとスライドのクリック(左半分で前・右半分で次)。別オリジンの
iframe にフォーカスが落ちるとキーがホストに届かなくなるため、再生中はステージの
上に透明なシールドを敷いている。引き換えに、再生中はデッキ内のボタン・リンクを
押すことはできない。詳細は [04-architecture](docs/basic-design/04-architecture.md)。

### 構成

```
src/
  core/      document(モデル・ストア・合成) / commands(エンジン・履歴) / editing / selection / events
  stage/     bridge(iframe DOM への唯一の窓口) / EditStage / PreviewStage / Overlay / ジェスチャ
  import/    パイプライン + Detector 群(reveal / deck-stage / impress / swiper / 汎用 / fullpage / 単一)
  features/  Toolbar / SlideList / PaneDivider / Inspector / StatusBar / 各種ダイアログ
  shared/    バックエンド境界 / フォントカタログ(fonts.ts) / ショートカット定義(shortcuts.ts) / UI 文言カタログ(i18n/) / テーマ(theme.ts)
  app/       App shell / Present(再生ウィンドウ) / 自動保存 / 各種アクション / 起動時のガイドデッキ
src-tauri/
  protocol.rs  slides:// スキーム
  commands/    project(HTML の読み書き) / preview / assets / window
```

Rust 側は HTML を一切解釈しない。ファイル I/O・アセット配信・プレビュー公開
(合成済みの HTML を預かって `slides://` の URL を返す)・ウィンドウ管理の 4 つに
徹し、HTML の知識はすべて WebView 側に置いている(二重実装を避けるため)。
預かった HTML も中身は読まず、文字列のまま配るだけ。

新しいファイルの置き場所は [05-directory](docs/basic-design/05-directory.md) の「配置ルール」表に従う。
