# ADR-0001: Source of Truth は HTML(DOM)そのもの

- **日付**: 2026-08-18
- **状態**: 採用

## 背景

AI が生成した HTML スライドを PowerPoint のように編集したい。
一般的なスライドエディタは内部に独自のデータモデル(スライド・シェイプ・テキストの JSON)を持ち、
インポート時にそこへ変換する。この方式をこのアプリで採ると、
任意の HTML/CSS/JS を表現しきれず、往復のたびに再現性が壊れる。

## 選択肢

1. **独自 JSON モデルへ変換** — 編集機能を作りやすく型も付けやすいが、
   モデルが表現できない CSS・スクリプト・カスタム要素は変換時に失われる
2. **HTML フラグメント文字列を正データにする** — エディタが理解できない構造もそのまま保持できるが、
   編集操作を DOM 操作として書く必要があり、型による保護が効きにくい

## 決定

案 2 を採る。

- スライドの正データは **HTML フラグメント文字列**
- 編集は「ロードした DOM への操作」として表現し、保存時に DOM をシリアライズする
- エディタが付与する属性(`data-hse-uid` 等)はシリアライズ時に完全除去する
  (文書全体で何を残してよいかは [../features/import-pipeline/design.md](../features/import-pipeline/design.md) の「書き出しに残してよいもの」を参照)

## 理由

このアプリの価値は「エディタが解釈できない CSS・JS・要素も、**触らなければ壊れない**」ことに尽きる。
モデル変換は「解釈できたものだけが生き残る」構造で、価値そのものと相反する。
型の保護を失う代償は、シリアライズの往復テスト([../../src/core/document/roundTrip.test.ts](../../src/core/document/roundTrip.test.ts))で埋める。

## 影響

- 独自 JSON モデルへの変換を今後も導入しない
- 「往復で HTML が変わらない」ことが最重要の回帰テスト対象になる
- Rust 側で HTML を解釈すると知識が二重化するため、HTML の知識は WebView 側に集約する
