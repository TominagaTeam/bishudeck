# ADR-0002: 編集モードとプレビューモードの分離

- **日付**: 2026-08-18
- **状態**: 採用

## 背景

取り込んだデッキの JS を動かしたまま WYSIWYG 編集をしたい。
しかし JS が DOM を書き換える一方でユーザーも書き換えるため、
1 つの実行系で「完全再現」と「安全な編集」を両立させようとすると原理的に破綻する。

## 選択肢

1. **JS を動かしたまま編集する** — 見た目は常に本番と同じだが、
   編集結果がデッキ側スクリプトに上書きされ、何が保存されるか予測できない
2. **編集中だけ JS を止め、確認は別モードで行う** — 編集は安定するが、
   アニメーション等の動的な結果は編集画面では見えない

## 決定

案 2 を採る。モードごとに iframe の構成を変える。

| | 編集モード | プレビュー / 再生モード |
| --- | --- | --- |
| JS 実行 | **停止**(sandbox が保証) | **完全実行** |
| CSS | 完全適用(アニメーション含む) | 完全適用 |
| DOM アクセス | ホストから直接操作(same-origin) | 不要 |
| iframe 構成 | `srcdoc` + `sandbox="allow-same-origin"` | **カスタムプロトコル配信 = 別オリジン** + `sandbox="allow-scripts"` |

**既定は編集モード**。取り込み直後・プロジェクトを開いた直後も編集モードで開く。

## 理由

- 編集モードの `sandbox="allow-same-origin"`(= `allow-scripts` を**与えない**)が要。
  スクリプト不実行を**ブラウザが保証**しつつ、親からは `contentDocument` を直接触れる。
  `<script>` の `type` 書き換えとイベントハンドラ属性の退避は、保存時の復元用と多層防御を兼ねる
- プレビューは `slides://` カスタムプロトコルで配信して**別オリジン化**する。
  `allow-scripts` を与えても `allow-same-origin` が無ければ sandbox 脱出・Tauri API 到達は不可
- 既定をプレビューにすると、デッキを読み込むたびに触り始める前の 1 クリックを強いる。
  このアプリの目的は編集であって、プレビューは結果を確かめに行く先

## 影響

- この 2 つの sandbox 属性の組み合わせを**入れ替えてはならない**(片方でも交換すると安全性か編集性が崩れる)
- 編集画面では CSS アニメーションの途中経過や JS 由来の描画は見えない。確認はプレビュー/再生で行う
