# ADR-0009: 自前 E2E(smoke)を廃止し、実ブラウザでの検証を手動確認に寄せる

- **日付**: 2026-08-25
- **状態**: 採用

## 背景

`scripts/smoke.mjs` は 4,559 行・`check()` 300 件超を持つ自前の E2E だった。
macOS の WKWebView には WebDriver が無く、Tauri ウィンドウを自動操作できない
([03-tech-stack](../basic-design/03-tech-stack.md))。そのため**同じフロントエンドを
Vite dev server から実 Chrome に読み込み、`window.__TAURI_INTERNALS__.invoke` だけを
スタブに差し替える**形を取っていた。境界より上(取り込み・分割ダイアログ・編集ステージ・
コマンドエンジン)は本物が動き、境界より下は `cargo test` が持つ、という立て付け
([08-test-policy](../basic-design/08-test-policy.md))。

立て付け自体は目的にかなっていた。合成イベントでは緑のまま実アプリで壊れる不具合を
実際に踏んでおり([issues](../issues.md) #8)、CDP の `Input` ドメインで実マウスを送る検査は
smoke にしか置けなかった。

一方で、**合否の最終判定は最初からユーザーの手動確認だった**。
[ADR-0008](0008-handoff-before-docs.md) の背景で測ったとおり、決着済み課題の大半は
インスペクタ・ステージの操作感で、「期待どおり気持ちよく効くか」は人が触るまで分からない。
smoke が緑でも手で触る工程は消えず、**同じ範囲を二度確かめる**構造になっていた。

そして末期には、**検証の対象ではなく検証基盤の側に手がかかる**状態になっていた。
2026-08-24〜25 に smoke 由来で起票した課題は 5 件あり、**5 件ともアプリではなく smoke 自身の不具合**。
うち 3 件が未解決のまま残っていた。

| 課題 | 内容 | 状態 |
|---|---|---|
| [#42](../issues.md#i42) | 範囲の取り方の前提が崩れて 2 件落ちていた。**通っていた 1 件も偽陽性**だった | 解決 |
| [#43](../issues.md#i43) | `workspace` シナリオが単独で走らない(前のシナリオが残した選択に依存していた) | 解決 |
| #33 | 実 HTML を渡すと再生の検査が落ちる。手順が**デッキの枚数を前提**にしていた | **未対応** |
| #45 | `extra` シナリオが単独で走らない(`workspace` が書くモジュール変数 `fontPicks` に依存) | **未対応** |
| #47 | **同一コミットで総件数が 319 と 308 に振れる**。固定プロファイルの使い回しによる状態依存 | **未対応** |

#47 のせいで**総件数を回帰の目安に使えなくなり**、[roadmap](../roadmap.md) からは件数の記載を外していた
(2026-08-25)。`N/N passed` の N が動くと、検査が 1 件落ちたのか、そもそも走らなかったのかを
数字から区別できない。

未解決の 3 件は smoke ごと消えるので、本 ADR の採用に伴って [issues](../issues.md) から落とした。
#42 / #43 は**過去に実際に起きて直した出来事**なので、issues にそのまま残している。

## 選択肢

1. **廃止して手動確認に寄せる** — `scripts/smoke.mjs` と CI の smoke ステップを消し、
   実ブラウザでしか見えない範囲は手で触るときに確かめる。基盤の維持コストがゼロになる代わりに、
   自動で回る網が jsdom の範囲まで縮む
2. **安定化させて維持する** — #33 / #45 / #47 を潰す。原因はどれも掴めており
   (枚数への依存・モジュール変数への依存・プロファイル使い回しによる状態依存)、
   **直すこと自体は可能だった**。実マウスの検査を残せるが、手動確認との二重化は解消しない
3. **Playwright など既製の E2E に載せ替える** — 実行基盤の面倒(プロファイル・待ち合わせ・
   スクリーンショット)を既製品に任せる。4,559 行の移植が要るうえ、WKWebView を触れない制約も、
   手動確認との二重化も変わらない

## 決定

**選択肢 1。** `scripts/smoke.mjs` を削除し、CI から smoke のステップを外す。
実ブラウザでしか見えない範囲は、[ADR-0008](0008-handoff-before-docs.md) の
**「手で触ってもらう」工程**で確かめる。

**見るべきものの一覧は捨てない。** smoke を前提に書かれていた各機能の `test.md` は、
何を見るかのリストを残したまま**手動確認の手順**として書き換える。
消えるのは自動実行であって、チェックリストではない。

## 理由

- **落としたのは二重化であって、検証そのものではない。** 合否は最初からユーザーが手で触った結果で
  決まっており([ADR-0008](0008-handoff-before-docs.md))、smoke はその前段の重複だった。
  重複を残す判断は、基盤の維持コストが**その重複が拾う分**を上回らない限り成り立つが、
  末期はそうではなくなっていた
- **末期の smoke 由来 5 件は、どれもアプリの不具合を指していなかった。** 5 件とも smoke 自身の不具合で、
  しかも [#42](../issues.md#i42) では**通っていた 1 件が偽陽性**だった。
  **緑であること自体が信用できない**なら、二重化の価値はほとんど残らない
- **選択肢 2 を採らない理由。** 3 件は直せるが、直しても「手で触るまで合否が決まらない」ことは変わらない。
  #47 を潰すには実行のたびにプロファイルを作り直す方向になり、
  **全体が分単位**という前提をさらに悪化させる
- **選択肢 3 を採らない理由。** 移植で改善するのは実行基盤の安定性だけ。
  `__TAURI_INTERNALS__.invoke` の差し替えは結局自前で書くことになり、
  **Chrome 越しに見ている**という限界(= WKWebView での挙動は分からない)も同じまま残る
- **単体テストは減らさない。** Vitest 445 件は据え置き。
  「一度でも不具合を出した箇所には回帰テストを追加する」([08-test-policy](../basic-design/08-test-policy.md))も
  変わらない。jsdom で書けるものは今後も Vitest に足す

## 影響

**自動検証から外れる範囲(ここを曖昧にしない)。** Vitest は jsdom なので、外れるのは
**iframe 境界の実挙動・実マウス操作・レイアウト計算・フォーカス移動**の 4 つ。
どれも手動確認だけが頼りになる。**それぞれ jsdom で何が見えないかの正は
[08-test-policy](../basic-design/08-test-policy.md)**(「自動検証から外れている範囲」)
—— 毎回引かれるのは運用側なので、ここでは繰り返さない。

とくに [#8](../issues.md#i8) の系列が痛い。左ペインのディバイダが動かなかったあの不具合は、
**合成イベントのチェックが緑のまま実アプリで壊れていた**。
CDP の実マウスでしか出ない不具合を自動で踏む手段は、これで無くなる。

- **実 HTML の流し込み(`npm run smoke -- <deck.html>`)も無くなる。** 実デッキでの検出・分割・
  可視性・サムネイルの収まりは、アプリに読み込んで目で見る
- **CI(`.github/workflows/ci.yml`)で回るのは `npm run typecheck` と `npm test` の 2 つになる。**
  `cargo test` は元から載せていない(Tauri のシステム依存の導入がテスト本体より長いため)ので、
  Rust 側は手元で回すまま
- [08-test-policy](../basic-design/08-test-policy.md) の E2E 行・実行タイミング・CI の各表を書き換える
- [rules/development](../rules/development.md) §2 の**シナリオ表は消え、逆引き表は
  手動確認のチェックリストとして残した**。上の「見るべきものの一覧は捨てない」と同じ扱いで、
  消えたのは `--only=<シナリオ>` の走らせ方であって、何を見るかの一覧ではない
- 各機能の `test.md` は**手動確認のチェックリスト**として残す(削除しない)
- [ADR-0008](0008-handoff-before-docs.md) の「渡す前に `--only` で自分で確かめる」は成立しなくなる。
  同 ADR に追記した

## 再考の条件

次のどれかが起きたら、この判断を見直す(そのときの第一候補は選択肢 3)。

- **手動確認が追いつかない規模になったとき** — 1 周で触る箇所が増え、
  「全部は見ていないがマージした」が常態化したら、網を自動化に戻す
- **同じ場所のリグレッションが繰り返し出るようになったとき** — とくに実マウス・実寸・
  iframe 境界のように **Vitest では原理的に押さえられない層**で 2 度以上再発したら、
  その 1 点だけを狙った E2E を戻す価値がある
- **WKWebView を直接自動操作する手段ができたとき** — Chrome 越しに見るという smoke の
  根本的な限界が消えるなら、それは二重化ではなく**手動確認では見られないもの**を見る道具になる

戻すときに `scripts/smoke.mjs` を書き直す必要は無い。
消した時点の中身は git の履歴(本 ADR を入れたコミットの直前)から取れる。
