# ADR-0010: 書体を 2 つだけ同梱し、`slides://` から配る

- **日付**: 2026-08-25
- **状態**: 採用

## 背景

`DEFAULT_FONT_STACK` の先頭は Noto Sans。**ラテンと日本語を同じ設計で覆う唯一の候補**で、
既定に選んだ理由もそこにある([features/fonts](../features/fonts/design.md))。

一方で [03-tech-stack](../basic-design/03-tech-stack.md) は **「書体はバンドルしない」**
と決めていた。既定もスタックとして名前を書くだけにして、
**書体のライセンスを配布物に持ち込まない**ためだった。

この 2 つは両立していなかった。ピッカーは「この機械に無い書体は出さない」を規則にしている
——無い書体を出すと**ブラウザが黙って別の書体に差し替え、次の機械で見た目が変わる**からで、
それこそこの機能が存在する理由。にもかかわらず、**既定の 1 件だけがその規則の外**にいて、
どの機械でも `Noto Sans` と名乗っていた。実際この Mac に Noto Sans は無く、
選ぶとヒラギノで描かれていた。

2026-08-25 に既定の名乗りを実測に変え([features/fonts/decisions](../features/fonts/decisions.md) #4 の
帰結)、`既定(ヒラギノ角ゴシック)` と出るようにした。嘘は消えたが、
**ピッカーから Noto Sans という名前ごと消えた**。

残ったのは、**目的そのものが満たせていない**という事実だった。
「同じデッキがどの環境でも同じ字形で描かれる」ためにこの機能はあるのに、
**既定がいちばんそれを満たしていない** —— 既定のまま作ったデッキは、
macOS ではヒラギノ、Windows では游ゴシックで描かれる。

## 選択肢

1. **2 書体だけ同梱する** — Noto Sans と Noto Sans JP の実体をアプリに入れ、既定をそこに向ける。
   どの環境でも同じ字形になる代わりに、配布物にライセンスとサイズを持ち込む
2. **同梱しない(現状維持)** — 既定は環境にある書体へ落ちる。配布物は軽いままだが、
   **既定で作ったデッキの見た目が機械ごとに変わる**状態が続き、ピッカーに Noto Sans も出ない
3. **実行時に Web から取りに行く**(Google Fonts など) — 配布物は増えない。
   ただし**オフラインで壊れ**、外部通信が要り、CSP を外部オリジンに開けることになる

## 決定

**選択肢 1。ただし 2 書体だけ。**

- `src-tauri/fonts/` に Noto Sans / Noto Sans JP を置く(Fontsource 5.3.0、どちらも **OFL-1.1**)
- 配信は **`slides://<origin>/fonts/…`**。アプリ窓・編集 iframe・プレビュー iframe の 3 面が
  同じ URL を読む
- **書き出した HTML には入れない。** 従来どおり `font-family` に名前を書くだけ
- **他の書体は今後も同梱しない。** カタログの残りはこれまでどおり実測で出し入れする

## 理由

- **ライセンスは障害ではなかった。** OFL-1.1 はライセンス本文を添えれば MIT の配布物に同梱できる。
  「持ち込まない」は**コストの回避**であって禁止ではなく、
  **既定の意味が壊れているコスト**のほうが大きかった
- **`slides://` から配るのは、フロント側に置くとプレビューだけ落ちるから。**
  プレビュー iframe は `allow-same-origin` を持たない=**不透明オリジン**で、
  Tauri がフロントのファイルに付ける `Access-Control-Allow-Origin` は
  **ウィンドウのオリジンそのもの**(`tauri-2.11.5/src/protocol/tauri.rs`)。不透明オリジンは一致しない。
  `public/` に置いた woff2 は**編集中は読めてプレビューだけ黙って落ちる** ——
  同じスライドの 2 つの見え方がずれ、しかも何も警告されない。
  `slides://` の応答は元から `*` を返すので、1 本の URL で 3 面ぶん足りる
- **2 つに絞るのは、これが「同じ設計でラテンと和文を覆う」最小の組だから。**
  1 書体ずつライセンスとサイズが増えるので、増やすなら**そのつど判断**する
- **書き出しに入れないのは、不変条件「書き出した HTML を壊さない」のため。**
  `slides://` はこのアプリの外で何も指さない。埋め込む案(data: URI)は
  **6MB のファイルを吐く**ことになるので採らない([ideas](../ideas.md) #13)
- **選択肢 3 を採らない理由。** このアプリはオフラインで動くデスクトップアプリで、
  **書体が要るのは編集中の毎フレーム**。ネットワークに依存させると、
  繋がらない環境で既定の字形が変わる —— 直そうとしている問題がそのまま残る

## 影響

- **[03-tech-stack](../basic-design/03-tech-stack.md) の方針を反転した。**
  「書体はバンドルしない」→「2 つだけバンドルする」。**他は今後もしない**を明記した
- **配布物が 6.3MB / 140 ファイル増える。** 和文は `unicode-range` で 124 サブセットに
  割れており、ブラウザは**実際に出てくる文字が属するぶんだけ**取りに来る
  (実測で 9 ファイル)。埋め込み表は `build.rs` がディレクトリを走査して作るので、
  書体を足し引きしてもコードは触らない
- **[10-security](../basic-design/10-security.md) の CSP を `style-src` / `font-src` で広げた。**
  足したのは `slides:` と `http://slides.localhost` の 2 つだけで、`https:` のような
  開いた指定は入れていない。理由は同ファイルの表に残した
- **OFL-1.1 の本文を配布物に同梱する義務が生じた。** `src-tauri/fonts/LICENSE-*.txt`
- **既定の名乗りが `既定(Noto Sans)` に戻る。** 名乗りを緩めたのではなく主張が本当になったからで、
  スタックを歩いて実際に当たる書体を名乗る処理(`firstResolvableFamily`)は残してある
- **素のブラウザで `npm run dev` したときは効かない。** `slides://` が無いので `<link>` を差さない。
  スライドは同梱前と同じくシステム書体で描かれる([issues](../issues.md#i95))
- **書き出した HTML を別の機械で開いたときの見た目は変わらない。** 従来どおりスタックの
  後続に落ちる([issues](../issues.md#i96))

## 再考の条件

- **配布サイズが問題になったとき** — 和文 5.2MB のうち、実運用で当たらないサブセット
  (CJK 拡張 B 以降)を落とす余地がある。**先に測ってから**削る
- **3 つ目を同梱したくなったとき** — 「2 つだけ」は最小の組だから成り立っている。
  増やすなら本 ADR ごと見直す(1 書体ずつライセンス・サイズ・字形の判断が要る)
- **WebView がカスタムスキームのサブリソースを配れなくなったとき** — 配信経路の前提が
  崩れる。そのときは Rust 側で通常の HTTP ポートを立てるか、
  プレビューの分離方式([ADR-0002](0002-edit-preview-separation.md))から見直すことになる
