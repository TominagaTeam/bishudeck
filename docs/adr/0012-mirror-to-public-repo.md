# ADR-0012: 開発は private に残し、リリースごとに公開リポへ写す

- **日付**: 2026-08-29
- **状態**: 採用

## 背景

[01-overview](../basic-design/01-overview.md) で一般公開を目指すと決めたが(2026-08-23)、
**形態は「決めていないという決定」として保留**していた。それを確定させるにあたって
公開前の点検をしたところ、引っかかったのは 1 点だけだった。

**コミットの author に個人の Gmail が 213 件入っている。** public にすると
GitHub API から誰でも一括で取得できる。

作業ツリーのほうはきれいで、API キー・トークン・秘密鍵は作業ツリーと履歴の
全 diff を通して 0 件、開発機のホームディレクトリのような実パスも 0 件、顧客名や第三者名も
0 件(外部 URL は `example.com` だけ)。依存 139 パッケージにコピーレフトは無く、
同梱書体は OFL-1.1 でライセンス本文も同梱済み。つまり**引っかかったのは
ファイルの中身ではなく、コミットのメタデータ**だった。

## 選択肢

1. **既存リポをそのまま public にする** — 最短。ただし Gmail が公開され、取り消せない
2. **既存リポの履歴を書き換えてから public にする** — `git filter-repo` で置換できるが、
   全 SHA が変わるので force push が要る。**既存の PR と、共同作業者が持っている
   clone が壊れる**
3. **公開用のリポジトリを別に立てて、そこへ写す** — 開発リポには一切触らない。
   写す内容を選べる。失敗しても公開側を消してやり直せる

## 決定

**案 3。** TominagaTeam org に **bishudeck** を新設し、開発リポ `html-slide-editor` は
private のまま残す。写し方は次のとおり。

- **履歴は squash して 1 コミット。** リリース tag ごとに丸ごと写す
- **除外はしない。** `docs/` も `CLAUDE.md` も全部出す
- **写すのは `git archive` の出力** —— その tag で追跡されているファイルだけ
- **push はしない。** [`scripts/mirror.sh`](../../scripts/mirror.sh) はコミットを作るところで止める

## 理由

**squash が最大の利き手だった。** 1 コミットに潰すと、213 件の Gmail も、廃止済み
`scripts/smoke.mjs` の 40 版(6.7MB)も、履歴に残っていた検証デッキのスクリーン
ショットも、まとめて存在しなくなる。**案 2 で `filter-repo` を使う理由がそもそも消える。**
判断が要る問題だと思っていたものが、写し方の選択ひとつで作業以前に消えた。

**除外はしないと決めたのは、実測でコストが分かったから。** 当初は `docs/issues.md`・
`CLAUDE.md`・`docs/rules/`・`docs/features/` を外す案だった。数えると、残す側から
外す側へのリンクが **155 本**切れる(docs 内 127 本 + `src/` のコード内コメント 28 箇所)。
`docs/INDEX.md` は「全ドキュメントの地図」なので 2/3 が空欄になり、
[ADR-0006](0006-docs-driven-migration.md) / [0007](0007-issues-md-and-task-file-rule.md) /
[0008](0008-handoff-before-docs.md) は**外す docs の運用を定めた ADR** なので、
対象が無いまま規則だけが公開される。
**外す代償は、外すファイルの中ではなく残すファイルの中に出る。**

**丸ごと 1 コミットにしたのは、手順を毎回同じにするため。** コミットを 1 対 1 で
写そうとすると、粒度と順序をミラーのたびに決めることになる。公開側は
「そのリリース時点のソース」であればよく、過程は private 側に残る。手順が固定なら
スクリプトにでき、スクリプトにできれば人が手順を思い出さなくて済む
([ADR-0008](0008-handoff-before-docs.md) と同じ考え方)。

**除外リストを別に持たないのは、`.gitignore` との二重管理を避けるため。**
`git archive` は追跡ファイルだけを出すので、`node_modules` / `dist` /
`samples/local` / `.env` / `.claude` の個人設定は最初から入らない。

**push しないのは、公開が取り消せないから。** `git log` と `git show` を見てから
人が押す。写す先の origin が bishudeck でなければ、中身を消す前に止める。

## 引き換えに失うもの

- **公開リポの PR を直接マージできない。** 次のミラーで丸ごと上書きされる。
  受け取ったら開発リポ側で取り込み直すことになる
- **開発の過程が外から見えない。** 220 コミットの粒度(1 課題 1 コミット)は private 側にだけ残る
- **ミラーを忘れると公開側が古びる。** リリース tag を打つ手順に組み込む必要がある

どれも**まだ起きていない**ので、[roadmap](../roadmap.md) の「一般公開に向けて
足りないもの」で追う([ADR-0007](0007-issues-md-and-task-file-rule.md) の判定軸)。

## 副産物として分かったこと

**GitHub のメール保護が先に効いていた。** 未 push だった 3 コミットを push しようと
したら `GH007`(private email を公開する push) で拒否された。この 3 つは誰も持って
いなかったので `filter-branch` で安全に書き換えられた(ツリーのハッシュは書き換え前と
一致 —— 中身は変わっていない)。**もし push 済みだったら、案 2 と同じ問題に当たっていた。**

以後のコミットのために `git config --global user.email` も noreply に変えてある。
