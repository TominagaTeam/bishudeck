# 何をつくるのか(概要)

## 一言で

AI が生成した HTML スライドを、**CSS も JavaScript もそのまま再現したまま**
PowerPoint のように編集する Tauri 製デスクトップアプリ。

## 解決する課題

AI に「スライドを作って」と頼むと、凝った CSS アニメーションや JS を含む HTML が返ってくる。
これを直したいとき、今は次のどちらかしかない。

- **HTML を手で書き換える** — CSS/JS が読める人にしか直せず、GUI で位置を微調整するような作業に向かない
- **PowerPoint に貼り直す** — レイアウト・アニメーション・スクリプトが全部失われる

つまり「見た目は気に入っているが、文言と配置だけ直したい」という一番よくある要求に応える手段が無い。

## 想定ユーザー

**AI にスライドを生成させ、それを自分で仕上げたい個人。**
CSS や JS が読めなくても、GUI で文言と配置を直せることに価値がある層。

**一般公開を目指す。** 作者自身と社内だけの道具として閉じない。
このことは設計判断に効く — 手元だけで使うなら「動く」で足りるが、
公開するなら**知らない人の HTML が入ってくる**前提が要る
([10-security](10-security.md))。

**形態はソース公開に決めた(2026-08-29)。** バイナリは配らない。
公開先は TominagaTeam org の **bishudeck** で、**開発はこの private リポに残し、
リリース tag ごとに写す**([ADR-0012](../adr/0012-mirror-to-public-repo.md))。

バイナリを配らない以上、署名・公証と自動更新は当面立たない。残るのは
コントリビューションの受け入れ方で、これは
[../roadmap.md](../roadmap.md) の「一般公開に向けて足りないもの」で追う。

> **推測マーカーとの違い。** マーカーは「確かめていないのに書いた」印で、
> 消すべきもの([ADR-0006](../adr/0006-docs-driven-migration.md))。
> 上の「未定」は**判断待ちだと判断した記録**なので、決まるまで残す。
> (この文にマーカーの記法そのものを書かないのは、残数を数える doctor が拾ってしまうため)

## 非機能要件

- **忠実性**: 未編集のスライドはエクスポート時にバイト単位で元と同等の見た目を保つ
- **安全性**: 読み込んだ HTML 内の任意 JS がアプリ本体(Tauri API・ファイルシステム)に触れない
- **拡張性**: ツール / パネル / インポータ / エクスポータをプラグインとして追加可能
- **性能**: 50 スライド規模で編集操作 60fps、起動 3 秒以内
- **可搬性**: macOS / Windows / Linux(Tauri がサポートする範囲)
- **配布可能性**: `npm run tauri build` でバンドルはできるが、**署名も公証もしていない**。
  ソース公開に決めた(上記)ので、当面は使う人が自分でビルドする。バイナリを配る日が
  来たら、OS の警告を越えられる形にする必要がある([../roadmap.md](../roadmap.md))

## スコープ外

- **スライドをゼロから作る機能** — 入力は既存の HTML デッキ。白紙スライドの追加機能は一度実装したが削除した
- **元 CSS のルール自体を書き換える編集** — スタイル編集は inline のオーバーライドで行う([ADR-0004](../adr/0004-style-edits-as-overrides.md))。
  ルール単位の編集は F14(コードビュー)とプラグインに委ねる
- **要素の複数選択** — 選択は常に 1 つ。階層をパンくずで辿る方式にしている
- **Rust 側での HTML 解釈** — ファイル I/O・アセット配信・プレビュー公開・ウィンドウ管理の 4 つに徹する
  ([ADR-0001](../adr/0001-html-as-source-of-truth.md))。プレビュー公開が扱うのも文字列のままの HTML で、
  中身は読まない([04-architecture](04-architecture.md))
