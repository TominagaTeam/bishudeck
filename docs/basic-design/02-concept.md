# コンセプト(目指すところ)

## 目指す状態

> **「HTML を壊さないスライドエディタ」**
> 読み込んだ HTML の CSS / JavaScript を完全に再現しつつ、
> GUI での編集結果を元の HTML に非破壊で反映する。

AI が生成したデッキを取り込み、文言と配置を PowerPoint のような操作感で直して書き出したとき、
**触らなかった部分が 1 バイトも変わっていない**。これが完成形。

## 優先順位・価値観

迷ったときの判断軸。上にあるものが優先する。

1. **他人の HTML を壊さない** — このアプリの価値は「エディタが解釈できない CSS・JS・要素も、
   触らなければ壊れない」こと。迷ったら**手を加えない側に倒す**
2. **忠実性 > 編集機能の豊富さ** — 再現性を犠牲にする機能は入れない。
   高度な編集はコードビュー(F14)とプラグインに逃がす
3. **安全性は構成で担保する** — 「気をつける」ではなく sandbox とオリジン分離で
   ブラウザに保証させる([ADR-0002](../adr/0002-edit-preview-separation.md))
4. **編集が主、プレビューは従** — 既定は編集モード。プレビューは結果を確かめに行く先であって、
   作業を始める前に 1 クリック挟む場所ではない

## 成功の定義

- 取り込み → 編集 → 書き出しの往復が**固定点**になっている
  (書き出した HTML を読み直すと同じプロジェクトに戻る。開くたびに何かが増えない)
- CSS アニメーションや JS を持つ実物のデッキを取り込んでも、再生時に元と同じように動く
- エディタが知らない構造(未知のフレームワーク・カスタム要素)を含むデッキでも、
  その部分に触らない限り書き出し結果が壊れない
