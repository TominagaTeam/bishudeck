# UI デザインシステム

画面ごとの操作方法は [README.md](../../README.md) の「画面の使い方」へ。
編集操作の中身は [../features/editing-engine/design.md](../features/editing-engine/design.md)、
キーボードショートカットは [../features/shortcuts/design.md](../features/shortcuts/design.md) へ。
ここは**全画面共通の決め事**のみ。

## トーン・方向性

**PowerPoint 準拠**。「AI が作った HTML を、いつもの操作感で直す」ことが目的なので、
独自の操作体系を発明しない。整列・重ね順・複製・選択の階層移動は PowerPoint と同じ挙動に寄せる。

## レイアウト

```
┌──────────────────────────────────────────────────┐
│ ツールバー(5 群。下の「ツールバー」)             │
├────────┬╥──────────────────────────╥┬────────────┤
│ スライド │║                          ║│ インスペクタ │
│ 一覧    │║       キャンバス          ║│ (スタイル / │
│ (サムネ │║  (編集 or プレビュー)     ║│  配置 /     │
│  イル)  │║                          ║│  スライド)  │
├────────┴╨──────────────────────────╨┴────────────┤
│ ステータスバー(7 スロット。下の「ステータスバー」) │
└──────────────────────────────────────────────────┘
          ↑ 境界(ドラッグで幅変更 / シェブロンで開閉) ↑
```

- **サムネイルは静的スナップショット**。編集確定時に編集 iframe から生成する
  (`foreignObject` → canvas、または縮小 srcdoc iframe)。**常時 N 枚の iframe を生かさない**
- **キャンバスの左右にある境界は、どちらもドラッグで幅を変えられる**。
  スライド一覧は 160–480px(既定 240px)、インスペクタは 240–520px(既定 280px)。
  下限が違うのは中身が違うため — サムネイルは 160px を下回ると読めなくなり、
  インスペクタの `.field`(56px のラベル + コントロール)は 240px を下回ると崩れる
- **境界上のシェブロンをクリックするとそのペインを隠し、もう一度で元の幅に戻す**。
  境界のダブルクリックでも同じ。畳んでいる間も幅はストアに残る(戻す先がそれ)
- 折り畳み時はグリッドのトラック幅を 0 にするだけでなく**ペインの padding と border も落とす**
  (border-box は自分の padding + border より細くならないため)
- **境界を押したときは既定動作を止める**(`pointerdown` の `preventDefault` と
  `user-select: none`)。止めないと押下が文字選択を始め、隣に `draggable` な
  `.slide-item` が並ぶ左側では**ブラウザがサムネイルの HTML5 ドラッグを開始**する。
  そこで飛ぶ `pointercancel` が境界のポインタキャプチャを解くので、左だけが
  十数 px で止まっていた([issues](../issues.md) #8)
- **2 本の境界は同じコンポーネント(`PaneDivider`)** で、`pane` prop 1 つで左右が決まる。
  どちらの端から測るか・シェブロンをどちらへ向けるか・幅の上下限・保存先キーは
  `uiStore` の `PANES` 表にまとまっている。左右で挙動がずれる余地を構造的に無くすため

## ステータスバー

**左から 7 スロット**(`src/features/StatusBar.tsx`)。**並びの正はこの表**で、
それぞれの文言は i18n カタログ(`src/shared/i18n/ja.ts`)が正。

| 順 | 中身 | 空になるとき |
|---|---|---|
| 1 | スライド番号(`3 / 12`) | 空にならない(0 枚のときは `—`) |
| 2 | 検出したフレームワーク(`reveal` / `generic:section` / 取り込み前は `empty`) | 空にならない |
| 3 | 保存状態(未書き出し / 変更あり / 書き出し済み / 書き出し済み + 時刻) | 一度も書き出さず、変更も無い間 |
| 4 | **選択の系譜**(`div.container › h1`) | 何も選んでいない間 |
| 5 | 進捗(取り込み・書き出しの最中だけ) | どちらも走っていない間 |
| 6 | テーマ(`select`。システム / ライト / ダーク) | 空にならない |
| 7 | ズーム(`select`。画面に合わせる + 25 / 50 / 75 / 100 / 150 / 200%) | 空にならない |

- **3・4・5 は条件で中身が消える**が、スロットは消えないので**並びは動かない**
- **伸びるのは 4 だけ**(`flex: 1`。あふれたら末尾を省略する)。可変幅をここが引き受けるので、
  **右端の 2 つは選択の深さに関わらず同じ位置**にいる
- **6 と 7 はどちらも「ワークスペースの見え方」**で、デッキに対するコマンドではない。
  だからツールバーではなくここに並ぶ([features/theme](../features/theme/decisions.md) #5)
- **2 は検出器の id をそのまま出す**(訳さない)。取り込みが何と判定したかを見るためのもの
- **系譜をここに常時出す理由**は
  [../features/editing-engine/design.md](../features/editing-engine/design.md) の「パンくず」にある。
  **ここは読むだけ**で、クリックで階層を移動できるパンくずはインスペクタにある(下の「選択の見せ方」)

## ワークスペースの状態は書き出さない

ペイン幅・開閉状態は `localStorage`(`hse.slideListPane` / `hse.inspectorPane`)に持つ。
**ペインごとに別のキー**にしてあるので、片方の設定を消してももう片方は残る。
**ワークスペースの好みであってドキュメントの内容ではない**ので、書き出す HTML には入れない。
同じ理由で、ズーム率や選択状態も HTML に持ち込まない。

**書き込みは 200ms の trailing debounce で間引く。** 境界のドラッグは 1px 動くたびに
`setPaneWidth` を呼ぶので、間引かないとペイン 2 枚分の同期書き込みが毎フレーム走る。
ストアの state は同期のまま更新し(ペインがポインタから遅れてはいけない)、
ディスクへ行く部分だけを遅らせる。閉じ際に取りこぼさないよう `pagehide` で flush する。

## モーダルの閉じ方は 4 つとも同じ

**Escape と背景クリックはどのモーダルでも「やめる」**を意味する。
実体は `ModalShell`(`src/features/ModalShell.tsx`)ひとつで、
各ダイアログは「やめるとは何か」だけを渡す。

| ダイアログ | やめる = |
|---|---|
| 取り込み確認 | キャンセル(ファイルはまだ触っていないので何も失わない) |
| ショートカット一覧 | 閉じる |
| 終了確認 | 終了をキャンセル(3 つの答えのうち、セッションも意図しないファイルも失わない唯一のもの) |

- **Escape は capture フェーズで取る。** ステージは Escape を「選択を 1 階層外へ」と読むので、
  同じキーが 2 つの意味を持たないように途中で止める
- **背景クリックは `event.target === event.currentTarget` のときだけ。**
  ダイアログの中で始まったドラッグ(入力欄の文字選択など)が外で離されても閉じない
- 当時の 4 つのうち 2 つだけが Escape を持ち、残り 2 つは**どうやっても閉じなかった**
  ([issues](../issues.md) #14)。ダイアログごとに書いていたのが原因なので、
  置き場をひとつにして構造的に揃わないようにした

## ツールバー(リボン方針)

**左から 5 群**(`src/features/Toolbar.tsx`)。

| 群 | 中身 |
|---|---|
| 1 | HTML を取り込む / 書き出し |
| 2 | 元に戻す / やり直す |
| 3 | スライド / 挿入 / 配置(いずれもドロップダウン) |
| 4 | モード切替(編集 / プレビュー) |
| 5 | ヘルプ / 再生 — ここだけ右端に寄る |

- コマンドは**枠なしのフラット**で、ホバーで初めて塗る
- グループの区切りはボタンの枠ではなく**ヘアラインの縦罫**。
  **4 と 5 には引かない** — モード切替は自前の枠を持ち、再生は離れて 1 つで立っているため
- モード切替は**セグメンテッドコントロール 1 個**にまとめる
- **メニュー項目のショートカット表記は手で書かない。** `MenuItem` の `shortcut` は
  ショートカットの id を受け取り、実行環境に合った表記(⌘ / `Ctrl+`)を
  [features/shortcuts](../features/shortcuts/design.md) が返す
- ヘルプは**一手でショートカット一覧を開く** —
  項目が 1 つしかないドロップダウンは、何も選ばせずに手数を増やすだけになる
- **未保存の印は書き出しボタンに付くドット 1 つ**(アスタリスクではなく、
  PowerPoint のタイトルバーと同じ見せ方)。ラベルを押し出さないので幅が動かない

## カラー

**配色は 2 つ**(ライト / ダーク)。既定はライトで、切り替えはステータスバーの 6 番目。
**トークンの一覧・どれが配色で動きどれが動かないかの正は
[../features/theme/design.md](../features/theme/design.md)。**
ここには**役割の分け方**だけを置く。

| トークン | 用途 |
|---|---|
| `--brand` | **再生ボタン 1 つだけ。** ライトではインク、ダークではほぼ白に反転する |
| `--dirty` | 書き出しボタンに付く未保存のドット。**両配色で同じ琥珀** |
| `--accent`(青) | **「いま選ばれている / 指している」の意味**。ステージ側にも chrome 側にも使う |

`--brand` を `--accent` と分けてあるのが要 — **青は「選ばれている」、`--brand` は「デッキを走らせる」**
(`src/app/styles.css` のトークン定義のコメント)。**`--brand` に色相を持たせずインク / 反転白にした**のは、
青が「選ばれている」で埋まっている以上、バーの上に 2 つ目の色相を置けば必ず青と喧嘩するため。
色を捨てたぶん、残る最大のコントラストで「走らせる」を立たせている。

**以前は再生ボタンと未保存ドットが `--brand` を共有していた**が、別々のトークンに割った。
brand は配色で反転するので、片方でインク・もう片方でほぼ白になり、
**どちらも「未処理のものがある」とは読めない**([features/theme](../features/theme/design.md))。

`--accent` は**ステージ限定ではない。** `styles.css` の 15 箇所のうち、ステージ側
(`.overlay-selection` / `.overlay-handle` / `.overlay-rotate` / `.overlay-focus`)は **4 箇所**で、
**残る 11 箇所は chrome 側** — スライド一覧の選択枠、パンくずの現在地、色見本の現在値、
フォーカスリング、境界とペイン開閉のホバー。
**面として塗る 2 箇所**(トグルの点灯・モーダルの既定ボタン)だけは
`--accent-fill` を取る —— ライトで `#3884ff` を塗ると白文字が 3.6:1 しか出ないため
([features/theme](../features/theme/design.md))。
**どれも「選ばれている / 指している / フォーカスがある」を指しており、装飾で青を使っている箇所は無い。**
`.color-swatch` が「`.active` にしない —— 他のトグルが使う accent の塗りが見本そのものを塗り潰すから」と
書いているとおり、**chrome のトグルは accent で点くのが既定**。

以前ここには「`--accent` を chrome に使わない」と書いてあったが、**初回コミットの時点で
既に chrome 側に 11 箇所**あり、実装がそうだった時期は無い。実際に守られている線は
**`--brand` との分離**と、**`--accent` を装飾に使わない(状態を指すときだけ使う)**の 2 つ。

## 角丸と行間

**角丸は 4 段**(`--r-sm` 4px / `--r-md` 7px / `--r-lg` 10px / `--r-xl` 14px)。
**生の px は書かず、必ずトークンを引く。**

| 段 | 当てるもの |
|---|---|
| `--r-sm` | 小さな内側の面 — サムネイル、色見本、見出しのフォーカスリング |
| `--r-md` | コントロール — ボタン、入力、セグメンテッドの両端、メニュー項目 |
| `--r-lg` | それらを載せる面 — スライド一覧の行、モード切替の枠、ポップオーバー、トースト |
| `--r-xl` | モーダル |

円は段に含めず `50%` と書く(未保存ドット・ペイン開閉・回転ハンドル)。

**以前は 3 / 4 / 5 / 6 / 8 / 12px が混在していた。** 同じ役割のものが 1px 違いで並んでいて、
どこまでが仲間なのかが読めなかったので 4 段に畳んだ。

**本文の行間は 1.5**(以前は 1.6)。デスクトップの密なパネルでは 1.6 は行が空きすぎる。
**書体は据え置き** —— `system-ui, -apple-system, 'Hiragino Sans', 'Noto Sans JP'`。
chrome 用に書体を同梱する案は見送った([features/theme/decisions.md](../features/theme/decisions.md) #11)。

**パネル見出しに `text-transform: uppercase` は使わない。**
見出しは日本語なので大文字化は効かず、道連れの字間だけが残って「文字書式」が
意味もなく間延びしていた。太さ(600)で見出しを立て、字間は 11px の英数字に効く 0.04em に留める。

## アイコン

`src/features/icons.tsx` にインライン SVG で置く。

- 16 グリッド・`currentColor`・同じストローク幅で揃える
- **アイコンはラベルの置き換えではない** — ツールバーのボタンは文字ラベルを残したままアイコンを添える。
  手順書も報告も不具合の指摘もボタンを**ラベル名で指す**ので、
  文字を消してアイコンだけにすると呼び名が無くなる
- ツールバー専用ではない。インスペクタの文字色・蛍光もここから引く
- **`currentColor` の例外は 1 つだけ** — 文字色・蛍光のアイコン下部のバーは、
  ボタンが**次に当てる色そのもの**なので実際の値で塗る。ボタンの文字色を借りたバーは
  どの色が読み込まれていても同じことを言ってしまう
  ([features/inspector/decisions.md](../features/inspector/decisions.md) #47)

## 選択の見せ方

- **選択枠・ハンドルはステージの外(ホスト側 DOM)に描く**。iframe の中に描くと書き出し HTML に混ざる
- インスペクタのパンくず(`div.inner › h2`)にホバー / タブ移動すると、
  その要素がステージ上に**破線の枠**で出る。クリックする前にどの箱か分かるようにするため。
  選択中の項目には出さない(すでに選択枠がある)
- 文字編集中は選択枠の見た目を変える
- **ドラッグ中は数値を出す。** 移動は `x, y`、リサイズは `w × h`、回転は `n°`。単位はデザイン px
- **ハンドルのカーソルは要素の回転に追従する。** 掴む辺と矢印の向きが合わないと、
  どちらに伸びるのか読めない

## 浮遊 UI(コンテキストメニュー)

ステージの上に浮くものは、**必ず `document.body` へ portal する。**

ステージは `.stage-surface` の中にあり、この要素は表示倍率を `transform: scale()` で持っている。
transform を持つ要素は **`position: fixed` の包含ブロックになる**ので、その中に描いた浮遊 UI は
ビューポート基準でなくなり、さらにズーム倍率ごと拡大縮小してしまう(25% 表示で文字が読めなくなる)。

位置は開くきっかけになったイベントの `clientX / clientY`(既にビューポート座標)をそのまま渡す。

**逆に、ステージの上に浮かないものは portal しない。** 上の理由は `.stage-surface` の `transform` に
由来するので、`transform` を持たないインスペクタの中で開くもの(色のパレットなど)には当てはまらない。
むしろ portal すると、`data-hse-text-tools` によるセッションの生死判定・外側クリックの判定・
スクロール追従の 3 つが**同時に壊れる** — どれも実 DOM の包含関係を見ているため
([features/inspector/decisions.md](../features/inspector/decisions.md) #43)。

**編集中のテキストに寄り添うミニツールバーは置かない。** 一度実装したが、
編集中ずっと本文の上に居座って隣接行を隠すため撤去した
([features/inspector/decisions.md](../features/inspector/decisions.md) #15)。
文字書式はインスペクタにある。

これは「選択枠・ハンドルはステージの外(ホスト側)に描く」
([rules/development](../rules/development.md) §4 不変条件 15)の延長で、
書き出す HTML にエディタ由来のものを混ぜないという同じ目的に仕える。

## レスポンシブ / 対応デバイス

デスクトップアプリのみ。モバイル対応は不要。
キャンバスはスライドの宣言サイズ(1920×1080 等)を保ったまま、ペインに収まるよう
fit スケールで縮小表示する(`src/stage/useFitScale.ts`)。
