# テスト方針

ここは**方針**のみ。個別のテストケースは各機能の `test.md` へ、
**実行手順と検証の実務**は [../rules/development.md](../rules/development.md) §2 へ。

## 何をどこまでテストするか

**「動くはず」で終わらせない。数値かスクリーンショットで確認する。**

次に当てはまる変更には**必ず回帰テストを追加する**。

- 座標・寸法の計算(ドラッグ、リサイズ、回転、スナップ、fit スケール)
- 文字列の生成・解析(スライドのシリアライズ、合成、書き出し、属性の復元)
- 外部由来データの扱い(取り込み Detector、実 HTML のスクリプト・スタイル)
- Undo/Redo の対象になる操作(コマンドの apply/revert、選択の復元)
- **一度でも不具合を出した箇所**

単体で書けるものは Vitest に足す。**実ブラウザの実寸・実描画が要るものは自動では見られない**ので、
その機能の `test.md` に **`手動` のケースとして**足す(下記「手動確認」)。

## ツール

| 層 | ツール | 担保する範囲 |
|---|---|---|
| ユニット | **Vitest**(+ jsdom) | 取り込み・往復シリアライズ・コマンド・幾何・選択ヒューリスティクス・UI 文言の補間とカタログ検査(`src/shared/i18n/i18n.test.ts`) |
| Rust | **`cargo test`** | `slides://` ルーティング・ファイル I/O |
| 手動確認 | **`npm run tauri dev`**(実ウィンドウ) | 実寸・実描画・sandbox の実挙動・実マウス操作・実 HTML の取り込み |

**自動化された E2E の層は持たない。** Chrome を直接起動する自前の smoke を 2026-08-25 に廃止した。
判断とその代償は [../adr/0009-drop-smoke-e2e.md](../adr/0009-drop-smoke-e2e.md)。

## 自動検証から外れている範囲

**ピラミッドの真ん中が空いている。** Vitest は jsdom で走るので、
次の 4 つは**どの自動テストも見ていない**。

| 見ていないもの | jsdom で見えない理由 |
|---|---|
| **iframe 境界の実挙動** | sandbox 属性が実際には効かない。`allow-scripts` の有無・`slides://` の読み込み・プレビューの `allow-same-origin` は実ブラウザにしか出ない([ADR-0002](../adr/0002-edit-preview-separation.md)) |
| **レイアウト計算** | `getBoundingClientRect()` が全部ゼロで返る。実寸・fit スケール・サムネイルの収まりは値にならない |
| **実マウス操作** | **`dispatchEvent` で作ったポインタイベントはブラウザの既定動作を一切起こさない。** 文字選択も HTML5 ドラッグも始まらないので、「押しても何も起きない」系の不具合は合成イベントのテストでは**通ってしまう**(左の境界がドラッグで動かなかった [../issues.md](../issues.md) #8) |
| **フォーカス移動** | `contenteditable` の抜け方・タブ順・IME に実体がない |

この 4 つを触った変更は、**手で見るまで未検証**。報告にそう書く。

## 手動確認

**手動確認は検証層の一つ**であって、「時間があれば見る」ものではない。
上の 4 つを触ったなら、これが唯一の検証手段になる。

- **実ウィンドウで見る** — `npm run tauri dev`。`npm run dev` をブラウザで開いて済ませない。
  **Chrome で動くことは WKWebView で動くことを意味しない**
  ([../rules/development.md](../rules/development.md) §2)
- **何を見るかは 2 か所にある** — 触ったものからの逆引きは
  [../rules/development.md](../rules/development.md) §2 の表、
  機能ごとの粒度は各機能の `test.md` の **`手動` の行**。どちらもチェックリストとして使う
- **目視で終わらせない** — 「画面を見て正しそう」で判断せず、数値かスクリーンショットで表明する
  ([../rules/development.md](../rules/development.md) §2「目視だけで終わらせない」)
- **手で見た範囲と、見ていない範囲を報告に書く** —
  自動テストが緑なことは、実ブラウザで壊れていないことの証明にならない

## 実行タイミング

| コマンド | いつ |
|---|---|
| `npm run typecheck` / `npm test` | **変更のたび必ず**。省略できない |
| `cd src-tauri && cargo test` | Rust 側を触ったら必ず |
| `npm run tauri dev` で手動確認 | UI・ステージ・取り込み・保存に触れたら。**手を抜くと自動検証から外れている 4 つが丸ごと未検証になる** |

## CI

`.github/workflows/ci.yml` が push と pull request で
**typecheck → test** を回す(ubuntu-latest)。

| 載せているもの | なぜ |
|---|---|
| `npm run typecheck` / `npm test` | 省略できない検証(§実行タイミング)をそのまま自動化する |

| 載せていないもの | なぜ |
|---|---|
| E2E | 廃止した([../adr/0009-drop-smoke-e2e.md](../adr/0009-drop-smoke-e2e.md))。CI に実ブラウザは残っていない |
| `cargo test` | Tauri のシステム依存(webkit2gtk など)の導入がテスト本体より長い。Rust を触る頻度が上がったら足す |
| スクリーンショット回帰 | WebView 差(WKWebView / WebView2)は Linux の runner では再現できない。基準画像の置き場も決まっていない |

**CI 特有の事情はコードに埋め込まず、環境変数で渡す。**
実ブラウザを起動していた頃は、Chrome の sandbox を切る `--no-sandbox` を
`HSE_SMOKE_CHROME_FLAGS` から入れていた —— 手元では保護を切るだけで得が無いため、既定には入れなかった。
いまは CI 固有の分岐は無い。

## 書体を名指ししない

書体を確かめるときは、**ピッカーが実際に出した書体**の中から選ぶ。
Helvetica や Georgia を名指しすると、それは「走らせている機械に何が入っているか」の
テストになってしまい、**別の OS では落ちる**(実ブラウザを CI に載せていた頃、
Linux の runner がこれで落ちた)。
検証したいのは「選んだ書体が適用されること」であって、特定の書体の存在ではない。

同じ理由で、「この環境に無い書体が出ないこと」は
**走っている側に無いはずの書体**(Windows ならヒラギノ、macOS / Linux ならメイリオ)で判定する。
