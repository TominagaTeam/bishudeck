# {{FEATURE_NAME}} — テスト設計

方針は [../../basic-design/08-test-policy.md](../../basic-design/08-test-policy.md) に従う。ここは個別ケースのみ。
ケースは [design.md](design.md) の受け入れ条件（EARS）と対応させる。

## EARS 記法（ケースの書き方）

曖昧さを排除するため、ケースは以下の型で書く：

- `WHEN <イベント/操作> THE SYSTEM SHALL <期待する動作>` — トリガー起点
- `IF <状態/条件> THEN THE SYSTEM SHALL <期待する動作>` — 条件分岐
- `WHILE <継続状態> THE SYSTEM SHALL <期待する動作>` — 継続動作

例: `WHEN ユーザーが有効なメールでリセット申請する THE SYSTEM SHALL 30分有効なリセットリンクを送信する`

## 種別

- `unit` — Vitest（jsdom）。純関数・コマンド・シリアライズなど、書けるものはここへ
- `rust` — `cargo test`。ファイル I/O と `slides://` のルーティング
- `手動` — **手で確認する。** E2E の自動テストは持たない（[ADR-0009](../../adr/0009-drop-smoke-e2e.md)）

**`手動` の行はそのままチェックリストとして使う。** 実ブラウザでの見え方・実マウスの操作・
実寸のレイアウト・フォーカスの移動は jsdom では見えないので、
**何を見れば良いかが分かる粒度**で書く（操作手順ではなく、確認したい事実を書く）。
