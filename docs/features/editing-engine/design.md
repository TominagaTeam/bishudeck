# editing-engine — 機能設計

## 概要

編集ステージ上での選択・移動・リサイズ・テキスト編集・スタイル変更と、その履歴。
**すべての変更は Command を経由する**([ADR-0003](../../adr/0003-all-edits-as-commands.md))。

## 責務と境界

**やること**: uid の付与と DOM ブリッジ / 選択モデル / ジェスチャ / 標準コマンド / 履歴 / スタイルインスペクタ

**やらないこと**

- HTML の取り込みと再合成(→ [import-pipeline](../import-pipeline/design.md))
- 画像のトリミング(→ [image-crop](../image-crop/design.md))
- **iframe の DOM に直接触ること以外の経路** — 触るのは `StageBridge` だけ

## インターフェース

| 入口 | 場所 |
|---|---|
| DOM ブリッジ | `src/stage/bridge.ts`(**iframe の DOM に触る唯一の窓口**) |
| コマンドエンジン / 履歴 | `src/core/commands/engine.ts` |
| 選択状態 | `src/core/selection/store.ts` |
| 選択ヒューリスティクス | `src/stage/selectionHeuristics.ts` |
| ジェスチャ | `src/stage/interactions.ts` / `geometry.ts` / `snapping.ts` |
| リッチテキスト | `src/core/editing/richText.ts` |
| インスペクタ | `src/features/Inspector.tsx` |

## uid 付与と DOM ブリッジ

- スライドを編集 iframe へロードする際、**全要素に `data-hse-uid` を付与**する
- `StageBridge` が `contentDocument` を握り、uid ⇔ 要素解決・矩形取得・DOM 変異をすべて仲介する
  (**コアは iframe を直接知らない**)
- 座標系: iframe 内 rect × キャンバスの zoom / pan 行列でホスト座標へ変換し Overlay に描画
- シリアライズ時に uid・`contenteditable`・ステージが足したクラスを完全除去する

## 選択モデル(PowerPoint 的な階層選択・単一選択)

- **クリックは「意味のある編集単位」を選ぶ。** カーソル位置の要素から祖先方向に
  ヒューリスティック(サイズ・display・セマンティクス)で編集単位を決定する
- **選択できるのは常に 1 要素。** 複数選択は一度実装したが取り下げた
  ([decisions.md](decisions.md) #1)
- **スライドそのものは選択対象にしない。** スライドはキャンバスであってその上のオブジェクトではないので、
  余白のクリックは「何もない場所」= 選択解除として扱う
- **スライドの外側も同じく「何もない場所」。** ポインタ層はスライド矩形ちょうどしか覆っていないので、
  その周りのキャンバス余白は `main.canvas` 自身が受ける。**キャンバスが直接の
  イベントターゲットであること**(`event.target === event.currentTarget`)が
  「スライドの外」の判定そのもの — 子に届いたものはステージが処理済みなので、
  `closest()` の除外リストは要らない
- **スライドの四辺すべてに(スライド幅・高さの 4% 以内まで)届いているものは、中身が何であれ背景と見なす**
- **背景と見なさないのは「それ自体が中身を持つもの」** — 画像・動画・canvas などの置換要素と、
  自前のテキストを持つ要素。ユーザーが置いたものは大きさで失格にしない
- **「自前のテキスト」はインライン要素を透過して数える。** 遡上と同じルールを使う
  (`<h1><b>見出し</b></h1>` の `h1` はテキストを持つ)。ブロックの子は辿らないので、
  段落を包んだだけの箱はテキストを持たない([decisions.md](decisions.md) #52)
- **`<ul>` / `<ol>` / `<li>` も同じく透過する。** リストはオブジェクトではなく
  **テキストボックスの中身の並び方**。透過しないと箇条書き 1 つでスライドに選択できる箱が
  2 つ増え、しかも編集ホストが `<li>` に入って **`<ul>` が編集対象の外側**に出るため、
  同じボタンで解除できなくなる(`execCommand` はホストの内側にあるリストしか外せない)
  ([decisions.md](decisions.md) #56)。
  **透過しても `<ul>` 自身がホストになる経路は残る** — スライドルート直下のリストは
  遡上が登り切れずそこで止まる。同じ制約がそのまま効くので、そちらは
  下の「編集ホストがリストを持てるか」で受ける
- **遡上はスライドルートの手前で止める。** そこまで登ると次の判定が「キャンバス」として
  弾くので、中身のクリックが「何もない場所」に化ける
- 置換要素(`img` など)は**インライン祖先の遡上を止める**。`img` の既定 display は `inline` なので、
  止めないと画像のクリックが親の段落に化ける
- **ただしトリミング枠の中の画像は、枠のほうを選ぶ。** 画像は枠より意図的に大きいので、
  画像を選ぶと**トリミング前の矩形**に選択枠とハンドルが出て、ドラッグがオブジェクトの移動ではなく
  枠内での画像スライドになる([image-crop](../image-crop/design.md))。
  枠は「中身を持つもの」に数えるので、全面写真でも背景扱いにならない
- **ダブルクリック: テキスト編集を始める**(画像なら[トリミング](../image-crop/design.md)を始める)。
  **1 階層内側へ潜る操作ではない** — 内側へは Tab(同じ親の中を巡る。[decisions.md](decisions.md) #38)と
  パンくずで行く。PowerPoint のダブルクリックと意味を揃えた結果で、経緯は
  [decisions.md](decisions.md) #59
- **編集開始のダブルクリックは、押した位置にキャレットを置くだけ。何も選択しない。**
  語を取るのは**セッションに入ってからの 2 連打**(下の「セッション中の選択もホストが引く」の表)。
  開始と同時に語が選択されていると次の 1 打で気づかず語が消えるため
  ([issues](../../issues.md) #25、[decisions.md](decisions.md) #72)
- **Esc: 1 階層外側へ。** ただしスライドルートの手前で止まり、そこから先は選択解除。
  ドラッグ中の Esc は先に「そのドラッグの取り消し」に取られる(下の「ジェスチャの取り消しと計測」)
- **Tab / Shift+Tab: 同じ親の中の次 / 前のオブジェクトへ。** クリックが選ばない兄弟(背景扱いの箱、
  中身を持たないラッパ)は飛ばし、端では折り返す。**ステージにフォーカスがあるときだけ** Tab を横取りする
  ので、ツールバーやインスペクタのタブ順は変わらない
- **Enter / F2: 選択中のテキストを編集し始める。** Esc(オブジェクトの外へ)の対になる操作
- **テキスト編集に入れるのは「自前のテキストを持つ」置換要素以外**(上の背景判定と同じ関数)。
  入口はダブルクリック・Enter / F2・右クリックメニューの **3 つ**。
  **テキストボックスの挿入は入口ではない** — 挿入は箱を置いて選択するところまでで、
  打ち始めるのはこの 3 つのどれかを通る 2 手目
  (下の「[新しいテキストボックスは空で入る](#新しいテキストボックスは空で入る)」)
- **判定は 1 箇所のままだが、3 つの入口はそれぞれ「挿入直後の箱」を追加で通す。**
  入れたばかりの箱はまだテキストを持たないので、この関数だけで測るとエディタが自分で作った箱に入れない。
  **関数のほうは緩めない** — 緩めるとデッキ由来の空 div まで編集対象になり、
  背景判定([decisions.md](decisions.md) #52)に波及する。例外は呼び出し側に
  `|| isUntouchedTextBox(uid, element)` として書き、対象は**挿入直後の 1 件だけ**
- **キャレットの行き先だけは入口で違う** — ダブルクリックは押した位置、
  Enter / F2・右クリックメニューは位置を持たないので**末尾**(空の箱ならキャレット位置は 1 つしかない)
- **Shift はジェスチャ中の修飾キー専用**(移動中は軸固定、リサイズ中は縦横比固定、回転中は 15 度刻み)。
  押下時には何の意味も持たない — 追加選択が無くなったため
- **Alt+クリック: 同じ点の 1 つ奥の要素へ**(下の「[ポインタが届かなくなった要素を拾う](#ポインタが届かなくなった要素を拾う)」)

### ポインタが届かなくなった要素を拾う

**ポインタで触れなくなる道は 1 つではない**([issues](../../issues.md) #102)。

| 何が起きたか | `elementFromPoint` | `elementsFromPoint` | 矩形が点を含むか |
|---|---|---|---|
| 不透明なオブジェクトの裏に回った | 前面の要素 | **列に入る** | 入る |
| 祖先の `overflow:hidden` に切り取られた | 別の要素 | **入らない** | **入る** |
| `pointer-events:none` が乗っている | 別の要素 | **入らない** | **入る** |

**切り取りと `pointer-events` は、描画だけでなくヒット判定からも要素を外す。**
確認用デッキの 12 枚目で実測 —— `overflow:hidden` のカードから外へドラッグした見出しは
(706, 162)–(1214, 258) にあってポインタは その中心 に立っているのに、
`elementsFromPoint` が返す 6 要素のどこにも居ない。**矩形で聞けば見つかる。**

なので列(`selectionStack`)の材料は `bridge.elementsAt` が 2 段で作る:
**ヒット判定が届くものを描画順で先に**、**届かないものを文書順の逆で後ろに**。
`z-index` を見ないのは後半だけで、前半は本物の描画順がすでに答えている。

出口は 2 つ。**同じ列を、ジェスチャは 1 歩ずつ歩き、メニューは一覧で見せる。**

- **Alt+クリック** — 押した点の列を、**押す前の選択の 1 つ奥**へ進める。端では先頭へ折り返すので、
  同じ場所を押し続ければ重なりを一周できる
- **右クリックメニューの「この位置にあるもの」** — 列をそのまま並べ、名前で選ばせる。
  **列が 1 つしか無ければ出さない**(素のクリックと同じ答えしか無いので)

**メニューを「1 つ奥へ」にしないのは、押す前に読まれるものだから。**
ジェスチャは繰り返せるので 1 歩でよく、外れても次の 1 歩で直る。
メニューは開いた時点で選択肢が確定するので、「奥」が何を指すのかを読み手に当てさせることになる。
一覧なら、そこに何があるかを**見てから**選べる。

**項目を指すと、その要素をステージ上に破線の枠で示す**(パンくずと同じ `focusUid` / 同じ理由。
`div.card` というラベルだけでは、どの箱を指しているのか選んでみるまで分からない)。
**メニューが閉じたら枠を落とす** —— 項目を選んだ時にもメニューは閉じるが、
そのとき `pointerleave` は来ない。

決め方は 3 つ:

- **列は「クリックが選ぶもの」で作る。** 生の当たりではなく `chooseSelectionTarget` を通した結果を
  重複を潰して並べるので、背景と見なす箱・スライドルート・単語とその `<span>` は列に現れない。
  **祖先は残す** — ポインタの下にあり、実際に奥に描かれているため。Esc やパンくずでも行けることは、
  この道を間違いにしない
- **デッキが自分で隠しているもの(`visibility:hidden`)は列に入れない。**
  `display:none` は矩形を持たないので判定が要らない。**切り取られた要素とは別物** ——
  前者はデッキの意思、後者は「ユーザーが今そこへ動かして、選択枠まで見えている」もの
- **Alt の意味が 2 つになるのを、押した瞬間ではなく離した瞬間に決める。** Alt ドラッグは複製で、
  そちらは**見えているもの**から始まらないと意味を成さない。ドラッグになったかどうかは
  デッドゾーン(`interactions.ts`)を越えたかで決まるので、判定はポインタを離すときまで待つ。
  **押したまま動かさなければ潜る、動かせば複製** —— 複製の側は一切変えていない
- **歩き始めるのは「押す前の選択」から。** 押下はドラッグのために最前面を選び直すので、
  離すときの選択を読むと**何度 Alt+クリックしても同じ 2 番目**で止まる

**選べても、次のクリックはまた最前面に当たる。** ドラッグの入口は選択枠のほうに置く。

#### そもそも見失わせない —— ドラッグは見える範囲で止める

拾う手段より先に、**ドラッグで見失わないこと**が要る。移動は
**要素の 24px(`MIN_VISIBLE`)を、その要素が見える範囲の中に必ず残す**。

- **「見える範囲」は、スライドを、あいだの祖先の `overflow` で狭めたもの**(`visibleBounds`)。
  スライドルート自身も含む —— 取り込みが `overflow:hidden` を敷く
  ([deckStage.ts](../import-pipeline/design.md))ので、**スライドの外へドラッグするのも
  カードの外へドラッグするのと同じ失い方**になる
- **止めるのは吸着のあと。** ここだけはジェスチャが言い抜けできない
- **デッキの `overflow` は切らない。** 祖先の `overflow` を上書きすれば見えるようにはできるが、
  それはユーザーが選んでいない要素への編集で、**丸めや他の子のはみ出し方まで変わる**(不変条件 2)。
  端で止めるほうが、デッキに何も起こらない
- **すでに外へ出ている要素は、最初の 1px で戻ってくる。** 止める規則は現在位置から測るので、
  枠の辺を少し引くだけで 24px が見える位置まで引き戻される(実測: 重なり **−139px → 24px**)
- 判定は 2 点で**緩い側に倒してある** —— ボーダーの内側ではなく外側で測る / 包含ブロックの連鎖は
  厳密には辿らない。**取りこぼしても他の拾い方がある**が、**行き過ぎると正当なドラッグを拒む**ため

**矢印キーの移動には掛けていない。** キーは「押しただけ動く」ものなので、
外に出ている要素を 1 回の押下で引き戻すのは意味が合わない。1px / 10px 刻みでは
1 回のジェスチャで見失うこともない。**リサイズにも掛けていない**(同じ理由で、
1 回で全部を外へ追い出すことがない)。

#### 選択枠の辺を掴んで動かす

選択枠の**四辺に、見えない 7px の掴みしろ**を敷く(`MoveGrips` / `stage/Overlay.tsx`)。
押すとその**選択中の要素**の移動が始まる —— ポインタがそこで何に当たるかに関係なく。

- **理由はリサイズハンドルとまったく同じ。** 枠もハンドルもステージの外(ホスト側)に描いてある
  (不変条件 15)ので、下の要素が切り取られていようが覆われていようが届く。
  **動かせないのにリサイズはできる**、という半端な状態のほうがおかしかった
- **辺だけで、中は塗らない。** 中まで掴みしろにすると、選択中のパネルの上に載っている小さな要素が
  **二度とクリックできなくなる**(選択が自分の領域のクリックを全部食う)。辺は、誰が見ても枠の一部
- **ハンドルより先に描く。** 角と辺の中点では両方が重なるので、後に描いたハンドルが勝つ。
  掴みしろが勝つと角でリサイズできなくなる
- テキスト編集中は出さない(枠の上の押下は「そこにキャレットを置く」意味になり、
  要素の周りの押下はすでにシールドが持っている)

実測(実アプリ・実マウス): 切り取られて見えない見出しを右クリックの一覧から選び、枠の下辺を
(345,236)→(385,416) にドラッグ。`translate(91.29px, 410.81px)` が付いて**高さは 80px のまま**
(移動であってリサイズではない)、画面上の移動量との比は両軸とも 0.438 で一致。
**⌘Z 1 回で元の transform に戻る**(不変条件 13)。

### ホバー枠はスライドが変わったら消す

ポインタが乗っている要素にはホバー枠を出す。**消えるきっかけは 2 つ** —
ポインタがステージから出たときと、**開いているスライドが変わったとき**。
後者を忘れると、ポインタをステージに置いたまま ← → やサムネイルで送ったときに、
**前のスライドの座標に枠が描かれたまま**残る([issues](../../issues.md) #13)。
テキスト編集中は枠を出さない(操作レイヤ自体が入力を通さなくなる)。

### パンくず

選択中の要素の系譜(`div.container > h1`)は**常時見えるところに置く** — インスペクタ側は
折りたたみの対象にすらしない。畳めるようにすると、入れ子の奥へ入った選択から
**クリックで戻る道が一緒に消える**ため。出る先は 2 つで、**クリックで階層を移動できるパンくずはインスペクタ**
([inspector](../inspector/design.md))、**ステータスバーは読むだけの 1 行**
(スロットの並びは [07-ui-system](../../basic-design/07-ui-system.md) の「ステータスバー」)。

**スライドルートは載せない** — パンくずの各項目はクリックで選択できるので、載せると上記のルールすべてを
1 クリックで迂回して「スライド全体を選択」できてしまう。

**項目を指すと、その要素をステージ上に破線の枠で示す**(マウスオーバーとキーボードフォーカスの両方)。
`div.container` というラベルだけでは、ラッパーが何重にも重なった AI 生成デッキの
どの箱を指しているのか**選んでみるまで分からない**状態だった。指した時点で答えを見せる。

- この状態は選択とは別の **`focusUid`** に持つ(`src/core/selection/store.ts`)。
  `uid` に混ぜると、インスペクタ・コマンド・履歴といった下流がマウスの通り道を編集対象と見なす
- 枠は**破線 + 薄い塗り**で、選択枠(実線 + ハンドル)と描き分ける
- **すでに選択中の項目には出さない。** 同じ矩形に枠が二重に乗ると描画の乱れにしか見えない

## インライン編集の抜け方

前提: **WebKit はスクリプト無効の document でリスナを動かさない。**

**2026-08-25 に実機で測り直した。** フレームの document に `keydown` / `input` /
`pointerdown` / `paste` / `dragstart` / `focusin` を capture で並べて張り、
`npm run tauri dev` の実ウィンドウで編集して打鍵・⌘Z を送った結果は **1 種類も発火しない**。
文字は打てているのでフレームはキーを受け取っており、**ホストから張ったリスナだけが呼ばれない**。
この前提の上に建っているもの（下のシールド・オーバーレイ・MutationObserver への相乗り）は、
**単純化できない**([issues](../../issues.md) #89)。

編集ステージの iframe は `allow-scripts` なしの sandbox なので、その document は「スクリプト無効」になる。
**WebKit(= WKWebView)はスクリプト無効の document では、親フレームから `addEventListener` した
リスナすら一切発火させない**(Safari での実測により確認。合成イベントの dispatch でも呼ばれない)。
Chromium は発火させるため、**ブラウザ(`npm run dev`)では動いて実アプリで壊れる**という罠になる。

一方で `focus()` / Selection API / `execCommand` を親から**呼ぶ**のは WebKit でも動く。
つまり **iframe の中で「起きたこと」は観測できないが、iframe に「させること」はできる。**
編集まわりの仕組みはすべてこの前提で組む。

- **セッション終了はすべてホスト側の要素で受ける。** 編集中はオーバーレイに「シールド」
  (編集中要素の外接矩形を除いた 4 枚の透明な帯)を張り、ステージ内のクリックはそこで受けて
  セッションを閉じ、クリック先の要素を hit-test(`elementFromPoint` を親から呼ぶのは可)で選択する
- **編集中要素の上も 1 枚のホスト要素で覆う**(`.overlay-text-shield`)。かつては穴を開けて
  キャレットとドラッグ選択をブラウザに任せていたが、それができるのは
  「ブラウザの答えが常に正しい」場合だけだった(下記)
- **編集中は選択枠の線だけを数 px 外へ逃がす**(`EDIT_FRAME_GAP`, `stage/Overlay.tsx`)。
  枠は要素の境界に置かれ、`box-sizing: border-box` なので線は境界の**内側**に落ちる ——
  そこはキャレットが立つ場所でもある。空の箱ではキャレットもエディタの青なので
  (`stage/placeholder.ts`)、同じ位置に同じ色が重なって**キャレットが消えて見える**
  ([issues](../../issues.md) #99)。線は `outline` + `outline-offset` で外に出し、
  border は透明にして残すので**塗りの届く範囲は要素の端のまま**。ホスト側の chrome だけの話で、
  スライドの markup には触れない(不変条件 15)
- ステージ外(ツールバー・パネル・キャンバス余白)はホスト window の capture フェーズ pointerdown で閉じる。
  ただし `data-hse-text-tools` を持つ文字書式パネルは例外(開いているセッションに対して働くため)
- キャレットが iframe 内にある間、キー入力は iframe に落ちてホストから観測できない
  (= WKWebView では Esc が効かない)。**どのエンジンでも確実に効く出口はホスト側の要素へのクリック**。
  frame document への Escape リスナは残してあるが、これは Chromium でだけ効く補助
- **⌘Z / ⌘⇧Z も同じ壁の向こうにある。** `App.tsx` の窓口はホスト window にしか付いていないので、
  キャレットがフレームにある間の ⌘Z は**ブラウザのネイティブ undo に取られる** ——
  アプリの履歴は動かないまま DOM だけが戻り、**戻った markup は `data-hse-uid` を失う**。
  uid を失った要素はクリックしても選べない(不変条件 6)。**2 段構えで受ける**:
  ①frame document の keydown で横取りして `preventDefault` し、アプリの undo / redo に回す
  (**Chromium でだけ効く**)②どのエンジンでも効く保険として、変異が落ち着いた rAF で
  **uid を持たない要素が箱の中にあれば `reindex()` を回す**。
  ②が狙うのは履歴の辻褄合わせではなく「**取り返しのつかない状態にしない**」ところまで。
  **WKWebView ではネイティブ undo が勝ったままで、アプリの履歴と DOM はずれる**
  ([issues](../../issues.md) に負債として記録)
- タイピング中のオーバーレイ追従は **MutationObserver**(イベントではないのでスクリプト無効 document でも記録される)

**フォーカスはフレームの境界を越えて渡す。** キャレットは
「**フォーカスされたフレームの、フォーカスされた要素**」にしか描かれない。
ところがセッションを開くきっかけの press は `handleLayerPointerDown` が
**ホスト側の `.stage-interaction` にフォーカスを載せている**(ダブルクリックなら 2 回)。
`element.focus()` だけでは、フレームの中の activeElement は動いても
**ホスト文書のフォーカスはレイヤに残ったまま**になりうる。
Chromium は中の要素を focus した副作用でホストのフォーカスも iframe へ動かすので
1 行で足りていたが、それはエンジンの親切に頼っていただけ。

そこで `holdTextFocus()`(`src/stage/textSelection.ts`)が**外から内へ 3 段**で渡す —
①`iframe` 要素(ホスト文書のフォーカスをレイヤから取り返す)
②フレームの `window`(「フォーカスされたフレーム」を切り替える)
③要素そのもの。**順序は逆にできない** — ①②はフレーム側の activeElement を body に戻すので、
③を先に呼ぶと捨てられる。直前に `contenteditable` を付けた要素は
スタイル再計算が済むまで「フォーカスできない」と見なされうるので、
先頭で `offsetHeight` を読んで recalc を流す。

**キャレットの位置は要素の中に収まっているか必ず確かめる。**
`caretRangeFromPoint` は**文書**に対して答えるので、箱の padding・行間に当たった点では
隣や親の range が返る。それをそのまま張ると contenteditable でない場所にキャレットが立ち、
**何も描かれず打鍵も落ちない**。端の丸め方はエンジンごとに違うので、
Chromium で出て WKWebView で出ない、という形で表に出る。
`placeCaret` は `element.contains()` を通らない点を捨てて末尾に落とす。

**セッション中の選択もホストが引く。** 前提の裏返し —
**フレームの中で起きたことは観測できない**ので、ブラウザが選んだ答えを取り消すことができない。
すでに選択されている範囲の上で press すると、ブラウザはそれを
「新しい選択の開始」ではなく**その範囲のネイティブドラッグ**と解釈し、
`dragstart` を潰すリスナはスクリプト無効の document では動かない([issues](../../issues.md) #17)。
そこで**編集中要素の上にもホスト側の 1 枚を敷き、press をフレームに渡さない。**
フレームが press を見なければドラッグは始まりようがないので、どのエンジンでも同じ挙動になる。

選択は `caretRangeFromPoint()` と Selection API を**親から呼んで**組み立てる
(`src/stage/textSelection.ts`)。これは「させること」の側なので WebKit でも動く。
`contenteditable` が無料でくれていたものは、その分だけ自前になる。

| 操作 | 挙動 |
|---|---|
| press → drag | 押した位置をアンカーに、引いた先まで伸ばす。枠外へ出たら**直前に枠内だった位置で止める** |
| 2 連打 | その位置の単語(`Selection.modify`) |
| 3 連打 | 要素全体。4 回目からは 1 に戻る |
| Shift + press | アンカーを保って向こう端だけ動かす |

**連打の回数はホストが数える。** `PointerEvent.detail` は仕様上 0 なので、
イベントからは読めない。400ms / 4px の窓で自分で数える。

**捨てたもの: 選択した文字をドラッグして移動する**(ブラウザ標準の text drag-and-drop)。
「選択し直せない」害のほうが大きいという判断([decisions.md](decisions.md) #67)。

**セッションを閉じるときはフォーカスも返す。** `contenteditable` を外すだけではキャレットと
iframe のフォーカスが残り、ホスト window に key イベントが届かなくなる。
選択レンジを消し、要素を blur し、操作レイヤ(`tabIndex={-1}`)にフォーカスを移す。

**履歴の基準はセッションが 1 つだけ持つ。** 入力はコマンドを生まない(キーはスクリプト無効の
iframe に落ちるのでホストから見えない)ので、マークアップは履歴より先に進む。
セッションは「履歴が到達済みのマークアップ」を 1 つ持ち、**書式適用の前後**と**セッション終了時**に
そこからの差分だけを積んで基準を進める。2 箇所が別々の基準(片方はセッション開始時)から記録すると、
同じ変更が二重に積まれ、**Undo 1 回目が何も起きないステップ**になる([decisions.md](decisions.md) #53)。
セッション中に Undo / Redo が走ったときは、履歴ストアの購読で基準を追従させる。

**追従させるのは Undo / Redo のときだけ。** 購読しているのは履歴ストアそのものなので、
`execute()` の push でも同じ通知が飛ぶ。push で基準を進めると、**そこまでの入力を
「その入力に触っていないコマンド」に渡してしまう** — 入力はどちらのステップにも属さなくなり、
セッション終了時の `commitTextSession()` は記録するものが無くなる。
文字を打ってから行揃えを押すと履歴に 1 手しか残らず、戻しても行揃えだけが戻って
**打った文字は戻らなかった**([issues](../../issues.md) #44)。
判定は `useHistory` の `lastAt` で、`execute()` が時刻を書き、`undo` / `redo` / `revoke` が 0 に戻す。
**ストアが既に引いている線**なので、同期させ続ける 2 つ目のフィールドも、
呼び出し側が渡し忘れられるフラグも要らない。

**要素スコープの編集は、先にセッションを確定してから積む。** 文字書式パネルのうち
**太さと行揃え**は範囲ではなく要素に書く(`withUndo` を通らない)ので、
`commitTextSession()` を自分で先に呼ぶ([features/inspector](../inspector/design.md))。
上のガードがあれば入力が消えることはもう無いが、**順序としてこれが正しい** —
行揃えは要素の中のリストノードにも書くので、後から積む `SetInnerHtmlCommand` の
マークアップにその上書きが含まれてしまい、入力を Undo するとマークアップごと差し替わって
`reindex()` が uid を配り直す。下に積まれたスタイルのコマンドは、**戻す相手を見失う**。

**同じ時点で、入力や書式が作った新しいノードに uid を配る。** `execCommand` も入力も
エディタが見たことのないノードを生む。**uid の無いノードはクリックから見えない**
(`uidOf` が null を返し、そこで止まるジェスチャが黙って何もしない)。インライン要素では
遡上が uid を持つ親まで登るので表面化しないが、箇条書きが作る `<ul>` / `<li>` は
ブロックなのでクリックはそこで止まり、**選択も再編集もできない行**になる
([decisions.md](decisions.md) #54)。

**書式ボタンは今の状態を表示する。** B / I / U / S / 上付き は**トグル**で、押すと当てるか外すかは
キャレット位置の状態で決まる。デッキは見出しを自前で太字にしているので「触る前から太字」が
普通で、点灯しないボタンは「太字にする」に見えるのに実際はデッキの太さを**外す**。
状態は `queryCommandState` を**ポーリングして**取る(200ms) — ステージはスクリプト無効なので
`selectionchange` がホストに届かない(ADR-0002)。コマンド適用直後にも 1 回引き直して、
押した指の下でボタンが切り替わるようにする([decisions.md](decisions.md) #58)。

**トグルは 1 つのリストから描く**(`FORMAT_BUTTONS`)。点灯のクラス・`aria-pressed`・
「オンです」と伝える title は、そこに 1 度だけ書く。手書きのボタンを 1 つ混ぜると
**そのボタンだけが状態を持たない** — 上付きが実際にそうなっていた
([issues](../../issues.md) #35)。エンジンに聞くコマンドの一覧(`QUERIED_COMMANDS`)も
同じ顔ぶれで揃える。トグルでないもの(書式のクリア)だけがリストの外にいる。

### 編集ホストがリストを持てるか

**リストのボタンは、押す前に編集ホストの形を見る。** `execCommand` は**編集ホストの内側**に
しかリストを建てられず・外せず、3 つのホストがそれに引っかかる
(Chromium で `samples/generic-deck.html` の実マークアップを実測。
実装は `src/core/editing/listHost.ts`):

| ホスト | 押すと何が起きるか | どう受けるか |
|---|---|---|
| `<ul>` / `<ol>` | 戻り値は `true` なのに **DOM が 1 バイトも変わらない**。自分自身は外せないため。`queryCommandState` は「リストの中」と答えるので**ボタンは点灯したまま何も起きない** | 同じ種類を押されたら `<div>` に、各 `<li>` も `<div>` に建て替える。別の種類ならタグだけ差し替える |
| `<span>` | `display` に関わらず **`false` を返して何もしない**(Blink)。同じインライン級でも `<strong>` / `<em>` / `<b>` / `<a>` / `<label>` は通るので、インラインだからではなく**タグの特別扱い** | `<div>` に建て替えてから、通常どおり `execCommand` に渡す |
| `<p>` | リストは建つが `<p><ul>…</ul></p>` になる。**HTML パーサがこの入れ子を受け付けない**ので、読み直すと `<p></p><ul>…</ul><p></p>` — 箱が空になり、リストが箱の外へ出て、空の段落が増える(不変条件 2 ②) | 同上 |

デッキが元から持っている箇条書きは、遡上が `<li>` と `<ul>` を透過してスライドルートの
手前で止まるので **`<ul>` がそのままテキストボックス**になる。1 行目はそこで必ず起きる
([issues](../../issues.md) #98)。

**建て替えはホスト要素そのものの差し替えで、uid は引き継ぐ**(不変条件 6)。
タグが変わるとデッキの `p { … }` / `ul { … }` が当たらなくなるので、
**差し替えの前後で computed を測り、変わった宣言だけ**をインラインの上書きとして書き戻す
(ADR-0004。デッキの CSS は書き換えない)。運ぶのは文字まわりの宣言だけで、
リストが持っていた箱の性質(行頭記号の溝・UA の上下マージン・記号の置き方)は
**インラインに書いてあっても落とす** —— 誰が書いたかは区別できないが、
行頭記号が消えた箱に記号のための余白を残す意味はない
(実測: 落とさないと `padding-left: 1.2em` = **31.2px** の字下げだけが残る)。
`text-align` だけは残す。行揃えは行についての指定で、リストより長生きする。

**書き戻す値は computed なので、`line-height: 2` のような相対指定は px で焼き付く**(`52px`)。
後から箱の文字サイズを変えても行間が追従しなくなる ——
インスペクタのブラシ([issues](../../issues.md) #31)が持つのと同じ性質で、
「今の見た目」で固定する上書きである以上は避けられない。

**編集ホストを一段上げる道は採らなかった。** スライドルートを一時的に `contenteditable` に
すれば `execCommand` はリストを外側から見られるが、実測すると解除が
**空の `<ul>` + 行ごとの `<span style="font-size:26px">` + 改行の消失**を残す。
さらにキャレット 1 点でリストが 3 つに割れるので、**1 つだったテキストボックスが 3 つに増える** ——
uid で箱を指す前提(不変条件 6)と噛み合わない。

**記録は `HtmlSnapshotCommand` 1 本。** `SetInnerHtmlCommand` は要素を名指しして**中身**を
書き換えるので、要素そのものが入れ替わる建て替えは表現できない(undo が古い中身を新しいタグへ
戻して辻褄が合ったことにしてしまう)。構造を変える他の編集と同じ経路に乗せ、
1 回の押下は 1 undo ステップのまま。建て替えの前に `commitTextSession()` を通し、
そこまでの打鍵を別のステップにしておく — さもないとリストの undo が打鍵まで巻き取る。

**キャレットは境界のノードと文字位置を控えて張り直す。** `Range` はライブなので、
子ノードを移した時点で境界が親へ繰り上がり、要素を外すとさらに上へ逃げる。
持ち越せるのは Range そのものではなく**中のテキストノードとオフセット**で、
テキストノード以外を指していた選択は建て替え後のホスト全体に倒す。

### リストの見た目をエンジンに任せない

**リストの適用・解除は「リストかどうか」だけを変える。** エンジンはそう思っておらず、
解除のときに**リストの中で持っていたサイズをインラインの `<span>` に焼き付けて**返してくる
(デッキが `ul { font-size: 26px }` なら、44px の見出しが往復して 26px になる)。
コマンドが**新しく作った** `<span>` のうち、**それまでのマークアップに無かった宣言**を持つものを
剥がして打ち消す。既にあった宣言を言い直しているだけのものは、ユーザーの指定をエンジンが
組み直したものなので残す。剥がす前後で選択は**文字数オフセット**として保存・復元する
([decisions.md](decisions.md) #57)。

**そのうえで、建てたリストに要素の行揃えを配り直す。** `execCommand` が作る `ul` は
自分の行揃えを持たず、外側から継承しても行までは届かない
([inspector/design.md](../inspector/design.md) の「要素スコープの上書きは、リストの中まで届かせる」)。
配り直さないと、**中央揃えにしてから箇条書きにした**ときだけ崩れる。
誰も行揃えを触っていない要素(computed が `start`)には何も書かない。
**配り直すのは行揃えだけ。** サイズ・色には「未指定」を表す computed が無いので、
ここに載せると箇条書きを 1 回押しただけで全デッキのリストに上書きが書き込まれる
([inspector/decisions.md](../inspector/decisions.md) #39)。
コマンドは別に積まず、`withUndo` の中で DOM に書く — 直後の `commitTextSession()` が拾う
`innerHTML` の差分に含まれるので、**リスト化は 1 undo ステップのまま**([decisions.md](decisions.md) #73)。

**さらに、建てたリストを箱に収める。** これは継承の話ではなく**箱に収まるか**の話で、
行揃えの配り直しとは別の問いに答えている。リスト化した瞬間に、箱から出ていく道が 2 つある
(挿入する 520×90 の箱・`font-size:28px` で実測):

- **下へ** — UA スタイルが `<ul>` に `margin-block: 1em`(28px × 2 = 56px)を与えるので、
  リストは行の高さより 56px 高い。リセットを持たないデッキで **64px** はみ出した
- **左へ** — `list-style-position: outside` の行頭記号は**リスト自身の
  `padding-inline-start` の中**に描かれる。`* { margin: 0; padding: 0 }` のリセットを持つデッキは
  その余白が無いので、記号が**負の x**(箱の完全な外)に落ちる

そこで作成直後に、①行頭記号が必要とする幅を**実測して**余白を確保し、
②上下マージンを 0 に潰し、③それでも内容が箱を超えるなら `height` を伸ばす。

**①の幅は決め打ちにできない。** 最初は `1.2em`(箇条書きの慣習値)を書いていたが、
番号付きの行頭記号はずっと幅を食う —— ユーザーのデッキの **76px の見出しを `1.` にすると
マーカーだけで 89.02px** を要求し、1.2em(91.2px)は**余裕がわずか 2.18px** で
枠線に接して見え、`10.` に届けば確実に外へ出る。

**マーカーの幅は DOM からは訊けない。** `::marker` は箱を渡してくれず、
`getComputedStyle(li, '::marker')` が答えるのは種別と色だけ。
だが `list-style-position` の 2 つの値は**同じマーカーを違う場所に置く** ——
`outside` は行から外へ吊るすので文字は項目のコンテンツ端から始まり、
`inside` は行の中に置くので文字はマーカーの後ろから始まる。
**その差がマーカーの送り幅そのもの**なので、一時的に `inside` へ倒して
文字の開始位置がどれだけ動いたかを測る(`measureMarkerAdvance`)。
測ったら必ず元へ戻す。書体・字数・カウンタ種別に依らず答えが出る。

確保するのは**実測値 + 0.3em**。文字に接して見えないための余白で、
`1.` の一覧が `10.` に届いたときの 2 桁目の分でもある。
**em で書く**ので、あとで文字サイズを変えてもマーカーと一緒に動く。
測れなかったとき(項目がまだ無い等)だけ `1.2em` に落ちる。
`padding` / `margin` を書くのはここだけで、**行揃えの配り直しの後**に走る
(左揃えの枝が `padding-left` を空にするので、先に書くと消える)。
**対象は「今この 1 押しが建てたリスト」だけ** — 作成前後の差分で取るので、
同じ箱にデッキ作者が書いたリストがあっても触らない。
`list-style-position` が `inside` のとき(中央・右揃えの枝)は記号が行の中にいるので余白は書かない。

**文字書式は「選択範囲の退避 → 復元」で守る。** ネイティブの select やカラーダイアログは
フォーカスを奪い、WebKit はその時点で iframe の選択範囲を失う。文字書式パネルへの
pointerdown(capture)の瞬間 — まだ選択が生きている — に Range を退避し、
コマンド実行直前に「要素内に生きた非折りたたみ選択が無ければ」復元してから `execCommand` する。
ユーザーが置いたキャレット(折りたたみ)も意図として退避・復元する。
**`focus()` が作る人工的なキャレットは信用しない**(復元をスキップする根拠にしない)。

**サイズだけは、同じ範囲への 2 回目以降を `execCommand` に通さない。** インスペクタの
サイズ欄は 1 打鍵ごとに当たるので、毎回通すと `<span>` が入れ子になり、テキストに近い内側が
勝って**打っても大きさが変わらなく**なる。`setFontSize` は直前に作った `<span>` を覚えておき、
**退避・復元した Range の境界がそれと一致する間だけ** `font-size` を差し替える
(一致しなくなれば通常の経路に戻る)。包んだ `<span>` の内側に残った `font-size` 宣言は剥がす —
宣言はテキストに近いほうが勝つため。理由と却下案は
[inspector/decisions.md](../inspector/decisions.md) #26。

## 新しいテキストボックスは空で入る

挿入されるテキストボックスは**中身を持たない**(`textBoxHtml`)。
かつては `テキストを入力` を実データとして入れていたが、それは
**エディタが選んだ言葉をユーザーの文書に置く**ことで、気づいて消さないかぎり
書き出した HTML にそのまま残った。

空の箱は見えないので、代わりに 4 つを組み合わせる。

**箱の高さは中身が決める。** 挿入する箱は `height` を持たず、`min-height` を**1 行分**だけ持つ。
Enter で行が増えれば箱もその場で伸びる —— **何も観測しなくていい**のがこの形の要点で、
ステージのフレームはスクリプトを走らせないので**打鍵はホストから見えない**(ADR-0002)。
かつては `height:90px` を書いていて、何行入れても 90px のままだった。

床(`min-height`)が要るのは、**空の箱を掴めるようにする**ため。
高さを一切書かないと空の箱は 0px になる —— 上に描くプレースホルダは通常フローの外にある
擬似要素なので箱の高さに寄与しない —— 選択枠もハンドルも太さのない線の上に描かれてしまう。

| 仕掛け | どこ | 何のため |
|---|---|---|
| 挿入したら**選択した状態で置く**(編集セッションには入らない) | `insertTextBox`(`src/core/editing/textBox.ts`) | 選択枠とハンドルが「そこに箱がある」ことを伝え、**まず動かせる** |
| **空の要素にプレースホルダを描く**(編集中の要素と、挿入直後の選択中の箱) | 編集ステージの注入 CSS(`::before`)+ `src/stage/placeholder.ts` | 何を打つ場所なのかを伝える |
| **空の箱への再入場を許す** | `isUntouchedTextBox`(挿入直後の 1 件)と `isKnownTextBox`(印の付いた箱・`selectionHeuristics.ts`)。呼び出しは `EditStage` の 3 つの入口 | 自分で入れた箱にも、**自分で空にした箱**にも打ち始められる |
| **一文字も入らなければ挿入ごと取り消す** | **選択が離れたとき / スライドが変わったとき**(`dropTextBox`) | 見えない空の箱を置き去りにしない |

**挿入でセッションに入らないのは、入ると動かせないから。** セッション中は操作レイヤが
`pointerEvents: 'none'` になり、Overlay もハンドルと回転ハンドルを描かない。
挿入と同時に入っていたころは、**置いた箱をその場で動かす手段が無かった** —
まず位置を決め、それから打つ、という PowerPoint と同じ順番にした。

**プレースホルダは擬似要素で描く。** `::before` の `content` は DOM に無いので、
シリアライズにも複製にも書き出しにも入りようがない(不変条件 2)。

**「デッキ側の空要素には出さない」ガードは CSS から script に降りた。**
セレクタは以前 `[contenteditable="true"][data-hse-blank]` で、
`contenteditable` が付くのは編集中の要素だけ、という事実がガードを兼ねていた。
挿入直後の箱は**選択されているだけ**で `contenteditable` を持たないので、それでは出せない。
セレクタは `[data-hse-blank]` だけにし、**印を付ける相手を script が決める** —
編集中の要素と、`pendingTextBoxUid()` が指す 1 件だけ。「選択中の空要素」に広げてはいけない
(デッキがパネルや罫線に使う空の div をクリックしただけでプレースホルダが出る)。
判定を CSS から降ろすのは [decisions.md](decisions.md) #78 と同じ手で、その延長にある。
**`caret-color` の宣言だけは `[contenteditable="true"]` を残す** —
選択しているだけの箱にキャレットは無いので、色を宣言する意味が無い。

### ユーザーが空にした箱も「箱」のまま残す

**印(`data-hse-blank`)はセッションを抜けても外さない。** 外していたころ、
文字を全部消してフォーカスを外すと**その箱は二度と触れなくなっていた**
([issues](../../issues.md) #104)。印が無ければデッキ自身の空 `<div>` と区別が付かないので:

- `isTextEditable` が false になり、ダブルクリック・Enter / F2・右クリックの**入口が 3 つとも閉じる**
- `isSelfContained` が false になり、クリックが**背後のパネルに登る**
- 下の CSS の床が当たらなくなり、箱が**幅 0 に潰れて掴めない**

**印を見るのは `selectionHeuristics.ts` の `isKnownTextBox`。**
「今テキストを持っているか」(`hasOwnText`)はデッキの markup に対しては正しい問いで、
パネル・罫線・スペーサに使われる空の `<div>` を編集可能にしないための一線
([decisions.md](decisions.md) #52・#75)。**ユーザーが空にした箱にだけ答えを変える**手段が印で、
印を書くのはステージだけなので、デッキが持ち込んだ空要素には付かない。

**空の箱には編集ステージ限定の床を敷く**(`min-width` / `min-height`, `placeholder.ts`)。
プレースホルダは通常フローの外、キャレットには幅が無いので、**空の箱には面積が無い** ——
`elementFromPoint` は中心を突いても背後の祖先を返し、クリックで選べない。
実デッキ(`samples/local/claude-code-basics.html`)の実測では、
**262 のテキスト要素のうち 122 が空にした瞬間に幅 0**になり、うち 99 が flex 行の中の `<span>`。
床を敷いた後は **0 / 262 が編集不能、7 / 262 が幅 0**(残りは元から 0×0 の要素と SVG の `<text>`)。
CSS は注入スタイルシート側なので**書き出しにも保存にも入らない**(不変条件 2)。

**⌘Z のあとは印を貼り直す。** 印の付いた箱に履歴が文字を戻すとき、
セッションはもう開いていないので**印を同期する観測者がいない** ——
戻ってきた文字の上にプレースホルダが描かれる。`useHistory` の購読で
印の付いた要素だけを `syncBlankMark` に通す(`EditStage`)。

**残っている穴**: 印は DOM にしか無く、保存される markup には入らない(`data-hse-*` は
シリアライズで落ちる)。**スライドを切り替えて戻る・保存して開き直すと、空の箱は
デッキの空要素に戻る**。区別を残すには markup に印を書くしかなく、それは不変条件 2 に触れる。

**空の要素にはキャレットが描かれないので、行を 1 つ貸す。**
空の要素は**行ボックスを持たない**ので、キャレットには立つ場所が無い。
Chromium 実測(本番と同じ `sandbox="allow-same-origin"` のフレーム・同じ注入 CSS)では、
`document.hasFocus()` も `activeElement` も `(div, 0)` の collapsed range も
**すべてホストから見て正しい**のに、点滅するものは何も描かれなかった。
`<br>` を 1 つ入れると出た。**プレースホルダを通常フローから外すだけでは出ない。**

その `<br>` はセッションの足場で、出口は 2 つある —
最初の打鍵でブラウザ自身が消す(`execCommand('insertText','あいう')` 後の innerHTML は `あいう` のみ)か、
一文字も打たれなければセッション終了時に `dropCaretLine` が回収する。
**まだ空のあいだしか回収しない**ので、打った人の改行は消さない。
デッキが自分で書いた `<br>` は掴まない(印 `data-hse-caret-line` が付いたものだけが対象)。
`isBlank()` は `textContent` を見るので、これを入れても「空」の判定は動かない。

**プレースホルダは通常フローから外す。** フロー内では行頭の実インラインボックスになり、
その後ろに立つキャレットが `テキストを入力|` と**文字列の末尾**に描かれた。
`position: absolute` にしてオフセットを全部 `auto` のままにすると
static position(フロー内で座っていたはずの位置)を保つので、余白も `text-align` もそのままに
`|テキストを入力` になる。要素側に `position: relative` は**当てない** —
このセレクタはセッション中に中身を消した要素にも当たるので、
デッキが絶対配置している見出しが「最後の 1 文字を消した瞬間に飛ぶ」ことになる。

**キャレットの色は空のときだけエディタの色にする。** 既定では `color` に従うが、
挿入する箱は `color:#14161a` を決め打ちで持つので、暗いデッキでは
「箱がここにある」と伝える唯一のものが背景に溶ける。文字がある要素では
`color` に従うのが正しい(デッキがその色で読めることを既に証明している)。

**「空か」はセレクタでは決められない。** CSS にテキストノードを見る手段が無いため。
`:empty` だけでは**中身を全部消したときにブラウザが残す `<br>` 1 つ**を拾えず、
そこを `:has(> br:only-child)` で補っていた。だが `:only-child` が数えるのは**子要素だけ**で
テキストノードを無視するので、`<h1>見出し<br>2 行目</h1>` のように
**`<br>` 1 つで改行しただけの要素**まで空と判定し、書いた文字の上にプレースホルダを描いた。
**タグは無関係** — h1 / p / h2 / h3 / div / span / li / td / blockquote すべてで起き、
条件は「`<br>` がその要素の唯一の子要素であること」だけだった(issues #46)。

判定は **`isBlank()`(`src/core/editing/textBox.ts`)に一本化**する。
「編集セッションに入れるか」「使われなかった箱を取り消すか」と同じ基準で、
**空の定義がプロジェクトに 1 つ**になる(`textContent.trim()` が空、かつ img・table 等を含まない)。
結果は `data-hse-blank` として要素に載せ(`src/stage/placeholder.ts`)、CSS はその印だけを見る。

印を更新するのは 4 点。

| いつ | 何をする |
|---|---|
| **挿入直後の箱が選択された**(`selectedUid` の `useEffect`) | その 1 件にだけ印を付ける(離れたら外す) |
| セッション開始 (`startTextEditing`) | いまの中身で印を付け直す |
| セッション中の DOM 変化 (MutationObserver) | 1 文字目で消し、最後の 1 文字を消したら戻す |
| セッション終了 (`finishTextEditing`) | `contenteditable` と一緒に外す |

`data-hse-` 接頭辞なので、外し忘れてもシリアライズが剥がす(`bridge.ts` の `cleanElement`)。
セッション中の自動保存が印を書き出しに載せないことは `bridge.test.ts` で押さえている。

### 足場は markup を写す door すべてで落とす

プレースホルダの条件から `contenteditable` を外した以上、**印だけで描かれる = 印が漏れた先すべてで描かれる**。
書き出し(`serializeSlide`)だけを見ていては足りず、**markup を写す道は 3 本ある**。

| door | 何のため | `data-hse-uid` / `data-hse-slide-root` | セッションの足場 | crop 前の姿の記憶・ステージ追加クラス |
|---|---|---|---|---|
| `serializeSlide` | 保存・書き出し | 落とす | 落とす | 落とす / 戻す |
| `slideMarkup` | 履歴スナップショット | **残す** | **落とす** | **残す** |
| `stripEditorMarks` | 複製(⌘D・Alt ドラッグ)・クリップボードへのコピー(⌘C・⌘X) | **落とす** | **落とす** | 残す |

**uid は door ごとに扱いが逆になる。** 履歴では住所が無いと復元後に要素を見失う(不変条件 6)。
複製ではクローンが元と同じ住所を名乗ると解決が壊れる。
クリップボードは**別のスライドへ運ばれうる**ので、住所を持ったまま出ていくと、
貼った先で「そのスライドには居ない要素の住所」を名乗ることになる。

**足場かどうかの判断の正は `src/stage/bridge.ts` の `SCAFFOLD_ATTRIBUTES`**
(`contenteditable` / `spellcheck` / `data-hse-blank` / `data-hse-caret-line` / `data-hse-cropping`)。
定数の**名前**の正は宣言元(`stage/placeholder.ts`・`core/editing/crop.ts`)のままで、
「どれが足場か」だけを 1 箇所に集めている。**新しい `data-hse-*` を足す人はここを見る。**

`data-hse-crop-origin` / `data-hse-crop-owned` は**足場ではない** —
「今動いているセッションの状態」ではなく「**undo が戻すべき crop 前の姿の記憶**」なので、
履歴には残す。この線引きが崩れると「元の画像に戻す」が戻せなくなる。

これを落とさなかったときに実際に起きたこと: 挿入した空の箱を ⌘D で複製すると
コピーに `data-hse-blank` が付いてきて、**pending ではないので編集にも入れないのに
「テキストを入力」が描かれ続ける箱**ができた。
「挿入 → 移動 → 別要素をクリック(削除される) → ⌘Z」でも同じものが復活した。

**空のまま手放された箱は `revoke()` で消す** — 履歴から取り下げて**なかったことにする**
(`src/core/commands/engine.ts`)。Undo ではないのは、Undo だと頼んでもいない箱が
redo に残り、消すのにもう一手かかるため。取り消せるのは**最新の 1 手だけ**なので、
挿入の後に別のコマンド(空の箱を動かした・インスペクタで書体を選んだ)が積まれていたら、
そのときだけ削除を 1 コマンドとして積む。つまり
**「挿入 → ドラッグで移動 → 一文字も打たずに他をクリック」では、箱は消えて削除が履歴に 1 手積まれる。**

**「手放した」の合図は 2 つ。** 挿入がセッションを開かなくなったので、
セッション終了だけを見ていると見えない空の箱がスライドに溜まる。

| 合図 | どこで見る | なぜそこか |
|---|---|---|
| **選択が箱から離れた**(別の要素・選択解除) | `useSelectionStore.subscribe`(`EditStage`) | React の再描画を待つと、**箱を 2 つ続けて挿入したとき 1 つ目を取りこぼす**(2 件目の挿入が記録を先に上書きする)。取り下げは選択を挿入前へ戻すので、**行き先の選択を取っておいて戻す** |
| **スライドが変わった** | `editorEvents.on('slide:changed')`(`EditStage`) | ストアが**同期的に**流すので、フレームが差し替わる前に走る。`[slideId]` の `useEffect` では遅く、そこで取り下げると**前のスライドの markup を次のスライドへ書いてしまう**(そちらには記録を捨てる `forgetTextBox()` だけを置く) |

セッション終了時(`finishTextEditing`)の取り下げも**残している** —
ダブルクリックで入って一文字も打たずに抜けたときは、まだ選択が箱に乗っているので、
選択が離れるのを待つと**見えない箱が選択枠付きで残る**時間ができる。

**消える対象は「挿入した直後の箱」だけ。** `textBox.ts` が覚えているのはその 1 件で、
中身が入れば忘れる。**既存の文章を全部消して抜けても要素は残る** —
それはユーザーの要素であって、エディタが勝手に消してよいものではない(rules §0-1)。

## 改行はブラウザが `<div>` で作る。セッションの出口で 1 枚だけ畳む

`contenteditable` の中で Enter を押すと、ブラウザは新しい行を **`<div>` で包む**。
`defaultParagraphSeparator` が選べるのは `div` か `p` かだけで、**包まない選択肢は無い**。
横取りもできない — 編集フレームはスクリプト無効なので、キーはホストから観測できない
(上の「[インライン編集の抜け方](#インライン編集の抜け方)」)。

結果、実測でこうなる:

| 操作 | 中身 |
|---|---|
| 空の箱に 1 文字 | `あ` (裸のテキストノード) |
| 空の箱で Enter 1 回 | `<div><br></div><div><br></div>` |
| `あ` の後で Enter → `い` | `あ<div>い</div>` |

1 行目だけ裸で 2 行目以降が包まれる**非対称**になり、
`<div uid><div>あ</div></div>` のように**箱の下に要らない階層が 1 枚増える**。
`<p>` の中で押すと `<p>abc<div>z</div></p>` になり、
再パースで `<p>abc</p><div>z</div><p></p>` に割れる(不変条件 2 ②の破れ)。

**そこでセッション終了時に、箱直下の単独ラッパーだけを畳む**(`src/core/editing/paragraphs.ts`)。
条件は 3 つ全部 — ①子ノードがちょうど 1 つ ②それが `<div>` ③`data-hse-uid` 以外の属性を持たない。
**複数行の `<div>` は改行の意味を持つので触らない。**

**そのうえで、末尾の空の段落を落とす。** Enter は編集を確定するキーではないが、
**「終わった」の意味で押される**。`aaa` のあとに押すと `aaa<div><br></div>` が残り、
子が 2 つなので上の単独ラッパーの規則は対象外にする。しかもその空 `<div>` は
`reindex()` で uid を貰うので**独立して選択できる要素**になり、箱の中に選択枠が 2 つ出る
(ユーザー報告・実デッキで実測)。

落とすのは**末尾だけ、かつ中身が読めないものだけ**。
段落の**あいだ**の空行はユーザーが空けた間隔なので残す。属性を持つブロックも残す
(`execCommand('justifyCenter')` が単一行の箱に置く `<div style="text-align:center">` を
剥がすと、揃えた行が動く)。**単独ラッパーを畳む前に走らせる** —
末尾を落とした結果が単独ラッパーになることがあるため
(`<div>aaa</div><div><br></div>` → `<div>aaa</div>` → `aaa`)。

置く場所はセッションの**出口**で、`commitTextSession()` の中ではない。
`withUndo` は書式コマンド 1 回につき `commitTextSession` を 2 回呼ぶので、
セッション中に走ると `<div><br></div>` が畳まれて**キャレットの container ごと消える**。
出口ならキャレットはもう失われているので、乗り換え先を考えなくてよい。

**貼り付けの洗浄が unwrap しない([decisions.md](decisions.md) #62)のとは別の話。**
洗浄が扱うのは**他所から来たマークアップ**で、剥がすとレイアウトが変わる。
こちらは**エディタのセッション中にブラウザが勝手に足した包み**で、
「属性を 1 つも持たない」という条件が「剥がしても見た目が変わらない」の代わりになっている。
残るリスクは、デッキが `.box > div` や `:nth-child` で裸の `<div>` を名指ししている場合
(不変条件 2 ③)。属性ゼロで線を引いただけなので、当たり方が変わる可能性は残る。

## セッション中のキーはブラウザのものになる

編集フレームはスクリプト無効なので、**キャレットがフレームの中にある間、
ホストは `keydown` を一切受け取らない**([ADR-0002](../../adr/0002-edit-preview-separation.md))。
⌘B / ⌘I / ⌘U も ⌘Z も、その間はブラウザ標準の `contenteditable` の挙動になる。

**それでも結果は履歴に載る。** セッションを閉じるときに `commitTextSession()` が
基準マークアップとの差分を「テキストを編集」コマンドとして記録するので、
⌘B で当てた書式も Undo 1 回で戻せるし、書き出しにも届く(手で確かめる範囲。[test.md](test.md))。

実際に残るズレは 2 点で、どちらも[許容](../../issues.md)している。

| ズレ | 評価 |
|---|---|
| ⌘B がそれ自体で 1 undo ステップにならず、入力とまとめて記録される | 不変条件 13「連続ジェスチャは 1 undo ステップ」とは**整合的**。取り立てて直す理由が無い |
| セッション中の ⌘Z がエディタの履歴ではなくブラウザ側の undo に行く | 直すには ADR-0002 を緩めることになり、**見合わない** |

## 貼り付けは「挿さったあとに洗う」

テキスト編集中の貼り付けは、**入ってきたマークアップを洗ってから残す**。
Word や Google ドキュメントからの貼り付けは `class="mso-*"` や
`<span style="font-size:99px">` を連れてきて、そのままスライドのマークアップに入り、
書き出した HTML にも残り、デッキ自身の CSS とぶつかる([issues](../../issues.md) #12)。

**`paste` リスナは使えない。** 編集フレームはスクリプト無効で、WebKit は
その document に付けたリスナを発火させない([ADR-0002](../../adr/0002-edit-preview-separation.md)。
⌘B が Command 履歴を通らないのと同じ壁 — [issues](../../issues.md) #2)。
一方 **MutationObserver の記録は境界を越える**ので、
テキストセッションのオーバーレイ追従に使っている観測に洗浄を相乗りさせる。
実体は `src/core/editing/paste.ts`。

残すのは**強調であって書体ではない**。

| 残す | 落とす |
|---|---|
| `<b>` `<i>` `<u>` などの要素、`font-weight` / `font-style` / `text-decoration*` | `font-size` / `font-family` / `color` / `background` などの見た目 |
| `href` `src` `alt` `title` `colspan` `rowspan` `start` | `class` / `id` / **すべての `data-*`** / `on*` |
| リストや段落の構造 | `<script>` `<style>` `<link>` `<meta>` `<iframe>` は要素ごと |

太字・斜体はユーザーが選んだ意味だが、サイズ・書体・色は**貼り元の文書のデザイン**で、
持ち込むとデッキのデザインが壊れる。`data-*` を全部落とすのは、
エディタ自身からコピーした断片が `data-hse-uid` を運んでくるため
(uid の重複は「どちらも指せない」より悪い。1 つのコマンドが 2 要素に当たる)。

**要素は unwrap しない。** `<div>` を剥がすと貼り付けた中身のレイアウトが変わる。
属性を落とした結果 `<span>` が裸で残るが、見た目も往復回数も変えないので許容する
(不変条件 2 の 3 条件を満たす)。

### 自前の書式コマンドは洗わない

`execCommand` も新しいノードを作る(`<b>`、サイズや書体を載せた `<span>`)ので、
`richText.ts` の `withUndo` が実行中だけフラグを立て、観測側はその間ノードに触らない。
**フラグを下ろすのは `mutate()` の後に積んだマイクロタスク。** 観測側の通知は
`mutate()` の最中に積まれるため、先に積むと観測より前に下りてしまい、
エディタ自身の `<b>` と span が洗われる(実際にそう書いて smoke が 3 件落ちた)。

### ブラウザ自身の編集も洗ってはいけない

**記録は「何が現れたか」しか言わない。「なぜ現れたか」は言わない。**
そしてノードを増やすのは貼り付けだけではない —— **Enter がいちばん増やす。**
Chrome は行を割るときにキャレットのいる run を丸ごと複製するので、
48px の行末で改行すると `<div><span style="font-size:48px"><br></span></div>` になる。
**ブラウザは正しい答えを、こちらに訊かずに出している。**

それを貼り付けとして洗うと、**0.2 秒後にサイズが剥ぎ取られ**、次に打った文字は箱の既定に戻る。
色と蛍光も同じ。`<b>` だけ生き残るのは、強調がもともと残す側だから。
**これがユーザー報告「フォントサイズ機能がうまく追従していません」の中身だった。**

線引きは**値で引く** —— **箱の中身が既に宣言しているものと、値まで一致する宣言は残す**。
ブラウザが編集中に作るものは必ず「箱の中に既にある run の複製」なので常に通る。
Word からの `font-size:99px` は、箱の中に 99px と言っているものが無いので通らない。
貼り元の書体がたまたま箱と一致していれば残るが、
**その文字は隣と同じに描かれる**ので見えるものは何も変わらない。

素朴な規則は実ブラウザで測って全部落ちた:

- 「エディタのコマンド中だけスキップ」(`isFormatting`) —— **こちらが作るノードしか覆わない。**
  Enter とタイピングはフラグが下りたまま来る
- 「追加ノードの**祖先**が持つ宣言を残す」—— 48px は**前の行の兄弟**にあり、祖先ではない
- 「裸の `<span style>` はブラウザ製、class 付きは Word 製」—— Google ドキュメントは裸の span を貼る

**属性は一切緩めない。** Chrome は run を `data-hse-uid` ごと複製するので、
割れた行の両方が同じ uid を名乗る(実測)。
現れたものから `data-*` を全部落とすことが uid の一意性を支えている(不変条件 6)。

### 履歴が戻した markup も洗ってはいけない

同じ観測を Undo / Redo の復元も通る。洗うと **uid が総剥がしになり**、
さらに次の Redo が「uid だけ違う」余計なコマンドを積んで redo を潰す
(実測: ⌘Z のたびに箱の中の uid が総入れ替えになり、⌘⇧Z が効かなくなる)。
`useHistory` の `lastAt === 0`(= undo / redo / revoke)で印を立て、
`withUndo` と同じくマイクロタスクで下ろす。

## 標準コマンド

| Command | 内容 | 実装メモ |
| --- | --- | --- |
| `SetTextContent` | テキスト変更 | セッションが持つ**基準マークアップ**からの差分を積む。書式適用時とセッション終了時の 2 箇所が同じ基準を進めながら記録する |
| `SetInlineStyle` | style プロパティ差分適用 | 変更前値を保持して revert。同じプロパティ集合なら 800ms 以内で `tryMerge` |
| `Translate` | transform 加算による移動 | ドラッグ中 merge、既存 transform と合成 |
| `Resize` | width / height 設定 | aspect 固定モーダル対応 |
| `InsertElement` / `RemoveElement` | 要素挿入・削除 | 挿入位置は (parentUid, index) |
| `ReorderElement` | 兄弟間の並べ替え | z 順・DOM 順 |
| `SetAttribute` | 属性変更(img src 等) | |
| `Slide*` | スライド削除 / 複製 / 並べ替え / サイズ変更 | DocumentStore 直接対象 |

**白紙のスライドを足す操作は持たない。** デッキのスライドは背景・フォント・ラッパの属性を
共有しているので、それを持たない 1 枚は列の途中で別の文書に見える。
枚数を増やす手段は取り込みと複製(`DuplicateSlideCommand`)だけにして、
新しい 1 枚は必ず既存のスライドから派生させる。

### 箱に画像を入れる(`imageFill.ts`)

`fillWithImage(src)` は**選んでいる箱の中身を `<img>` 1 つに差し替える**。
箱そのものは残す —— 大きさを決めているのは箱のまわりのレイアウト
(flex のセル、`aspect-ratio`)なので、箱ごと置き換えると入れた瞬間に配置が変わる。

出どころは**取り込んだデッキの写真枠**。Artifacts の `<image-slot>` は自分でドロップを
受け取るカスタム要素だが、その実装はテンプレートランタイムの一部で、取り込みが捨てる
([import-pipeline](../import-pipeline/design.md) の「自己展開型アーカイブの展開」)。
残るのは破線の箱とキャプションだけで、写真を落としても何も起きない
([issues](../../issues.md) #100)。

**枠だと見分ける印は持たない。** 印を付けるなら `data-hse-*` になるが、
シリアライズが `data-hse-` で始まる属性を**全部落とす**(`stage/bridge.ts` の `cleanElement`)ので、
**最初の保存までしか保たない印**にしかならない。開き直した瞬間に写真枠でなくなる機能は、
無いよりたちが悪い。構造(破線 + `inset:0` + キャプション)で見分ける手もあるが、
それは `materializeImageSlots` が今日たまたま書いている markup にこのモジュールを縛る。

**そこで操作のほうを一般化した。** 往復を越えて残るのは箱そのものなので、箱を対象にする。
写真枠は「一番それを欲しがっている箱」でしかない。

| 決めたこと | 中身 |
| --- | --- |
| 対象 | 選択中の 1 要素。`isFillable` を満たすときだけ |
| `isFillable` | `!isReplaced && !isCroppable && !isTextEditable` —— 既存の試験の読み合わせで、**新しい「画像とは何か」を宣言しない** |
| 入れる markup | `<img src style="display:block;width:100%;height:100%;object-fit:cover">`。`materializeImageSlots` が `src` 付きスロットに書くのと同じ形 |
| `alt` | **箱が持っていた文字をそのまま移す**。写真枠のキャプション(「写真添付エリア：…」)は著者による写真の説明そのもの |
| 履歴 | `withHtmlSnapshot` 1 回。中身の差し替えは構造の変更なので、スタイル差分では戻せない |

**中身のある箱でも拒まない。** ラベルが「画像を入れる」でヒントが「中身が画像に置き換わります」と
言っており、Undo 1 回で戻る。拒む条件を増やすほど、写真枠に届かない経路が増える。

#### 入口は 3 つ。本線はドロップと右クリック

**箱に画像ファイルを落とす**か、**箱を右クリックして「画像を入れる」を選ぶ**か、
**インスペクタの画像パネルのボタンを押す**。
どれも `fillSelectionFromPicker()` —— ダイアログ → `importAsset` → `fillWithImage` ——
を呼ぶので、「ダイアログを閉じただけのとき」「取り込みが失敗したとき」の答えが 1 箇所にある。

**ダブルクリックでは開かない(2026-08-26 に変更)。** それまでは本線がダブルクリックだった ——
元の `<image-slot>` がクリックでファイル選択に入る作りだったので、
**枠を押したら写真を選べる**のが一番短い、という理由で。
だがその形は**同じジェスチャの意味を箱の中身に決めさせる**。文字を持つ箱ならテキスト編集、
画像ならトリミング、どちらでもない箱ならファイルダイアログ ——
そして「どちらでもない箱」は、見ただけでは空のテキストボックスと区別が付かない。
挿入直後の空テキストボックスが `isFillable` を満たしてしまうため
`textual` を先に見る**順番**で凌いでいたこと自体が、
ジェスチャが 1 つの意味に収まっていない証拠だった。

**右クリックなら行に名前がある。** 「画像を入れる」と書いてある行を選ぶので、
箱の中身がどちらでも読み違えようがない。**順番の縛りも消える** ——
挿入直後の空テキストボックスでは「テキストを編集」と「画像を入れる」が**両方出て**、
どちらのつもりだったかはユーザーが選ぶ。メニューは押す前に読まれるので、
「この位置にあるもの」を 1 段ずつ歩かせずに一覧で見せているのと同じ理由が効く
(下の「[コンテキストメニュー](#コンテキストメニュー)」)。
「画像を入れられるか」はメニューを開く時点で確定させる(`stage/contextMenuStore.ts` の `fillable`)——
メニューはステージの外に描かれるので、描いている最中に「あの点」を尋ね直せない。

**クリックが枠に届くようにするのは取り込み側の仕事だった。**
写真枠のキャプションは枠全面を覆っているので、印を付けない限りクリックはそこで止まる ——
[import-pipeline](../import-pipeline/design.md) の「自己展開型アーカイブの展開」を参照。

`chooseImageAsset()` が `src/shared/` にいるのは、**`stage → features` が無い向きだから**
([05-directory](../../basic-design/05-directory.md) の「依存方向」)。
ダブルクリックを受けるのは `stage/EditStage.tsx` で、パネルは `features/`。
共通の入口は横断層に置くしかない。

#### ドロップは HTML5 の `drop` では受けられない

**編集ステージのレイヤに `dragover` / `drop` を書いても発火しない。**
Tauri がネイティブ側でドラッグを消費してしまい、WebView はセッションを見ない
([ADR-0011](../../adr/0011-native-file-drop.md))。これは**スクリプト無効の iframe とは別の話**で、
ホスト側のレイヤに張っても同じ。

代わりに `backend.onFileDrag()` が Tauri のイベントを購読し、
**CSS ピクセルの座標と絶対パス**をアプリ側に渡す。EditStage 側の仕事は 3 つ:

| やること | どう作ったか |
| --- | --- |
| 落ちる先を決める | ビューポート座標 → レイヤのローカル座標(`/ scale`)→ `elementAt` → `chooseSelectionTarget` → `isFillable`。**ポインタイベントが `offsetX` で無料でやっている変換**を手で書く |
| 「ここに落ちる」を見せる | **ホバー枠を流用する**。ドラッグ中は CSS が効かない(`:hover` すら来ない)ので描くしかなく、枠は元から「ポインタが指しているもの」の意味。OS がポインタを握っている間、本物のホバーとは衝突しない |
| 落とす | 落ちた先を**選択してから** `fillSelectionFromDrop(paths)`。右クリックからの挿入と同じ形(あちらは開いた時点で選択済み) |

**テキスト編集中は受けない。** キャレットが立っている箱に写真を入れる操作に、読める意味が無い。

**受け入れられない場所に落ちても何も起きない。** 枠が出ていないところに落ちたときは黙って無視する ——
ドラッグ&ドロップの標準的な振る舞いで、「落ちる先が光っていない」ことが答えになっている。
スライドの余白に落としたら新規挿入する案は [ideas](../../ideas.md) に置いた。

**画像でないものが混じったドロップは、画像だけを拾う。** 複数ファイルなら**最初の 1 枚**
(枠は 1 枚しか持てないので、残りをどうするかはユーザーが訊いていない問い)。
ディレクトリは拡張子が合わずに落ちる。

### リサイズは「動いた分を実測して戻す」

サイズを書き換えたとき要素が自分でどれだけ動くかは、要素ではなく**まわりのレイアウトの性質**で決まる。
`left`/`top` で留められた箱は左上から広がり中心が半分ずれる。flex で中央寄せされた箱は中心が動かない。
通常フローの箱は軸ごとに違う。**予測すると必ずどれかで外れ、掴んでいない側の角が伸びの半分だけ動く。**

そこで `resizeKeepingAnchor` は
**サイズを書く → transform をジェスチャ開始時に戻す → 実測する → 差分だけ translate する** の順で、
ポインタ移動 1 回につき強制レイアウト 1 回を払う。

### 掴んだ辺だけが吸着する

移動中の吸着は箱の 6 本(左・中央・右 × 上・中央・下)すべてを候補にする。箱ごと平行移動するのだから、
どの線が合っても意味がある。**リサイズは違う。** 東ハンドルを引いているときに左辺が吸着候補に入ると、
幅ではなく箱全体が横滑りする。

そこで `snapToGuides` は第 4 引数 `edges` で「自分のどの線を差し出すか」を選べる。
**省略すると 6 本すべて = 移動時の既存挙動**で、呼び出し側は変えていない。
リサイズは掴んだハンドルの辺 1 本だけを差し出す。

返る `dx`/`dy` は依然「平行移動量」だが、線を 1 本に絞ってあるので**その辺をどれだけ動かせば吸着するか**と
同義になる。幅への反映は `width += dx * growX`(`growX` は東 +1 / 西 −1)で、辺ごとの場合分けは要らない。

**回転済みの要素と縦横比固定中は吸着しない。** 回した箱の軸平行 bounds の辺を吸わせても意味が合わず、
比を保ったまま片側だけ動かすこともできない。

順序は**適用 → 実測 → 補正して再適用**で、上の `resizeKeepingAnchor` と同じ理由による。
増える強制レイアウト 1 回分は、他要素の bounds をジェスチャ開始時に 1 度だけ測ることで相殺している
(ジェスチャ中に他の要素は動かない)。

### Shift はドラッグを軸に固定する

Shift を押しながら動かすと、**移動が水平か垂直のどちらか一方に固定される**(PowerPoint と同じ)。
どちらの軸かは**押した位置からの移動量が大きいほう**で決まり、ポインタが動くたびに決め直す。
ドラッグを離さずに角を曲がれるし、途中で Shift を離せばその場でもう一方の軸が戻る。

**3 つのジェスチャで Shift の意味が食い違っていたのを揃えた結果**([issues](../../issues.md) #97)。
リサイズの縦横比固定・回転の 15 度刻みは最初から PowerPoint と同じ意味で、移動だけが
「吸着オフ」という別の意味を持っていた。押す側からは同じ 1 つのキーなので、
覚え違いではなく**アプリの側がずれていた**。

**吸着オフのキーは置き直さなかった。** Alt は複製で埋まっており、⌘ / Ctrl は空いていたが、
ドラッグ中に覚えるキーを 3 つに増やすほどの用途ではない —— 吸着を避けたい 1px 単位の詰めは
矢印キー(1px / Shift で 10px)が担う。**移動中の吸着は常に効く**ようになった。

**軸を固定しているあいだ、止まっているほうの軸は吸着の候補に線を出さない。**
出すと「Shift が押さえている軸から吸着が引き剥がす」ことになり、固定の意味が消える。
`snapToGuides` の第 4 引数(`edges`)に**その軸だけ空配列**を渡して実現していて、
リサイズが「掴んだ辺だけを差し出す」ために足した仕組みをそのまま使っている(上の節)。

### Alt+ドラッグは複製しながら動かす

Alt を押しながらドラッグすると、**開始位置にコピーが残り、元の要素がポインタに付いて動く**。
逆(コピーを動かす)にすると、ジェスチャの途中で uid が入れ替わり、選択・開始時スナップショット・
吸着候補の除外がまとめて張り替えになる。**動く側の uid を変えない**のがこの向きを選んだ理由で、
画面上の結果は PowerPoint と同じ。

複製は**ドラッグが実際に動き出してから 1 度だけ**行う。Alt を押しただけでポインタが止まっていると、
真上に重なったコピーができる。

Undo は `HtmlSnapshotCommand`。`StyleSnapshotCommand` は `style` 属性しか戻さないので、
**Undo してもコピーが残る**。通常のドラッグは今までどおり `StyleSnapshotCommand`(軽い)のままで、
markup を取るのは Alt が押された瞬間だけ。

「before」の markup を取る前に、**要素をいったん開始位置へ巻き戻す**。そうしないと
「少し動いた要素」が before に写り、Undo が開始位置に戻らない。この巻き戻しはコピーの位置決めも
兼ねている(コピーはその瞬間の元要素を写す)。

ドラッグ中の Esc も分岐する。ノードが増えているので style を戻すだけでは足りず、
`replaceSlideContent` で markup ごと戻す。

## 要素のコピー / 切り取り / 貼り付け(`clipboard.ts`)

⌘C / ⌘X / ⌘V で、選んだ要素そのものを運ぶ。**一度作って取り下げ、貼り付け先を決め直して戻した**
機能で、取り下げの理由はキーではなく**どこに貼るか**だった —— 旧実装は貼り付け先をスライドルート
直下に固定していたので、grid のセルや `.container .card` で塗られていた箱が親から切り離され、
別物の見た目で現れていた([../../roadmap.md](../../roadmap.md))。

**規則は 2 段。**

1. **選択があれば、その要素の次の兄弟として挿す** —— 親が変わらないので、
   親に効いていた CSS がそのまま貼ったものにも当たる(⌘D と同じ挿し方)
2. **選択が無ければ、スライドルート直下に置く** —— 空のスライドへ運ぶ経路

どちらになるかは**押した時点の選択で決まる**ので、選ぶのはユーザーであってこのモジュールではない。
何もない場所の右クリックは選択を外す(下の「コンテキストメニュー」)ので、
メニューから 2 を選ぶ道も同じ規則の上に乗っている。

### ずらすのは「隠れるとき」だけ

`COPY_OFFSET`(16px)を足す条件は **2 つ揃ったとき**に限る。

1. **要素が自分で位置を持っている**(computed の `position` が `absolute` / `fixed`)。
   grid のセル・flex のアイテム・フローの中のブロックは**親が置き場所を決める**ので、
   コピーは自分のセルをもらい、元の上には決して重ならない
2. **その場所にまだ何か居る** —— コピー元(直前に貼ったものがあればそれ)が解決できる。
   uid はそのステージが発行したものなので、**別のスライドを読み込んだ時点で解決しなくなる**

**1 を見落とすと grid が崩れる。** 実ブラウザで測ったところ、条件を 2 だけにしていた時点では
3 列 grid の 3 列目に入ったカードが**行から 16px 下がって**いた —— セルには収まっているのに
隣のカードと揃わない。「元をよける」つもりのずらしが「自分のセルから出る」になっていた。
どちらの位置決めかは**コピーした時点で計測して覚える**(貼るときに残っているのは文字列だけ)。

| 操作 | 貼り付く位置 |
| --- | --- |
| grid / flex / フローの要素 | **親が決めた場所ちょうど**。ずらさない |
| 自分で位置を持つ要素を同じスライドへ | +16px。続けて貼ると +32px・+48px と段になる |
| 切り取り → 貼り付け | **元の位置ちょうど**(元が居ないので、ずらす理由が無い) |
| 別のスライドへ貼り付け | **元の位置ちょうど**(同じ位置に同じものを置く、が普通) |

**コピーはコマンドではない。** 文書が何も変わらないので履歴に 1 手も積まない(書式のコピーと同じ形)。
切り取りは削除 1 手で、**ラベルは「切り取り」**。Undo ボタンの tooltip はコマンドのラベルなので、
⌘X に「要素を削除」と出すと、頼んでいない側の半分の名前が出てしまう。

**OS のクリップボードは経由しない。** 運ぶのはアプリ内のモジュール変数で、
他アプリとの間や別ウィンドウとの間ではやり取りできない。
編集中のテキストの中での ⌘C / ⌘V は従来どおりブラウザのものが走る
(ハンドラは `activeTextSession()` で手を引く)。

## ジェスチャの取り消しと計測

### ドラッグは画面上 4px 動くまで始まらない

押して離すだけのつもりの操作で、指の震え数 px 分だけ要素が動いてしまう
([issues](../../issues.md) #18)。Undo で戻せるが、気づかないまま少しずつレイアウトが崩れる。

**移動距離が 4px を超えるまで何も書かない。** 超えなかった press はクリックで、
クリックはスライドを変えない。判定は `GestureController.move()` の入口 1 箇所で、
`moved` フラグ(**移動・リサイズ・回転の 3 つが共通で持つ**)を立てる形で行う。
このフラグは「履歴にコマンドを積むか」と「Alt の複製を起こすか」もすでに兼ねているので、
**しきい値がそれら全部へ自動的に効く**。

**ハンドルの上でも同じ。** 回転ハンドルを掴んで離しただけで角度が変わり履歴が 1 段積まれる、
リサイズハンドルはポインタが 1px も動かなくてもサイズが確定する、という同型の症状があった
([issues](../../issues.md) #29)。**トリミングのグリップも同じしきい値に乗る**
(→ [image-crop](../image-crop/design.md)。換算は `deadZoneFor()` で共有する)。

**4px は画面上の 4px で、ステージ px ではない。** 手の震えは物理的な距離なので、
しきい値もそこで測らないと意味が変わる。ジェスチャはステージ座標(デザイン px)で動くから、
`beginMove` がジェスチャ開始時のズームで `4 / scale` に換算して覚える。
ステージ px 固定にすると **46% 表示では画面上 1.8px しか吸収できず、症状がほぼ残る**
(実測: 46% 表示の 3 画面 px がスライド実寸 9.83px の移動になっていた)。

しきい値を越えたあとは**始点基準**、つまり `pointerdown` からの移動量そのままで追従する。
越えた地点を新しい原点にすると、以降ずっとポインタより 4px 遅れた位置に要素が付いてくる。

### ジェスチャは「押した時点」では DOM を書かない

デッドゾーンが効くための前提。`begin*` は**測って覚えるだけ**で、要素には触らない。
書き始めるのは `move()` がしきい値を越えたと判定してから。

これに合わなかったのが**リサイズの寸法ピン留め**で、
`beginResize` が `pointerdown` の時点で `width` / `height` を書いていた。しかも
**before スナップショットを取る前**だったので、Undo が戻す先が「ピン留め済み」になり、
**リサイズを取り消しても `width` / `height` が残った**([issues](../../issues.md) #24)。
元は `style` を持たない、中身に応じて伸びる箱が固定サイズになる — 見た目は戻るので気づきにくく、
書き出した HTML にも残る。

ピン留め自体は要る(内容で伸びる箱がドラッグ中に reflow すると、掴んだ辺が逃げる)。
**書く場所を `#resize` の先頭へ移し、しきい値を越えた最初の 1 回だけ書く。**
これで 2 つ同時に解ける — スナップショットはもう取り終えているし、
クリックで終わった press はそこまで到達しない。

### Esc はドラッグを開始位置に戻す

始めてしまったドラッグから逃げる手段が Undo しか無いと、「まだ確定していないのに一度確定させる」ことになる。
`GestureController.cancel()` / `CropController.cancel()` はジェスチャ開始時の `style` 属性を書き戻し、
**コマンドを積まない** — 取り消したドラッグは履歴に残らない。

Esc の意味はこの時点で 4 つあるので、**優先順位は `EditStage` の keydown 1 箇所だけで決める**。

| 順 | 状況 | 動作 |
| --- | --- | --- |
| 1 | トリミングのグリップをドラッグ中 | そのドラッグを取り消す |
| 2 | 移動・リサイズ・回転をドラッグ中 | そのドラッグを取り消す(Alt で作ったコピーごと) |
| 3 | トリミング中(ドラッグしていない) | トリミングを終了(確定。取り消しは Undo) |
| 4 | それ以外 | 選択を 1 階層外へ、最外なら解除 |

取り消しはステージの DOM を書き戻すので、そのあと `commit()` してストアを DOM と揃える。

### `pointercancel` も「取り消し」であって「完了」ではない

ポインタは**ユーザーが離さなくても死ぬ**。ブラウザが選択のネイティブドラッグを始めた、
Windows のタッチパッドが同じ動きをシステムジェスチャと判定した、キャプチャを取り上げられた —
どれも `pointercancel` として届く。

これを `pointerup` と同じ扱いにすると、**そこまで動いた数 px が確定して残る**。
Windows ビルドで報告された「オブジェクトがピクッと動いて止まる」はこの形をしている
([issues](../../issues.md) #16)。だから `pointercancel` は Esc と同じ `cancel()` を通し、
**開始位置に戻して履歴には何も積まない**。「ジェスチャは失敗した、だから何も動いていない」が正しい報告になる。

`pointerup`(完了)と `pointercancel`(取り消し)でハンドラを分けているのはこのため。

### ステージのレイヤでは選択を始めさせない

`.stage-interaction` の上での press は**必ずジェスチャの始まり**で、テキスト選択の始まりではない。
放っておくとブラウザが選択を作り、**すでに選択済みの範囲の上で押した次のドラッグは
「選択のネイティブドラッグ」になって `pointercancel` を投げる** — 上の話の原因側。

止め方は 2 つ重ねてある。どちらか片方でも足りるが、**壊れ方が違う**ので両方置く
(スタイルシートが失われた場合と、ハンドラが走らなかった場合)。

- `pointerdown` の `preventDefault()`(`EditStage`)
- `.stage-interaction { touch-action: none; user-select: none }`(`src/app/styles.css`)

`preventDefault()` は press によるフォーカス移動も止めるので、レイヤへの `focus()` を明示的に呼ぶ。

**テキストセッションを抜けるときは、ホスト文書側の選択も畳む。**
`releaseTextFocus` が消していたのはフレーム側だけで、実測すると Esc の後もホスト側の選択が
`isCollapsed: false` のまま残っていた(2026-08-23)。生きた range の上で押すことが
ネイティブドラッグの引き金なので、フレーム側だけでは半分しか閉じていない。

これは `.pane-divider` が [issues](../../issues.md) #8 で通ったのと同じ道筋
([decisions.md](decisions.md) #64・#65)。

### 右ボタンではジェスチャを始めない

右クリックはコンテキストメニューを求める操作なので、`pointerdown` は主ボタン以外を無視する。
以前は右ドラッグでも要素が動いていた。

### ドラッグ中は数値を出す

移動・リサイズ・回転の最中、選択枠の下に現在値を出す(移動は `x, y` / リサイズは `w × h` / 回転は `n°`)。
**単位はデザイン px** — インスペクタが見せている値・HTML が持っている値と同じ空間で、
スクリーン px はズームで意味が変わる。

バッジはオーバーレイ側(ホスト)に描く。回転した選択枠の外に置くので文字は常に水平で、
下に収まらなければ要素の上へ反転する。

### ハンドルのカーソルは回転に追従する

90° 回した箱の n ハンドルが `ns-resize` のままだと、掴む辺と矢印の向きが合わない。
リサイズカーソルは双方向(`ew-resize` は左右どちらも同じ矢印)なので、
**ハンドルの基準角 + 要素の回転角を 180° で割った余り**を 45° の 4 バケットに丸めれば足りる。
`styles.css` の静的な `cursor` 宣言はフォールバックとして残してある(インラインが勝つ)。

## コンテキストメニュー

ステージ上の右クリックで、**ポインタのある場所に操作を出す**。項目はすべて既にあるコマンドを呼ぶだけで、
新しい編集ロジックは無い。

| 対象 | 項目 |
| --- | --- |
| 要素 | テキストを編集 / トリミング / 画像を入れる(3 つとも該当するときだけ)/ 重ね順 4 つ / 左右中央・上下中央 / 切り取り・コピー・貼り付け / 書式のコピー・貼り付け / 複製 / 削除 |
| 何もない場所 | テキストボックスを挿入 / 四角形を挿入 / 貼り付け(コピー済みのときだけ) |

右クリックは**選択も動かす**(PowerPoint と同じ)。何もない場所なら選択解除。
これは「画像を入れる」の前提でもある —— `fillSelectionFromPicker()` は選択を読むので、
メニューを開いた時点でポインタの下の箱が選ばれていることが効いている。
「トリミング」と「画像を入れる」が同時に立つ選択は無い(`isFillable` は `isCroppable` が
受けるものを拒む)ので、2 つは同じ席のように隣り合う。詳細は上の「箱に画像を入れる」。

**メニューは `document.body` へ portal する。** ステージは `.stage-surface` の中にあり、この要素は
`transform: scale()` を持つ。transform を持つ要素は **`position: fixed` の包含ブロックになる**ので、
ステージの中に描くとメニューがビューポート基準でなくなり、さらにズーム倍率ごと拡大縮小してしまう。

ハンドルや回転ハンドルは操作レイヤの**兄弟**(`.stage-overlay` 側)なので、
右クリックのハンドラは操作レイヤとオーバーレイのルートの両方に要る。

**テキスト編集中は出さない。** そのとき操作レイヤは `pointer-events: none` になり、右クリックは
iframe に落ちる。スクリプト無効 document では WebKit がリスナを発火させない(上の「インライン編集の抜け方」と
同じ制約)ので、ホストから `preventDefault()` する手段が無い。抑止できないカスタムメニューは
OS のメニューと二重に出るだけなので、その場は OS に任せる。

メニューは `features` にあり、ステージの `contenteditable` の扱いには触れない。
「テキストを編集」は `useCropSession` と同じ形で**ストア越しにステージへ依頼する**
(`stage/textEditRequest.ts`)。依存の向きは `features → stage` の一方通行のまま。

**「この位置にあるもの」も同じ形**(`stage/selectRequest.ts`)。選択とパンくずは
ステージの `selectElement` が対で書くもので、`useSelectionStore.select` を直に呼ぶと
**パンくずだけが取り残される** —— それが正しいのはパンくず自身のボタン(登った道を残す)だけ。
**その位置に何があるかはメニューを開く時点で決める** —— メニューはステージの外に描かれるので、
描いている最中に「あの点」をもう一度尋ねる術が無い。

## キーボード

窓口は 2 つある。**アプリ全体のもの**は `app/App.tsx` の `useKeyboardShortcuts`、
**選択とステージに閉じたもの**は `stage/EditStage.tsx` の keydown。
どちらも `INPUT` / `TEXTAREA` / `SELECT` とテキストセッション中は手を出さない。

**どのキーが何に割り当てられているかは [../shortcuts/design.md](../shortcuts/design.md) が正。**
ここは「押されたときに何をするか」だけを扱う。両者の窓口は
`matchesShortcut(id, event)` でカタログに「これは何のキーか」を尋ねる。

- Esc は**ステージの中で 4 つの意味を持ち、順番がそれを分けている** —
  ドラッグ中なら取り消し、トリミング中なら終了、それ以外は選択を 1 階層外へ、
  文字編集中は capture フェーズで先にセッションを閉じる。
  これは「キーの照合」ではなく**状態の優先順位**なので、カタログではなくここが正
- 矢印は選択があれば移動、無ければスライド送り。カタログ側では
  `contextual` と宣言してあり、選ぶのはこのハンドラの仕事
- Shift はジェスチャ中の修飾キー(軸固定 / 縦横比固定 / 15 度刻み)と、矢印移動の**度合い**にだけ効く

## 履歴と保存

- History は**コマンドスタック**(上限あり・merge 対応)。スライド単位ではなく**プロジェクト単位**
- 編集確定のたびに該当スライドの DOM をシリアライズして DocumentStore の `html` を更新する
  (= ストアは常に保存可能な状態。クラッシュ耐性)
- **連続ジェスチャは 1 undo ステップ**(`tryMerge` / gesture 終了時に 1 コマンド)。
  さもないとドラッグ 1 回で履歴が埋まる
- **打鍵は畳むが、ボタンは畳まない。** テキストセッションは打鍵も書式コマンドも
  同じ `SetInnerHtmlCommand` で記録するので、「同じ uid なら畳む」だけでは
  **U を押して 150ms 後に S を押すと 1 手になる**(実測)。
  区別は**触った要素の集合**で付く —— タイピングは要素を増やさず**テキストノードだけ**を変えるが、
  書式コマンドは `<u>` や `<span>` を**新しく生む**ので uid が増える。
  `innerHTML` から uid を拾って集合が同じときだけ畳む。
  パースせず文字列を走査するのは、比べる 2 つが同じ作り方(`reindex` 直後の `innerHTML`)で
  作られているため —— 打鍵ごとに DOM をもう 1 つ建てる必要が無い
- **スナップショットの畳み込みは名前付きで opt-in。** `StyleSnapshotCommand` は
  ジェスチャ(移動・リサイズ・回転・トリミング)と**打鍵ごとに当たる数値欄**の両方が使うが、
  畳むのは **merge key を渡したものだけ**。ジェスチャは `end()` の時点ですでに 1 コマンドとして
  到着するので畳む必要が無く、無条件に畳むと「少し空けて 2 回ドラッグした」が 1 手になってしまう。
  インスペクタの位置とサイズは `geometry:<欄>:<uid>` を渡し、**その欄のその要素への run だけ**が
  1 手にまとまる([features/inspector](../inspector/design.md) の「位置とサイズも打つそばから当たる」)。
  X / Y / 回転は同じ `transform` を書くので、`SetInlineStyleCommand` のようにプロパティ集合では
  区別できない — 欄の名前をキーに入れているのはそのため
- **畳んでも `before` は最初のものを残す。** さもないと Undo が 1 打鍵前にしか戻らず、
  デッキが `width` を持たない箱に打ち込んだ寸法が焼き付いたまま残る
  ([issues](../../issues.md) #24 と同じ症状)
- **Undo は選択も復元する。** 削除を Undo して要素だけ戻り選択が戻らないと、
  オーバーレイが出ないので気付きにくい(`HtmlSnapshotCommand`)
- **頼んでいない 1 手は履歴に残さない。** 一文字も入らないまま手放されたテキストボックスの挿入は
  `revoke()` で取り下げ、undo にも redo にも残さない
  (上の「[新しいテキストボックスは空で入る](#新しいテキストボックスは空で入る)」)
- 保存は書き出しと同義。⌘S・自動保存・「書き出し」ボタンはすべて同じ経路(`exportHtml`)を通る
- **自動保存: アイドル 2 秒**で書き出し先の HTML へ直接書き込む(atomic rename なので中断しても直前の版が残る)。
  テンポラリ + 復旧フローを挟まないのは、復旧の判断をユーザーに投げる UI が増えるだけで、
  書き込みの安全性は rename で足りているため
- **書き出し先が未設定のデッキは自動保存の対象外**で、ウィンドウを閉じるときに確認する。
  確認はアプリ内のモーダル(`src/features/CloseConfirmDialog.tsx`)で、
  **「書き出して終了」「書き出さずに終了」「終了をキャンセル」の 3 択**(Esc はキャンセル)
- **取り込んだ HTML のパスを書き出し先として自動採用しない** — 元ファイルを黙って上書きしないため

## 利用可能フォントの判定(`src/shared/fonts.ts`)

カタログには macOS 系(ヒラギノ / 游書体 / Avenir 等)と Windows 系(メイリオ / 游ゴシック UI /
BIZ UD / Segoe UI 等)を並べて持ち、**実行時に実在するものだけを表示**する。
無い書体を選べてしまうと、ブラウザが黙って別の書体に落として「別のマシンで開くと見た目が変わる」ことに
気付けないため、**グレーアウトではなく非表示**にしている。

判定は canvas の `measureText` による幅比較 — ラテン + 仮名 + 漢字を混ぜた文字列を
`monospace` / `serif` / `sans-serif` の 3 つの総称フォントそれぞれと、`'<書体名>', <総称>` で測り、
1 つでも幅が変われば実在すると見なす。**総称を 3 つ試すのは、macOS の `sans-serif` 自体が
日本語ゴシックなので、CJK だけで測るとヒラギノが「無い」と判定されてしまう**ため。
`document.fonts.check()` は `@font-face` の登録状況を答える API で、
ローカルインストール済み書体については何も言わないので使わない。

既定は **Noto Sans**。ラテンと日本語を同じ設計で覆う唯一の候補で、
**Noto Sans JP ともどもアプリが同梱している**ため、どの環境でも実在する。
**この 2 件と既定スタックだけが判定の対象外**(常に表示)。
同じ書体が OS ごとに別名を持つ場合(`YuGothic` / `Yu Gothic`)は両方を候補に入れ、
実在した方だけを 1 行にまとめる。

同梱書体をどう配るか(`slides://` を使う理由・書き出しには入れないこと)の正は
[fonts](../fonts/design.md)。

## 受け入れ条件(EARS 記法)

- WHEN スライドをステージへロードする THE SYSTEM SHALL 全要素に解決可能な uid を与える
- WHEN 何も編集せずに保存する THE SYSTEM SHALL スライドを一切変えずに返す
- WHEN 保存する THE SYSTEM SHALL エディタ属性を markup に残さず、スライド以外の殻をシリアライズしない
- WHEN 保存する THE SYSTEM SHALL 編集モードが無効化したスクリプトとインラインハンドラを復元する
- WHEN 単語をクリックする THE SYSTEM SHALL インライン span ではなくそれが属するブロックを選ぶ
- WHEN スライドを埋めるコンテナをクリックする THE SYSTEM SHALL 「何もない場所」として扱う
- IF 要素が自前のテキストや画像を持つ THEN THE SYSTEM SHALL 大きさに関わらず選択可能にする
- WHEN Esc を押す THE SYSTEM SHALL 1 階層外へ移動し、**スライドルートの手前で止めて選択解除する**
- WHEN トリミング枠の中の画像をクリックする THE SYSTEM SHALL 画像ではなく枠を選ぶ
- IF トリミング枠がスライド全面を覆っている THEN THE SYSTEM SHALL 背景扱いにせず選択可能に保つ
- WHEN スライドの外側(キャンバス余白)をクリックする THE SYSTEM SHALL 選択を解除する
- WHEN テキスト編集中にスライドの外側をクリックする THE SYSTEM SHALL セッションを終了し、選択も解除する
- WHEN パンくずにフォーカスする THE SYSTEM SHALL 選択を変えずにプレビュー枠だけを出す
- WHEN 削除を Undo する THE SYSTEM SHALL 要素を**選択された状態で**戻す
- WHEN 選択のある状態で貼り付ける THE SYSTEM SHALL その要素の次の兄弟として、同じ親の中に置く
- WHEN 選択の無い状態で貼り付ける THE SYSTEM SHALL スライドルート直下に置く
- IF 貼るものが自分で位置を持ち、かつコピー元(または直前に貼ったもの)がまだスライドに居る THEN THE SYSTEM SHALL 貼り付けを 16px ずらす
- IF 貼るものの位置を親が決めている(grid / flex / フロー) THEN THE SYSTEM SHALL ずらさず親の決めた場所に置く
- WHEN 切り取ったものを貼り付ける THE SYSTEM SHALL ずらさず元の位置に置く
- WHEN コピーする THE SYSTEM SHALL 履歴に 1 手も積まない
- WHEN スライドルートを選んでコピーまたは切り取りをする THE SYSTEM SHALL 何もしない
- WHEN 貼り付けを Undo する THE SYSTEM SHALL 1 手で貼り付け前に戻す
- IF 選択した要素が画像でも文字を持つ要素でもなく、子を持てる THEN THE SYSTEM SHALL そこへ画像を入れられるようにする
- WHEN 画像を入れられる箱を右クリックする THE SYSTEM SHALL メニューに「画像を入れる」を出す
- WHEN メニューの「画像を入れる」を選ぶ THE SYSTEM SHALL 画像を選ぶダイアログを開く
- WHEN 画像を入れられる箱をダブルクリックする THE SYSTEM SHALL 何もしない(ファイル選択を開かない)
- WHILE 画像ファイルを箱の上へドラッグしている THE SYSTEM SHALL 落ちる先の箱を枠で示す
- WHEN 画像を入れられる箱に画像ファイルを落とす THE SYSTEM SHALL その箱を選んでから画像を入れる
- IF 落とした先が画像を入れられない THEN THE SYSTEM SHALL 何もしない
- IF 落としたものに画像が 1 つも無い THEN THE SYSTEM SHALL 何もしない
- WHILE テキストを編集している THE SYSTEM SHALL 落ちる先を示さず、落とされても何もしない
- IF その箱が挿入直後の空テキストボックスである THEN THE SYSTEM SHALL メニューに「テキストを編集」と「画像を入れる」を両方出す
- WHEN 箱に画像を入れる THE SYSTEM SHALL 箱そのものは残し、中身だけを画像に差し替える
- WHEN 箱に画像を入れる THE SYSTEM SHALL その箱が持っていた文字を画像の `alt` に移す
- WHEN それを Undo する THE SYSTEM SHALL 元の中身をひとまとまりで戻す
- WHEN transform を書く THE SYSTEM SHALL 元から書かれていた transform を基底として保つ
- IF エディタのオフセットが 0 になる THEN THE SYSTEM SHALL transform プロパティごと削除する
- WHEN 要素を回転する THE SYSTEM SHALL 中心を動かさない
- WHEN 押した位置から画面上 4px 以内で離す THE SYSTEM SHALL 選択だけを変え、要素を動かさず履歴にも積まない
- WHEN ハンドルを押して 4px 以内で離す THE SYSTEM SHALL 寸法も角度も書かず、履歴にも積まない
- WHEN しきい値を越えてドラッグする THE SYSTEM SHALL 押した位置からの移動量そのままで追従させる
- WHEN リサイズを Undo する THE SYSTEM SHALL ジェスチャがピン留めした `width` / `height` も一緒に戻す
- WHEN 打鍵ごとに当たる数値欄を打ち続ける THE SYSTEM SHALL その run を 1 つの Undo ステップにする
- WHEN その Undo を実行する THE SYSTEM SHALL run の**最初の打鍵より前**の状態に戻す
- WHEN 続けて 2 回ドラッグする THE SYSTEM SHALL それを 2 つの Undo ステップとして残す
- WHEN 近い辺があるところへドラッグする THE SYSTEM SHALL 正確に吸着させる(複数候補なら最も近いもの)
- WHEN Shift を押しながらドラッグする THE SYSTEM SHALL 移動量の大きいほうの軸だけに動かす
- WHEN 軸を固定したまま反対の軸へより大きく動かす THE SYSTEM SHALL ドラッグを離さずに固定軸を入れ替える
- WHILE 軸が固定されている THE SYSTEM SHALL 止まっているほうの軸に吸着させない
- WHEN ドラッグの途中で Shift を離す THE SYSTEM SHALL 両方の軸への移動に戻す
- WHEN テキスト編集中に本文をドラッグする THE SYSTEM SHALL 押した位置から引いた先までを選択する
- WHEN **すでに選択された範囲の上から**押して引く THE SYSTEM SHALL 選択を作り直す(ドラッグ移動にしない)
- IF ドラッグが編集中要素の外へ出る THEN THE SYSTEM SHALL 直前に枠内だった位置で選択を止める
- WHEN テキスト編集中に本文を押す THE SYSTEM SHALL セッションを閉じない
- WHEN テキストボックスを挿入する THE SYSTEM SHALL 中身が空の箱を入れて**選択だけ**し、編集セッションは開かない
- WHILE 挿入直後の空の箱が選択されている THE SYSTEM SHALL 移動・リサイズ・回転を受け付ける
- WHILE 挿入直後の空の箱が選択されている THE SYSTEM SHALL プレースホルダを描き、**3 つの入口すべて**から再入場を許す
- IF 空の要素が挿入直後の箱でない THEN THE SYSTEM SHALL プレースホルダを描かず、テキスト編集にも入らせない
- WHILE 編集中の要素が空である THE SYSTEM SHALL プレースホルダを描き、**保存する markup には残さない**
- IF 編集中の要素が `<br>` を含んでいても文字を持つ THEN THE SYSTEM SHALL **タグに関わらず**プレースホルダを描かない
- IF 挿入したテキストボックスに一文字も入らないまま選択が離れる / スライドが変わる THEN THE SYSTEM SHALL 挿入ごと取り消し、履歴にも残さない
- IF 挿入の後に別のコマンドが積まれている THEN THE SYSTEM SHALL 取り下げではなく削除を 1 コマンドとして積む
- IF ユーザー自身の文章を全部消してセッションが終わる THEN THE SYSTEM SHALL 要素を消さない
- WHEN セッション中にコマンドが積まれる THE SYSTEM SHALL そこまでの入力を履歴の基準に飲ませない
- WHEN セッション中に Undo / Redo が走る THE SYSTEM SHALL 履歴の基準をそこへ追従させる
- WHEN ホストのコントロールに選択を奪われる THE SYSTEM SHALL 退避した Range を復元する
- IF 要素内に生きた選択がある THEN THE SYSTEM SHALL 退避よりそちらを優先する
- IF 編集中の要素が `<ul>` / `<ol>` そのものである THEN THE SYSTEM SHALL 同じ種類のボタンで**リストを外し**、別の種類のボタンで**種類を変える**
- IF 編集中の要素が `<span>` / `<p>` である THEN THE SYSTEM SHALL リストを持てる要素へ建て替えてからリスト化する
- WHEN リストのためにホストを建て替える THE SYSTEM SHALL uid を引き継ぎ、**タグが変わって失われた文字の宣言だけ**をインラインで書き戻す
- WHEN リストのためにホストを建て替える THE SYSTEM SHALL 押下を 1 つの Undo ステップにし、そこまでの打鍵を巻き込まない
- WHEN リストを適用した markup を読み直す THE SYSTEM SHALL 同じ構造で戻す(パーサが分解する入れ子を作らない)
- WHEN 変更が続いたあと落ち着く THE SYSTEM SHALL 1 回だけ自動保存する(書き込みを重ねない)
- WHEN 未書き出しのまま閉じようとする THE SYSTEM SHALL 3 択のモーダルで 1 回だけ答えを取る
