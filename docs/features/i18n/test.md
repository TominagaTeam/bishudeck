# i18n — テスト設計

方針の正は [basic-design/08-test-policy.md](../../basic-design/08-test-policy.md)。ここは個別ケースだけ。
ケースは [design.md](design.md) の受け入れ条件（EARS）と対応させる。

EARS の 3 型: `WHEN <イベント> THE SYSTEM SHALL <動作>` /
`IF <条件> THEN THE SYSTEM SHALL <動作>` / `WHILE <状態> THE SYSTEM SHALL <動作>`。

## 分担

この機能は 3 つの層で守られていて、**どれか 1 つでは足りない**。

| 層 | 担保するもの | 実体 |
|---|---|---|
| **型** | カタログに無いキーを書けないこと。後から足す言語がキーを落とせないこと | `t()` の引数が `MessageKey`（`index.ts:21`）、`Record<Locale, Record<MessageKey, string>>`（`index.ts:28`）。**`npm run typecheck` が検証**する |
| **unit** | 補間の規則とカタログ自体の健全さ（#1〜#6） | `src/shared/i18n/i18n.test.ts`（**6 件**） |
| **手動** | その文面が**実際に画面へ出るか**、ロケール解決が実環境でどう転ぶか（#7〜#17） | `npm run tauri dev` |

**「画面にキーがそのまま出ていない」を自動で見る検査は持たない。** 過去に smoke へ足そうとして、
**わざとキーを直書きしても赤くならなかった**（検査した時点でその文言が画面に出ていないだけで通る）。
守れていない検査は入れず、型（綴りの保証）と手動（#8）に分けた（[decisions.md](decisions.md) #13）。

## テストケース

### 補間とカタログ（自動）

| # | 種別 | ケース(EARS 形式) | 状態 |
|---|---|---|---|
| 1 | unit | WHEN キーを渡す THE SYSTEM SHALL 現在の言語の文面を返す | 実装済み |
| 2 | unit | WHEN 補間つきのキーに値を渡す THE SYSTEM SHALL `{name}` を値で置き換える | 実装済み |
| 3 | unit | IF `{name}` の値が渡されていない THEN THE SYSTEM SHALL プレースホルダをそのまま残す | 実装済み |
| 4 | unit | WHEN 文面が持たない名前の値を渡す THE SYSTEM SHALL 文面を変えずに返す | 実装済み |
| 5 | unit | IF カタログに空文字の項目がある THEN THE SYSTEM SHALL テストを失敗させる | 実装済み |
| 6 | unit | IF カタログに `{` と `}` の数が合わない項目がある THEN THE SYSTEM SHALL テストを失敗させる | 実装済み |

実体は `src/shared/i18n/i18n.test.ts`。

**ケース 3 が一番重要。** 空文字に落とす実装でも「何かが表示される」ので画面上は同じに見え、
**どの呼び出しが値を渡し忘れたのか分からなくなる**。見えている `{label}` はそれを名指しする
（[decisions.md](decisions.md) #6）。

**ケース 6 は補間そのものではなくカタログの検査。** `t()` は `/\{(\w+)\}/g` でしか置換しないので、
`{count` のような閉じ忘れは**例外にもならず、そのまま画面に出る**。文面を足すときに踏む罠なので、
1 件ずつ目で見るのではなくカタログ全体に対して当てる。

**ケース 5 と 6 は新しい言語カタログにもそのまま効かせる。** 今は `ja` だけを見ているが、
言語が増えたら対象を `CATALOGS` 全体に広げる（キーの欠落は型が見るので、ここは中身だけを見る）。

### 実際の画面に出るか（手で確認）

**jsdom には画面が無い。** `t()` が正しい文字列を返すことと、その文字列が**その場所に描かれる**ことは
別なので、下の 8 件はアプリを起動して目で見る。

| # | 種別 | ケース(EARS 形式) | 状態 |
|---|---|---|---|
| 7 | 手動 | WHEN 日本語環境でアプリを起動する THE SYSTEM SHALL 上バー・インスペクタ・スライド一覧・ステータスバーをすべて日本語で表示する | 手で確認 |
| 8 | 手動 | WHILE 画面が出ている THE SYSTEM SHALL キー文字列（`toolbar.import` のようなドット区切り）をそのまま表示しない | 手で確認 |
| 9 | 手動 | WHEN 数を含む文面が出る（取り込みダイアログの「{count} 枚」・ズームの「画面に合わせる ({percent}%)」） THE SYSTEM SHALL `{...}` を残さず値を入れる | 手で確認 |
| 10 | 手動 | WHEN コマンドが失敗して通知が出る THE SYSTEM SHALL `{label}` にそのコマンドの名前（「移動 に失敗」）を入れる | 手で確認 |
| 11 | 手動 | WHEN 埋め込みフォントを持つ HTML を取り込む THE SYSTEM SHALL 要約を「〜、〜しました」と 1 文につなぐ（区切りと語尾がカタログから来る） | 手で確認 |
| 12 | 手動 | WHEN 「元に戻す」ボタンにマウスを載せる THE SYSTEM SHALL 直前のコマンド名（`command.*`）をツールチップに出す | 手で確認 |
| 13 | 手動 | WHEN 元に戻したあと「やり直す」ボタンにマウスを載せる THE SYSTEM SHALL やり直す対象のコマンド名（`command.*`）をツールチップに出す | 手で確認 |
| 14 | 手動 | WHEN 再生ウィンドウを開く THE SYSTEM SHALL そちらの文言も同じ言語で出す | 手で確認 |

**確かめ方は「`samples/generic-deck.html` を取り込んで、上バーから順に読む」。**
9〜11 は文面が組み立てられる場所なので、**取り込み直後の通知**をその場で読む
（`{count}` や `{items}` が残っていたら、そこが呼び出し側の渡し忘れ）。

**ケース 8 は「出ていないこと」を見る。** 出ている文言を確かめるだけだと、
**その画面をまだ開いていないだけ**で通ってしまう —— これが smoke に検査を入れなかった理由そのもの
（[decisions.md](decisions.md) #13）。開いていない画面（各ダイアログ・コンテキストメニュー・
ショートカット一覧・空状態）を一通り開き切ることまでが確認の中身。

**ケース 12 と 13 を分けているのは、「やり直す」のラベルが別のスタックから来るから**
（`redoStack.at(-1)?.label`。`src/core/commands/engine.ts:57-58`）。一度も元に戻していない間は
ボタンが無効で、ツールチップも `toolbar.redo` の既定文言（「やり直す」）のままなので、
**編集 → 元に戻す → 「やり直す」にマウスを載せる**の順で踏まないと 13 を見たことにならない。

**ケース 14 を分けているのは、再生ウィンドウが同じバンドルを `#/present` で開き直すから**
（`src/main.tsx:13-21`）。`initLocale()` はそちらでも走るが、**別ウィンドウなので別の実行**になる。
本体だけ見て済ませない。

### ロケールの決め方（手で確認）

| # | 種別 | ケース(EARS 形式) | 状態 |
|---|---|---|---|
| 15 | 手動 | IF `localStorage` に `hse.locale` が無い THEN THE SYSTEM SHALL 機械の言語から決め、日本語で起動する | 手で確認 |
| 16 | 手動 | IF `hse.locale` にカタログの無い値が入っている THEN THE SYSTEM SHALL 起動を止めず日本語へ落とす | 手で確認 |
| 17 | 手動 | IF `localStorage` が使えない THEN THE SYSTEM SHALL 例外を外へ出さず起動を続ける | 手で確認 |

**15〜17 は言語が 2 つ以上になるまで「日本語で出る」以上のことを言えない。**
今はどの枝を通っても答えが `ja` なので、確かめられるのは**落ち方**（起動が止まらないこと）だけ。
`hse.locale` に `fr` を書いてから起動し、白画面にならないことを見る。

**英語カタログを足すときは、ここが最初に効くケースになる。**
そのとき 15 は「機械の言語で出る」、16 は「保存した選択が機械の言語に勝つ」に格上げする。

## 未カバー

- **英語カタログでの見え方。** カタログが 1 つしか無いので、
  **言語を切り替えたときに文面が入れ替わること自体を誰も見ていない**。
  smoke があった頃は 169 箇所の日本語照合が抽出の正しさを裏書きしていたが、
  廃止した今その後ろ盾は無い（[ADR-0009](../../adr/0009-drop-smoke-e2e.md)、[decisions.md](decisions.md) #10）
- **言語切替後の再描画。** `t()` を毎回引き直す設計（[decisions.md](decisions.md) #4）が
  本当に効くか、**すでに構築済みの Command のラベルが古い言語のまま残る**問題が
  実際にどう見えるかは、切替 UI が無いので未検証
- **空のテキストボックスのプレースホルダ**（`stage.textBoxPlaceholder`）の見え方は
  [editing-engine/test.md](../editing-engine/test.md) が持つ。カタログ側の関心は
  「markup に残らないこと」だけなので、ここでは二重に持たない
