# image-crop — 機能設計

## 概要

画像を PowerPoint と同じ感覚でトリミングする。
画像をダブルクリックで開始し、枠の角と辺で切り取り、内側のドラッグで位置を合わせる。
Enter か Esc で終了、やり直しは Undo。

## 責務と境界

**やること**: 枠 / 画像の 2 矩形モデルの読み書き、トリミング中のジェスチャ計算、オーバーレイ描画

**やらないこと**

- 枠のリサイズそのもの(→ [editing-engine](../editing-engine/design.md) の `resizeKeepingAnchor`)
- 画像の挿入・差し替え(→ editing-engine の `SetAttribute`)

## モデル — 2 矩形

**枠**(スライド上のオブジェクト)と、その中に置かれた**画像**。
枠からはみ出した部分は**隠れるだけで捨てない**ので、いつでも緩められる。

```html
<div style="position:absolute;left:…;top:…;width:枠W;height:枠H;overflow:hidden">
  <img src="…" style="position:absolute;left:…;top:…;width:画像W;height:画像H;max-width:none">
</div>
```

## 設計判断

### `clip-path: inset()` を採らなかった

描画は切れるが**レイアウトボックスは元のまま**で、`getBoundingClientRect` が切る前の矩形を返し続ける。
選択枠・スナップ対象・整列コマンドがすべて見た目とズレる。
**辺を掴めないトリミングはトリミングではない。**

### エディタ固有のマークを付けない

枠かどうかは**形で判定**する(クリッピングする箱 + 唯一の子が絶対配置の `<img>`)。
手書きでそう書かれたデッキもトリミングでき、書き出して読み直したファイルも同じプロジェクトに戻る
— `data-hse-*` の目印はシリアライズで消えるので、これはできない
([ADR-0001](../../adr/0001-html-as-source-of-truth.md))。

ただし**トリミング中はこの判定が computed style だけでは効かない**。セッション中の
`[data-hse-cropping] { overflow: visible !important }` が author-important として
インライン宣言に勝ち、`overflow` が `visible` に見えるため。判定側で
`data-hse-cropping` を持つ要素はクリッピングしているものとして扱う
(外したのはステージ自身なので、その分を補うだけ。形での判定は変えない)。

### 枠は「作る」より先に「借りる」

開始時、画像がすでにクリッピングする箱の中に**単独で**入っているなら、**その箱を枠として使う**。
新しい `<div>` は作らない。取り込んだデッキの画像はまさにこの形
(`<div style="position:absolute;inset:0;overflow:hidden">` + `<img style="width:100%;height:100%">`)で、
中にもう 1 枚挟むと**デッキ側の箱がトリミング前の大きさのまま画像の周りに残る**
— これはトリミングではなく「画像が縮んだ」ようにしか見えない。
さらに 2 回目のダブルクリックで 3 枚目、と際限なく入れ子になる。

箱に他の子や自前のテキストがある場合は借りない(画像を絶対配置にすると他の中身がずれるため)。
スライドルートも借りない(スライドはキャンバスであってオブジェクトではない)。
**同じ理由で、スライドルートは枠として「認識」もしない** — 生成デッキのスライドは
`overflow:hidden` で全面写真 1 枚を抱えることがあり、構造条件だけなら枠に見えてしまう
([decisions.md](decisions.md) #18)。
借りた枠は**詰めない**(下記の「開始時に見た目を 1px も変えない」の例外) —
著者が選んだ大きさの箱で、余白にも自前の板を描いているため。

### 包むのはトリミングを開始した瞬間だけ

借りられる箱が無いときだけ `<img>` → `<div><img>` に包む。この構造変更は**頼まれてもいない**ので、
独立した undo ステップとして記録する。**すでに枠に入っている画像を開き直すのは編集ではない**
— 構造を触らず、記録も残さない。

### 開始時に見た目を 1px も変えない

`object-fit` が実際に描いている矩形を計算して、明示的な `left/top/width/height` に書き直す。
書き直したあとは `object-fit` に仕事が無いので `fill` に固定する(同じ比率では同じ描画)。

**ただし `contain` で余白がある場合**(エディタの「画像を挿入」がこれ)は、**枠を実画像まで詰める**。
詰めないと「画像より枠のほうが大きい」状態から始まり、不具合に見える。
背景・枠線・影を持つ画像は余白にも描くので、その場合は詰めない。

### 枠の辺を動かしても画像は画面上で動かない

画像は枠を基準に配置されているので、**枠の角が動いた分だけ逆向きに `left/top` を足す**。
辺は画像の端で止める(枠が何も映さない状態を作らない)。

### 枠のリサイズは画像も一緒に拡大縮小する

editing-engine の `resizeKeepingAnchor` を通す。
枠だけ変えると、**リサイズが黙って再トリミングになってしまう**。

**枠のサイズを変えるすべての経路**がこれを守る — ハンドルのドラッグだけでなく、
インスペクタ「位置とサイズ」の幅 / 高さも。倍率の計算は `scalePlacement()` 一箇所に置き、
枠と画像を 1 つのスナップショット(= 1 undo ステップ)にまとめる。
インスペクタの各フィールドは**触った軸だけ**を拡縮する(幅なら `left` と `width`)。

### 枠が選択対象で、中の画像ではない

トリミング済みの画像をクリックすると**枠が選ばれる**。画像は枠より意図的に大きいので、
画像を選んでしまうと**トリミング前の矩形**に選択枠とハンドルが出て、ドラッグは
オブジェクトの移動ではなく枠内での画像のスライドになる。判定は
[editing-engine](../editing-engine/design.md) の `chooseSelectionTarget` 側に置く
(枠は「中身を持つもの」= 背景ではない、として扱う)。

### 解除は開始前の状態に戻す

「元の画像に戻す」は、**開始時に書き換えた `style` を復元する**。
エディタが作った枠はそのとき取り除き、借りた枠は残して自分の `style` を戻すだけ。
包み込みは相対サイズ(`width: 100%` など)を px に焼き付けるので、枠を残したまま広げるだけでは
**画像が親の箱に追従しなくなったまま**になる — 取り込んだデッキの画像
(`<div style="position:absolute;inset:0"><img style="width:100%;height:100%">`)がこの形。

戻し先は開始時に `data-hse-crop-origin` として**書き換える要素それぞれ**に退避する
(画像は常に、枠は借りた場合)。用途は**戻し先だけ**で、枠かどうかの判定には使わない
(上記「形で判定」を維持)。エディタが作った枠には `data-hse-crop-owned` を付け、
**これが付いている枠だけを取り除く**。`serializeSlide` が `data-hse-*` を落とすので
書き出しには漏れず、`slideMarkup()` は残すので undo / redo をまたいでも失われない。
開き直しても記録は**上書きしない**(2 回目の「開始前」はすでにトリミング後なので)。

- **借りた枠・デッキが書いた枠は外さない。** 著者の要素と styling を壊さないため。
  借りた枠は自分の `style` を戻すだけ、記録が無い枠は従来どおり**画像全体まで広げる**にとどめる
- **セッションの印はスナップショットに入れない。** `data-hse-cropping` を含んだ markup を
  undo で書き戻すと、セッションが無いのに印だけ残った枠ができ、以後**二度とクリッピングしない**
- **サイズは戻り、位置は残る。** 枠にした状態のリサイズは元の `style` に戻すことで破棄され、
  スライド上でどこに置いたか(エディタの `translate` / `rotate`)は `<img>` に載せ替える。
  トリミングではない操作まで巻き戻さないため
- 構造変更なので、開始と対称に**独立した undo ステップ**(`HtmlSnapshotCommand`)にする

### 確定だけがあり、取り消しは無い

Enter も Esc も「終了」で、やり直すのは Undo — PowerPoint と同じ割り切り。

### トリミング中の見せ方

枠のクリッピングを外して切り落とされる側も見せる。外し方は**ステージのスタイルシート**の
`[data-hse-cropping]` ルールで、**インラインスタイルには書かない**(保存されるのは要素の `style` 属性のほう)。
減光の帯はホスト側のオーバーレイに描く(選択枠・ハンドルをステージの外に描くのと同じ理由)。

### グリップも画面上 4px 動くまで切らない

トリミング中にグリップを掴んで離しただけで履歴に「トリミング」が 1 段積まれ、
指が数 px 震えればその分だけ実際に切り取られていた([issues](../../issues.md) #30)。
移動・リサイズ・回転で先に直したもの([issues](../../issues.md) #18 / #29)と同じ症状で、
`CropController` だけがその外にいた。

**しきい値とその考え方の正は [editing-engine](../editing-engine/design.md) の
「ドラッグは画面上 4px 動くまで始まらない」。**ここはそこに乗るだけで、独自の数字を持たない
— 換算(`4 / ズーム`)ごと `deadZoneFor()` として共有する。2 つ持つと片方だけ調整されてズレる。

`begin` は DOM を書かないので、リサイズの寸法ピン留めのような順序の問題([issues](../../issues.md) #24)は
起きない。**しきい値を越えなかった press は `end()` でも何も積まない。**

## インターフェース

| 入口 | 場所 |
|---|---|
| 開始 | 画像のダブルクリック / インスペクタ「画像」パネル |
| 幾何計算 | `src/core/editing/crop.ts`(`object-fit` の描画矩形計算を含む) |
| ジェスチャ | `src/stage/cropGesture.ts` |
| オーバーレイ | `src/stage/CropOverlay.tsx` |

インスペクタの「画像」パネルには、縦横比(1:1 / 4:3 / 16:9 / 3:2)・塗りつぶし・はめ込み・
元の画像に戻す、を置く。

## 受け入れ条件(EARS 記法)

- WHEN 枠の辺をドラッグする THE SYSTEM SHALL 画像を画面上で動かさない
- WHEN 枠の角をドラッグする THE SYSTEM SHALL 2 辺を同時に動かす
- IF 辺が画像の端に達する THEN THE SYSTEM SHALL そこで止める(何も映さない枠を作らない)
- THE SYSTEM SHALL 枠を潰さない(最小サイズを保つ)
- WHEN 画像を内側でドラッグする THE SYSTEM SHALL 枠を動かさずに画像だけを動かす
- IF 画像が枠より大きい THEN THE SYSTEM SHALL どの辺も露出させない
- IF 画像が枠より小さい THEN THE SYSTEM SHALL 画像を枠の内側に留める
- WHEN `object-fit: contain` の画像を開始する THE SYSTEM SHALL レターボックスを計算して中央に置く
- WHEN `object-fit: cover` の画像を開始する THE SYSTEM SHALL はみ出しを計算する
- WHEN `object-position` が指定されている THE SYSTEM SHALL 比率でも長さでも尊重する
- IF 画像が固有サイズを持たない THEN THE SYSTEM SHALL 枠を埋める
- WHEN 枠の幅 / 高さをインスペクタで変える THE SYSTEM SHALL 中の画像も同じ倍率で拡縮する
- IF 画像がクリッピングする箱の中に単独で入っている THEN THE SYSTEM SHALL その箱を枠として使い、新しい枠を作らない
- WHEN 同じ画像でトリミングを開き直す THE SYSTEM SHALL 構造を変えず、開始前の記録も上書きしない
- WHEN トリミング済みの画像をクリックする THE SYSTEM SHALL 画像ではなく枠を選択する
- WHEN エディタが作った枠を解除する THE SYSTEM SHALL 開始前の `style` を復元して枠を取り除く
- WHEN 借りた枠を解除する THE SYSTEM SHALL 枠を残し、枠と画像の `style` を開始前に戻す
- WHEN 枠を動かしたあとに解除する THE SYSTEM SHALL 位置は保ったままサイズだけ戻す
- IF 開始前の記録が無い THEN THE SYSTEM SHALL 枠を外さず画像全体まで広げるにとどめる
- WHEN 解除を Undo する THE SYSTEM SHALL セッションの印が残らない状態で枠を戻す
- WHILE トリミング中 THE SYSTEM SHALL 枠を枠として認識し続ける(インスペクタのパネルを消さない)
- WHEN トリミング中に保存する THE SYSTEM SHALL セッションの痕跡を残さない
- IF グリップの press が画面上 4px 動かなかった THEN THE SYSTEM SHALL 何も切らず、履歴にも積まない
