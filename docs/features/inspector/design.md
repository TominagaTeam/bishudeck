# inspector — 機能設計

## 概要

選択中の要素の見た目を数値と色で編集する右側のパネル。
ステージのジェスチャが「掴んで動かす」のに対して、こちらは「正確な値を入れる」ほうを受け持つ。

## 責務と境界

**やること**

- 選択中の要素の位置・サイズ・回転の数値編集
- **パネルは全部出し、よく使う順に並べ、残りは畳んでおく。その要素に当たる先が無いものは
  グレーアウトして列の末尾へ**(後述)
- 塗り・枠線の編集
- 文字の書式(太字・斜体・下線・色・サイズ・フォント・太さ・行揃え・箇条書き・リンク)。
  **当たる先は開いているテキストセッションの有無で決まる**(後述)
- トリミングの開始と補助操作(比率・フィット・解除)
- **画像を持たない箱に画像を入れる**(「画像」パネルのもう一つの役。後述)
- 選択の階層を示すパンくずと、その要素をステージ上で指し示すプレビュー

**やらないこと**

- **DOM を自分で書き換えない。** 変更はすべて Command 経由
  ([ADR-0003](../../adr/0003-all-edits-as-commands.md))
- **元の CSS を書き換えない。** インラインの上書きだけ
  ([ADR-0004](../../adr/0004-style-edits-as-overrides.md))
- iframe の DOM に触らない。読み書きは StageBridge 越し
- 選択の決め方・ジェスチャ・履歴は [editing-engine](../editing-engine/design.md) の担当

## パネルの幅はユーザーのもの

右ペイン全体の幅は **240–520px の範囲でドラッグして変えられ、畳んで消せる**(既定 280px)。
色見本とフォント名が並ぶので狭い画面では邪魔になり、広い画面では逆に足りない。

**境界はスライド一覧と同じ `PaneDivider`** で、左右の違いは `uiStore` の `PANES` 表だけに書いてある。
レイアウトの正は [basic-design/07-ui-system.md](../../basic-design/07-ui-system.md)。ここは下限の根拠だけ:
**240px を下回ると `.field`(56px のラベル + コントロール)が崩れる**ので、
スライド一覧の 160px をそのまま流用していない([decisions.md](decisions.md) #13)。

## 文字書式の置き場は右のパネル 1 つ

文字書式(`TextFormatControls`)が出るのは**インスペクタの「文字書式」パネルだけ**。

以前は編集中のテキストに寄り添う浮遊ツールバーにも同じ部品を置き、`groups` prop で
部分集合を描いていた。**この浮遊版は撤去した** — 編集中ずっと本文の上に居座り、
編集している行の隣接行を隠すため([decisions.md](decisions.md) #15、[issues](../../issues.md) #23)。
置き場が 1 つになったので `groups` prop も一緒に消し、常に全コントロールを描く。

**「テキスト」パネルも廃止した。** フォント・色・サイズを要素へのインライン上書きとして
書く別パネルが下に並んでいて、文字書式と見分けがつかなかった
([decisions.md](decisions.md) #17、[issues](../../issues.md) #19)。

### 編集セッションが開いているあいだ、文字書式は必ず目に入る

置き場が 1 つになった以上、**そこに辿り着けないことは機能が無いことと同じ**。
セッション中は 3 つを揃って満たす:

1. **有効であること** — `offeredPanels` の判定はステージと同じものを使う。
   `isTextEditable` は「自前のテキストを持つ」を訊くので、**挿入直後の空の箱には no と答える** ——
   スライドの上で最も明らかに「これから打つ」要素なのに。ステージは編集の入口すべてで
   `isTextEditable(el) || isUntouchedTextBox(uid, el)` と例外を作っており、
   **パネルの判定だけが前半しか訊いていなかった**。
   結果は「箱を入れてダブルクリックすると、キャレットは点滅しているのに
   文字書式が画像より下でグレーアウトしている」——
   このパネルが防ぐためにあるはずの事態そのもの。
   `isTextEditable` 自体は緩めない(背景判定と同じ関数なので、
   デッキの空 div が編集対象になる。[decisions.md](decisions.md) #52 / #75)
2. **開いていること** — セッション中は畳み状態の記憶を**一時的に上書きして開く**。
   畳みは手で戻すまで残る仕様なので、いつか写真の列で畳んだ記憶がここまで効いてしまう。
   セッションは「この文字を触っている」という表明なので、閉じた見出しで応えるのは間違い。
   **ストアには書かない**ので、セッションが終われば記憶した状態に戻る
3. **画面内にあること** — セッション開始時に `scrollIntoView` する。
   列の先頭にあってもペインがスクロールしていれば切れている

**選択中のサイズ・フォント・色はコンポーネントのローカル state ではなく共有ストア**に置く。
理由は置き場が 2 つだったころとは別で、**インスペクタは選択が無くなるとパネルごと落とす**ため。
ローカル state だと、クリックを外して戻すたびに 28px へ戻ってしまう。

### 押下状態はパネルの中で揃える

B / I / U / S / x² / 箇条書き / 番号 は `aria-pressed` を持つのに、
**行揃えだけ `className="active"` しか持っていなかった**(実測 `pressed: null`)。
同じパネルに並ぶトグルなので、支援技術から見た状態表現も揃える。

### リンクはアプリのダイアログで訊く

`window.prompt` を使っていた最後の 1 箇所。見た目がアプリと揃わないのは小さいほうの問題で、
**大きいのは prompt が web プラットフォームの保証ではない**こと ——
WKWebView では埋め込み側がテキスト入力パネルのデリゲートを実装して初めて出るので、
「リンクを押して何か起きるか」が**このコードではなく、載っているシェルの性質**になっていた。
アプリが自分で描けば `npm run dev` でも `tauri dev` でも同じに振る舞う。

**ダイアログは 文字書式パネルの中に描く。** 全画面の覆いとして塗られるが、
`<body>` へ portal しない —— `data-hse-text-tools` を持っているのはパネルで、
EditStage はその印の下に落ちなかった pointerdown でセッションを閉じる。
portal したダイアログは印の外なので、**開いた瞬間にリンクを当てる先が消える**。

### `data-hse-text-tools` は器が持つ

この属性は「クリックしてもテキストセッションを閉じない場所」の目印で、
EditStage の capture リスナが `closest()` で見ている
([editing-engine](../editing-engine/design.md) の「インライン編集の抜け方」)。

**器(右のパネルの `<section>`)が持ち、部品側は持たない。**
「ホスト UI のどの領域か」は器の話で、部品が知るべきことではないため。
浮遊版を撤去したあともこの属性は**必要**で、外すとインスペクタで B を押した瞬間に
セッションが閉じて書式が当たらなくなる。

**新しい除外条件を書き足さないこと自体が設計判断**で、書き足したくなったらそれは
器に属性を付け忘れたサイン。

選択要素の computed style を読み、主要プロパティを GUI 化する:
文字(font-family / size / weight / color / align)、塗り・枠線・角丸・影、
余白(margin / padding)、配置(position / z-index / transform)。

すべて**インラインの上書き**として書く([ADR-0004](../../adr/0004-style-edits-as-overrides.md))。

## 当たる先は「いま何を選んでいるか」で決まる

同じコントロールが 2 つのスコープを持つ。

| 状態 | 当たる先 | 経路 |
| --- | --- | --- |
| テキストセッションが開いている | その選択範囲 | `execCommand` → `SetInnerHtmlCommand` |
| 開いていない(要素を選んだだけ) | 要素まるごと | `SetInlineStyleCommand` |

PowerPoint と同じで、**ボックスを選んで書式を変えれば全体に、範囲を選べばその範囲だけ**に効く。
分岐は `TextFormatControls` の `applyToScope` 1 箇所にあり、
判定は `activeTextSession()?.uid === uid` — **セッションの有無だけでなく uid の一致まで見る**。
別のボックスに開きっぱなしのセッションが、いま選んでいる要素への編集を横取りしないため。

**この分岐を持つのはフォント・文字色・サイズの 3 つだけ。**
太字・斜体・下線・取消線・蛍光・箇条書き・リンクは従来どおり選択範囲専用で、
**太さと行揃えは逆に、セッションが開いていても常に要素へ書く**([decisions.md](decisions.md) #18)。

**要素へ書く 2 つは、先にセッションを確定してから積む**(`asOwnStep`)。
範囲へ書くものは `withUndo` が前後で確定するので何もしなくてよいが、この 2 つはそこを通らない。
確定せずに積むと**打った文字が履歴から消える**（[issues](../../issues.md) #44。
仕組みと、順序としてもこれが正しい理由は
[features/editing-engine](../editing-engine/design.md) の「履歴の基準」）。

### 要素スコープの上書きは、リストの中まで届かせる

**要素スコープだが、要素「だけ」ではない。** 要素へ書いた宣言は、
その中の `ul` / `ol` / `li` にも配り直す(`src/core/editing/listOverrides.ts`)。
**要素スコープの経路はすべてここを通る** — 行揃え・文字色・サイズ・フォント・太さ・
Format Painter の貼り付け。

選択がリストになることは無い — `chooseSelectionTarget` が `UL` / `OL` / `LI` を
**選択に対して透過**させるので([editing-engine/design.md](../editing-engine/design.md) の選択モデル)、
箇条書きの行をクリックしても必ず外側のテキストボックスに登る。
つまり宣言は構造上リストの外側にしか書けず、行までは**継承でしか届かない**。

**そしてデッキが `ul` / `li` を型セレクタで名指していると、継承は必ず負ける。**
カスケードは「どの宣言が強いか」を問う前に「この要素に宣言が当たっているか」を見るので、
親がインラインでも関係ない — 親はそのルールがマッチした要素ではないため。

配り方は 2 種類あり、**行揃えだけが別扱い**。

| | 何を配るか | いつ配るか |
| --- | --- | --- |
| **行揃え** | `text-align` に加えて `list-style-position` / `padding-left` | リストがあれば**無条件に全ノード** |
| **他の継承プロパティ** | `color` / `font-family` / `font-size` / `font-weight` / `line-height` | **継承が遮られていると実測できたノードだけ** |

#### 行揃え(issues #27)

継承だけでは 3 通りに負けることを実測した(サンプルデッキ)。

| | 継承だけだと | 打った手 |
| --- | --- | --- |
| `ul` の `padding-left` | 左だけの余白の**半分だけ中心がずれる**(実測 15.59px) | 中央・右のとき `padding-left: 0` |
| `list-style-position: outside` | 行頭記号が `li` のコンテンツボックスの外に置かれ、**文字だけ動いて記号は左に残る** | 中央・右のとき `inside` |
| デッキが `ul` / `li` に `text-align` を宣言 | **子孫の宣言に負けて何も動かない**(実測 -303px = 左端のまま) | `li` にも直接書く(インラインは常に勝つ) |

**マーカーに触るのは中央・右のときだけ。** 左と `justify` は行頭が左に揃うので、
`outside` のままが正しい。左へ戻すときは上書きを**消す**(`''` = `removeProperty`)ので、
デッキ側の宣言が残る。

`justify` の枝は**ボタンを畳んだあとも残す**([issues](../../issues.md) #39)。
インスペクタからは書けなくなったが、**デッキ自身が `text-align: justify` を持つ**要素で
箇条書きにすると、`carryAlignmentIntoLists` が computed からその値を受け取って配るため。

**無条件に配るのは行揃えだけ。**「揃える」という指示そのものが行に向いていて、
リスト自身の余白とマーカーも口を出すので、**何も宣言されていないノードにも打つ手がある**
([decisions.md](decisions.md) #31)。

**リストを作ったときも同じことをする。** `execCommand` が建てた `ul` は自分の行揃えを持たないので、
**中央揃え → 箇条書き**の順でも崩れないよう、リストコマンドの直後に要素の現在の行揃えを配り直す
([editing-engine/design.md](../editing-engine/design.md) のリストの節)。
誰も行揃えを触っていない要素(computed が `start`)には**何も書かない**。
**サイズ・色はここに乗せない** — 「未指定」を表す値が無いため([decisions.md](decisions.md) #37)。

#### 他の継承プロパティ(issues #31)

**測ってから降ろす。** 新しい値を要素へ一時的に当て、各リストノードの computed を
**要素自身の computed と比べる** — 一致すれば継承が通っているので何もせず、
食い違えばそのノードに直接書く。実測(サンプルデッキ、`ul { font-size: 26px }`)：

| 経路 | 修正前(箱 / 行) | 修正後(箱 / 行) |
| --- | --- | --- |
| 書式のコピー | 32px / **26px** | 32px / 32px |
| インスペクタのサイズ | 60px / **26px** | 60px / 60px |
| 文字色(デッキが `ul` を名指していない) | 届く | 届く。**上書きは書かれない** |

比較の両辺を computed で取るのが肝。インスペクタは `#ff0000` を渡すがフレームは
`rgb(255, 0, 0)` と答えるので、生の入力値と比べると**全デッキの全リストに色の上書きが増える**。

**直しながら測る。** ノードは文書順に見て、遮られていたらその場で当ててから次を測る。
`ul` を直せば `li` は継承で届くので、**デッキのルール 1 本に対して上書きは 1 つ**で済む。
デッキが `li` も名指していれば、そのときは `li` にも書かれる。

**ボックス系(`background-color` / `padding` / 枠 / 不透明度)は絶対に降ろさない。**
継承しないので `li` が箱と食い違うのは正常であり、遮りと読むと行ごとに背景が塗られる。
インスペクタの他の欄が `SetInlineStyleCommand` のままなのはこのため。

#### 書き先が複数になるので

コマンドは `SetInlineStyleGroupCommand`
(uid → 宣言の対応表を 1 つ受け取り、1 手で戻す)。リストが無ければ、あるいは
遮るものが無ければ書き先は要素 1 つだけで、
**従来の `SetInlineStyleCommand` とまったく同じ形**に落ちる。

サイズ欄の連打が 1 手に畳まれるのも従来どおり。ただし
**「遮られている / いない」が切り替わる 1 打鍵だけは書き先が変わる**ので、
`tryMerge` が断って undo が 1 手増える(コマンドが触る対象が実際に変わっているため、これを正とする)。

### 数値欄は PowerPoint と同じ確定にする

**打った数字は下書き。Enter とフォーカス移動で確定する。スピナー(▲▼・↑↓)だけが即時。**

以前は**打鍵ごとに当てて**いた。「サイズは見て決める値なので、確定操作を挟むと 1 打ごとの結果が
見えない」という理由で、遅延コミットの `NumberField` を撤去してまで揃えた
([decisions.md](decisions.md) #25 / #48)。それを覆した。理由は 2 つ。

1. **PowerPoint がそうしている。** フォントサイズ欄は打った値を Enter / フォーカス移動で確定し、
   スピナーだけが即時。ユーザーの求めているのは「馴染みのある操作」であって、
   当時の判断が優先した「見て決められること」とは別の軸だった
2. **打鍵ごとの適用は実際に壊れていた。** `9` → `6` と打つと欄は `486`、スライドは 200px
   (上限クランプ)。`100` は 8px→200px→200px を経由して欄は `6400` を表示。
   欄とスライドが blur するまで食い違う(実測)

当時の理由には答えを用意した。「見て決められない」→ **スピナーが即時**なので見て決められる。
「数値欄が 2 流儀になる」(#48)→ **全部の数値欄を同じ方式に揃えた**(文字サイズ・余白・角丸・
枠線の太さ・位置とサイズ)。「blur を起こすのが別のボックスへのクリックだから退避が要る」→ 下記。

**スピナーと打鍵は `change` イベントで分ける。** 座標でもイベントの種別の推測でもない。
実測すると **▲ / ↑ は `input` と `change` を同時に出し、打鍵は `input` だけで
`change` は Enter / blur まで出さない**。つまり `change` がそのまま
「この数値はもう決まった」の意味になる —— HTML がもともと持っている区別で、
こちらが推測する必要がない。React の `onChange` は 2 つを畳んで区別できないので、
`ref` 経由で素の `change` を聴く。

**キャンバスをクリックして確定する経路は順序が逆になる。**
セッションを閉じるのは window の capture フェーズの `pointerdown` で、これは `blur` より**先**に走る。
つまり「セッションが閉じた後に blur が来る」ので、そのままでは適用先が無い。
`richText.ts` の `onBeforeSessionEnd` が `setTextSession` の唯一の代入点で鳴るので、
**閉じる直前に下書きを流す**。EditStage に flush の呼び出しを撒かないのは、
セッションを閉じる経路が複数あり、今後増えたときに取りこぼすため。

### サイズは、範囲スコープでも連打に耐える

範囲へ当てる経路は `execCommand` を通るので、**打鍵のたびに素通しするわけにはいかない**。
2 つの問題があり、それぞれ別の場所で潰している([decisions.md](decisions.md) #26)。

| 問題 | 起きること | 潰し方 |
| --- | --- | --- |
| `prepareSelection` が iframe にフォーカスを戻す | 2 文字目が**本文に打ち込まれる** | 適用後に数値欄へフォーカスを戻す(`LiveNumberInput`) |
| 毎回 span で包み直す | 内側の span が勝ち、**打っても大きさが変わらない** | 直前に作った span がまだ選択されていれば、包み直さず `font-size` だけ差し替える(`setFontSize`) |

再利用してよいかの判定は **Range の一致**で行う。`reselect` が張った範囲を
`withUndo` 末尾の `snapshotSessionRange` が退避しているので、**サイズを触り続けている間だけ**
境界が一致する。ユーザーが本文をクリックし直せば一致しなくなり、自動的に `execCommand` 経路へ戻る
(無効化フックを各所に置かずに済む)。

包んだ span の**内側に残った `font-size` は剥がす**。宣言はテキストに近いほうが勝つので、
残すと指定したサイズが見えない。剥がすのは宣言だけで、要素は残す
(デッキ自身の `class` 付き span を消さないため。`dropPreservationSpans` と同じ線引き)。

### 欄はキャレットの書式を映す

**セッション中は、サイズ・フォント・太さの 3 欄がキャレット位置の実効値を映す。**
キャレットを動かせば欄が切り替わる —— PowerPoint のリボンと同じ。

以前は **uid が変わったときだけ computed で seed** していた。理由は
「範囲に当てても要素の computed は変わらないので、要素を映すと 3 文字だけ変えた瞬間に表示が戻る」で、
それ自体は正しい。だが**キャレット位置の実測値を読む経路が無かった**ので、
200px にした部分から 64px の部分へキャレットを動かしても**欄は 200 のまま**だった(実測)。
B / I / U / S の点灯だけが追従していたのは、そちらが `queryCommandState` に乗っていたから。

サイズ・書体・太さは**真偽値ではなく値**なので `queryCommandState` には乗らない。
選択範囲が覆うテキストノードの親を `getComputedStyle` で読み、値ごとに畳む。
**全員一致ならその値、割れたら「何も言えない」**(PowerPoint と同じく欄を空にする)。
3 プロパティは独立に判定するので、サイズだけ混在なら書体と太さは値が出る。

**読み取りは既存の 200ms ポーリングに相乗りさせる。** 2 本目のタイマーは生やさない。
ステージはスクリプトを走らせないので `selectionchange` がホストに届かず、
点灯を追うために既に見に行っている —— そこに `getComputedStyle` を足すだけ。
実測で `queryCaretStyle()` が 0.006ms、既存の `queryFormatState()` が 0.404ms なので増分は約 1.5%。
**値が変わらない限り publish しない**ので、打鍵中に欄を踏まない(実測 8 打鍵 / 7 tick で publish 0 回)。

**欄がフォーカスを持っている間は下書きが正**で、追従は入らない。さもないと打っている数字が
ポーリングに巻き戻される。セッション外は従来どおり要素の computed から seed する。

**空の `styles` では seed しないこと。** computed の読み取りは effect なので、
選択直後の 1 レンダリングは値が来ていない(後述の uid 添え)。そこで seed するとデッキ中のどの箱も 28px になる。

### 太さは範囲に効く。行揃えは効かない。それをヒントで言う

**太さ(400/700…)は範囲を選べばその範囲だけに効く** —— B ボタンと同じスコープ。
以前は範囲を選んでいても要素全体に落ちていた(実測 `<h1 style="font-weight: 400;">`)。
範囲を選ばずに押したときは従来どおり要素全体。

**呼び分けは「セッションがあるか」ではなく「範囲があるか」で行う。**
値を書く 3 つ(サイズ・書体・太さ)は**キャレットだけの状態を意図的に拒む** ——
`execCommand` はそこで要素を 1 つも作らず pending style を立てるだけで、
その pending style は数値欄がフォーカスを取り返した瞬間に捨てられ、
**`<font>` だけがスライドに残る**(`hasSessionRange` / richText.ts)。

セッションの有無だけで振り分けていたときは、**最もよくある操作** ——
箱をクリックしてサイズを変える —— が「何も起きないコマンド」に流れていた。
パネル冒頭のヒントは「範囲を選ばずに押すと、これから打つ文字に効きます」と
約束していたので、**サイズについてはその約束が嘘だった**。

範囲が無ければ要素へ落とす。それはユーザーの意図でもある ——
何も選んでいないときの「大きくして」は、箱についての話。

**行揃えは範囲を無視する。** 段落単位の操作なので設計として正しいが、
「選んだ範囲に適用」と書かれた枠の中に範囲を無視する操作が混ざっているのは直感に反する。
ヒントの主語を**文字の書式**に限り、例外はヒント本体に並べず**例外の側に置く**
(280px の枠でヒントが 3 行になるのを避けるため) —— 行揃えのボタンと太さのセレクトに
スコープを言う `title` を付けた。箇条書き / 番号は据え置き:
`insertUnorderedList` は選択範囲が触る段落に効くので「選んだ範囲に適用」は嘘ではない。

## 行揃えの点灯は、論理値を物理の側に直してから比べる

**誰も揃えていない要素の computed は `left` ではなく `start`。**
ボタンが持つのは `left` / `center` / `right` という**物理値**なので、
computed をそのまま比べるとどれも消灯し、左に揃って見えている要素について
「まだ何も選んでいない」と言ってしまう([issues](../../issues.md) #32)。

`shownAlign()`([styleValues.ts](../../../src/features/styleValues.ts))が
`start` / `end` を要素の `direction` で解決してから比べる。

| computed | `ltr` | `rtl` |
| --- | --- | --- |
| `start` | 左 | 右 |
| `end` | 右 | 左 |
| `left` / `center` / `right` | そのまま | そのまま |
| `justify`(デッキ由来) | そのまま = **点灯なし** | 同左 |
| `''`(読み取りが届く前の 1 レンダリング) | 点灯なし | 点灯なし |

**`justify` はどのボタンにも当たらない。** 両端ボタンを畳んだ([issues](../../issues.md) #39)ので、
デッキ自身が両端揃えを宣言している要素では 3 つとも消灯する。#32 の症状が
**justify のデッキにだけ残る**形だが、`左` に倒して点けるほうが悪い —
要素が持っていない選択を UI が主張し、続けて `左` を押すと「何も起きていないのに上書きが増える」ため。

**RTL では「文字が実際に寄っている側」を点ける。** ラベルが 左 / 右 という物理の名前である以上、
`start` に 左 を点けると**文字の無いほうの端**を指すことになる([decisions.md](decisions.md) #40)。

**読むだけで、書く側は変えない。** `chosenAlign()`(`listOverrides.ts`)は `start` を
「誰も選んでいない」として扱ったまま — あちらは**上書きを書くかどうか**の判断で、
同じように解決させると箇条書きを 1 回押しただけのデッキに `text-align` が書き込まれる
([行揃え(issues #27)](#行揃えissues-27) の「リストを作ったときも同じことをする」)。
`direction` は `READ_PROPERTIES` にだけ足した(後述の「読むものと塗るものは別のリスト」)。

## 出すのは全部。効かないものはグレーアウトする

パネルもコントロールも、**当たる先が無くても描く。描いたうえで無効にする**
([decisions.md](decisions.md) #56)。

**右ペインはこのアプリに何ができるかの一覧でもある。** 消してしまうと、
「画像を選ぶと文字書式が無い」ことを**ユーザーの記憶に預ける**ことになり、
一度見た機能が次に見えないのは不具合と区別が付かない。
グレーで残っていれば、そこに何があるかと、いま使えないことの両方が同時に見える。

**代わりに払うのは高さ**で、そのぶんは**畳むことと並べる順**で取り返す(後述の「並びと折りたたみ」)。
無効なパネルは**畳んだまま列の末尾**に置き、中身そのものを作らないので、
1 枚あたりの費用は `summary` 1 行で済む。

**「効かない」と「間違っている」は別物**で、後者にはグレーアウトだけでは足りない。
位置とサイズがそれで、扱いは後述する。

### 何が無効になるか

| 階層 | 無効になるもの | 条件 |
| --- | --- | --- |
| パネル | 文字書式 | `isTextEditable` が false(画像・挿入した直線・文字を持たない箱) |
| パネル | 画像 | `isCroppable` も `isFillable` も false(文字を持つ要素・`<svg>` や `<video>`) |
| パネル | 位置とサイズ | **この要素で**テキストセッションが開いている |
| コントロール | B / I / U / S・x²・解除、蛍光、箇条書き / 番号、リンク | テキストセッションが開いていない |
| コントロール | 縦横比・枠に合わせる・元の画像に戻す | トリミングの枠が開いていない |

**ボックス・枠線は無効にならない。** 余白・角丸・背景・枠線は `<img>` にも `<svg>` にも効くので、
「この要素には意味がない」と言える相手がいない。

### パネル単位 — 門番は同じ 2 つの試験のまま

**文字書式パネルが生きるのは、自分の文字を持つ要素のときだけ。**
判定は [`isTextEditable`](../../../src/stage/selectionHeuristics.ts)
(`!isReplaced(element) && hasOwnText(element)`)で、
**ダブルクリックがテキストセッションを開くかどうかと同じ試験**。
トリミングパネルは `isCroppable` で同じことをしている。

**同じ試験を使うこと自体が判断**([decisions.md](decisions.md) #21)。
別の条件を書くと「編集には入れるのに書式が使えない」「書式は使えるのに編集に入れない」という
食い違いが生まれ、どちらが正しいのか誰にも言えなくなる。
**変わったのは試験の答えの使い道だけで、試験そのものではない。**

#### 画像パネルは 2 つの役を 1 つの席で持つ

**画像が生きる理由は 2 つあり、種別なのは片方だけ。**

| 選んだもの | パネルの中身 | 生かす試験 |
| --- | --- | --- |
| 画像(またはトリミング枠) | トリミングと補助操作 | `isCroppable` |
| 画像でない箱 | 「画像を入れる」ボタン 1 つ | `isFillable` |

後者は**取り込んだデッキの写真枠**のための経路。Artifacts の `<image-slot>` は
自分でドロップを受け取るカスタム要素だが、その実装はテンプレートランタイムの一部で、
取り込みが捨てるしかない([import-pipeline](../import-pipeline/design.md) の
「自己展開型アーカイブの展開」)。**残るのは破線の箱とキャプションだけで、
写真を落としても何も起きない**([issues](../../issues.md) #100)。
元のコンポーネントも `window.omelette.writeFile` が無い環境では読み取り専用なので、
書き出した HTML を素のブラウザで開いた時点で動かないのは元からの仕様。

**操作は「枠に入れる」ではなく「選んだ箱の中身を画像に差し替える」。**
枠だと見分ける印を持てないため —— 理由と markup の中身は
[editing-engine](../editing-engine/design.md) の「箱に画像を入れる」が正。

**このボタンは 3 つある入口の 1 つで、本線ではない。** 本線は**箱の右クリックメニューの
「画像を入れる」**(とドロップ)で、どれも同じ `fillSelectionFromPicker()` を呼ぶ。
2026-08-26 まで本線はダブルクリックだったが、
ジェスチャの意味が箱の中身で変わる形をやめた([editing-engine](../editing-engine/design.md) の
「入口は 3 つ」)。パネルに残す理由は
トリミングと同じ ——「ジェスチャを知らなくても、パネルを見れば何ができるか分かる」
([decisions.md](decisions.md) #56 の「出すのは全部」)。

**`isFillable` は 3 つ目の試験ではない。** 中身は既存の 2 つの否定
(`!isCroppable && !isTextEditable`)に「子を持てない要素か」を足したもので、
**新しい「画像とは何か」を宣言していない**。だから種別(`ElementKind`)には影響せず、
画像パネルを生かすかどうかだけを決める。

**無効なパネルは中身を作らない。** 開けない以上、誰も届かないコントロールになるうえ、
作るのは無料ではない — 文字書式は要素の computed からドラフト欄を seed し、
画像はトリミングセッションを購読する。**無効なパネルの実体は `summary` 1 行**
(`DisabledPanel`、[CollapsiblePanel.tsx](../../../src/features/CollapsiblePanel.tsx))。

**見出しは押せない。** `onToggle` が呼ばれないので、無効なパネルから
`hse.inspectorPanels` に上書きが書かれる経路がゼロになる — 逆向きも同じで、
**無効なパネルは折りたたみの記憶を読まない**。生きている列の記憶と混ざらないため。

**タブ順からは外さない。** `aria-disabled="true"` を付けてフォーカスは通す。
タブ順から抜くと、スクリーンリーダーのユーザーにとっては**消したのと同じ**になり、
全部描いた意味がその人にだけ失われる。

**理由は `summary` の `title` と `aria-description` に出す**
(`inspector.disabledText` / `…Image` / `…Geometry`)。
文言は「なぜ使えないか」ではなく**「何をすれば使えるか」**——
「画像ではありません」は選択を見れば分かることの言い換えにしかならない。

### コントロール単位 — 範囲が無ければ範囲専用のものが暗くなる

| | セッション外 | セッション中 |
| --- | --- | --- |
| B / I / U / S・x²・解除 | **無効** | 使える |
| 蛍光 | **無効**(文字色と同じ行) | 使える |
| 箇条書き / 番号・リンク | **無効** | 使える |
| 文字色・サイズ・フォント・太さ・行揃え | 使える | 使える |

**文字色が生きたまま隣の蛍光だけが暗くなる行**が、
[当たる先は「いま何を選んでいるか」で決まる](#当たる先はいま何を選んでいるかで決まる)の
2 つのスコープを画面 1 行で説明している。文字色は要素にも書けるが、
蛍光には要素まるごとの意味が無い(箱の背景は `塗り` のほう)。

**ヒントの文言は状態で切り替えたまま**(`inspector.textFormatHint` / `…HintRange`)。
以前は「消えた理由」を言うために要ったが、いまは「暗い行を明るくする方法」を言うために要る。
**個々のコントロールにも `title` を出す**(`text.rangeOnly`)。

**トリミングも同じ形にした。** 縦横比・枠に合わせる・元の画像に戻すは枠が開くまで無効で、
ヒントが `inspector.cropHintIdle` に切り替わる。
以前は「トリミング」ボタン 1 つしか出ておらず、**このパネルにそれしか無いように見えていた**。

**`aria-pressed` は無効でも残す。** ボタンがトグルであることは、いま押せるかどうかとは別の事実。

### パネル単位 × モード — セッション中の「位置とサイズ」は暗くする

**テキストセッション中、位置とサイズは無効になる**([issues](../../issues.md) #37)。
他が「押しても効かない」なのに対し、**これだけは出ている数字そのものが間違っている**。

X / Y / 幅 / 高さは `Inspector.tsx` の再読み取り effect が `[uid, revision]` で読むもので、
`revision` はコミットのたびに動く。ところが**タイピングはコマンドを 1 つも作らない**
(キー入力はスクリプト無効の iframe に落ちてホストに届かない)ので、
セッション中に本文を伸ばしても高さの欄は開いた瞬間の値のまま止まる
(実測: 実寸 66px → 132px に対し、欄は 66 のまま)。

**だから「暗くする」だけでは足りず、値そのものを画面から外す必要がある。**
無効なパネルが `summary` 1 行で、中身を作らず、押しても開かないという性質が
そのまま効いている——**古い数字に届く経路が無い**。

- **折りたたみの上書きを読まないので、上書きに負けない。**
  一度でも手で位置とサイズを畳んで開き直したユーザー(`{geometry: true}` が保存済み)でも、
  セッション中は畳まれたまま
- **見出しを押しても開かないので、そこから上書きも書かれない。**
  セッション後の既定が書き換わる経路もゼロ

**暗くするのは `geometry` だけ。** ボックスと枠線は文字を編集している間も箱の見た目を表しているので触らない。
判定は「このデッキでセッションが開いている」ではなく **「この要素で開いている」** で、
文字書式パネルが使っているものと同じ式(`useTextSession((s) => s.uid) === uid`)。
第三の意見を作らないため([decisions.md](decisions.md) #21)。

**セッション中に開くパネルは文字書式 1 枚**になる。「開くのは 2 枚まで」は上限の宣言なので違反しない。


### 並びは 56px のラベル列に揃える

箇条書き・番号・リンクは**ラベルの無い行に素で置かれていて**、
上の欄が揃っている 56px の列から外れて左端にぶら下がっていた。
`段落` / `挿入` のラベルを与えて `Field` に載せ、箇条書きと番号は行揃えと同じ連結ボタンにした。

**リンクを上のツールバー行に混ぜない。** 既定幅 280px では B〜解除で行がほぼ埋まり、
リンクだけが折り返して結局「単独行にぶら下がるボタン」に戻る。

## 行のタグは、載せるコントロールで決まる

`Field` が描く行は **`<div>`** で、`<label>` ではない。
`<label>` は `for` が無くても「最初の labelable な子孫」と暗黙に関連付き、**click をそこへ転送する**。
labelable には `button` も含まれるので、行全体を `<label>` で包むと
ラベル文字・56px 列の余り・入力欄の右の空白のどこを押しても**先頭のコントロールが動いた**
([issues](../../issues.md) #28。実マウスで実測)。

| 行の中身 | タグ | ラベルの結び方 |
|---|---|---|
| ボタン群・コントロールが複数(行揃え・段落・背景・枠線の種類・文字色・枠線の太さ・余白・挿入・縦横比・枠に合わせる) | `<div>` + `<span>` | `role="group"` + `aria-labelledby` |
| コントロールが 1 つ(不透明度・角丸・枠線の色・文字サイズ・フォント・太さ) | `<div>` + `<label for>` | `for` / `id` で明示 |
| `.field.compact`(位置とサイズ・辺ごとの余白) | `<label>` のまま | 暗黙(子孫は入力欄 1 つだけ) |

**1 つのときだけ `<label>` を残すのは、ラベルを押して入力欄へフォーカスが利くから。**
`onClick` を `preventDefault` して転送を止める案もあったが、それだと label 本来の利点まで消える。
結び先は `Field` の `children` に**関数**を渡した行だけで、関数は `useId()` が作った id を受け取る
(`{(id) => <LiveNumberInput id={id} … />}`)。
呼び出し側が id を書かずに `for` だけ付ける、が構造的に起こらない。

**`.field.compact` を直さないのは、直す理由が無いから。** 入力欄が `width: 100%` で列を埋めるので、
転送先を取り違える余白がそもそも無い。

**文字色がボタン群と同じ扱いなのは、行の中身がセッションで変わるから。** セッション外は分割ボタン 1 つだが、
開くと蛍光がもう 1 つ増える。結び先が状態で入れ替わる行は、どちらにも結ばないほうが読める。

## `mousedown` の既定動作を止めてよいのは、それが「フォーカスの移動」だけのとき

このパネルのボタンは軒並み `onMouseDown={(e) => e.preventDefault()}` を持っている。
**`<select>` には付けない。**([issues](../../issues.md) #40)
判定はコントロールの種類ではなく、**そのコントロールで `mousedown` が既定で何をするか**で行う。

| コントロール | `mousedown` の既定動作 | 止めると |
|---|---|---|
| `<button>`(B / 解除 / 行揃え / 段落 / リンク / 色の分割ボタン / スウォッチ) | **フォーカスの移動** | フォーカスがフレームに残り、選択範囲が視覚的にも保たれる |
| `<input type="color">`(パレットの「その他の色」) | **フォーカスの移動だけ。**OS のダイアログを開くのは `click` のほう | フォーカスは動かず、**ダイアログはそれでも開く**。付けたままでよい |
| `<select>`(フォント・太さ) | **ポップアップの表示**(Chromium / WebView2) | **リストが出ない。**マウスからは選べなくなる |

太さの `<select>` だけが周りのボタンと揃えて `preventDefault` を持っていて、
**そのせいでリストが 1 度も開かなかった**。フォントの `FontSelect` には最初から無い。

**`<input type="color">` が巻き添えにならないのは、開く仕掛けが `mousedown` の側に無いから。**
HTML 仕様はピッカーの表示を **input activation behavior** に置いており、これは `click` の
ディスパッチ中に走る。`mousedown` の `preventDefault` は `click` も activation behavior も止めない
(止めるなら `click` の側で止めることになる)。Blink・WebKit ともに `ColorInputType` の
`HandleDOMActivateEvent` から開いていて、`mousedown` の枝に居るのは `<select>` のポップアップ
(`MenuListSelectType::DefaultEventHandler`)だけ。**同じ「既定動作」でも乗っているイベントが違う。**

実測(2026-08-24 / headless Chrome を CDP の実マウスで叩いた)も同じ答えだった。
`preventDefault` した `mousedown` を `<input type="color">` に送ると、**フォーカスは動かない**
(= `preventDefault` は確かに効いている)のに `click` は `defaultPrevented: false` で届く。
OS のダイアログそのものは DOM から見えないので、**同じ activation behavior で開く
`<input type="file">`** を代役にして測った — `Page.fileChooserOpened` は `preventDefault` の
有無にかかわらず 1 回ずつ発火した。`<select>` のポップアップは headless では描かれないので
**測れない**(#40 は実アプリで再現したもの)。

**止めなくても選択範囲は死なない。** 範囲を守っているのは `preventDefault` ではなく退避と復元のほう —
[`data-hse-text-tools`](#data-hse-text-tools-は器が持つ) を見ている EditStage の capture リスナが
パネルの上の `pointerdown` で `snapshotSessionRange()` を呼び、コマンドの実行直前に
`prepareSelection()` が戻す(`richText.ts`)。フォントが確認ボタン無しで成立しているのがその実証で、
太さはそもそも[要素スコープ](#当たる先はいま何を選んでいるかで決まる)なので範囲を使いもしない。

**キーボード(Tab → ↑↓)は塞がっていなかった。** 適用は `change` に載っていて、
`mousedown` はマウスの側にしかない。**マウスだけが効かない**という切り分けが、原因を 1 行に絞った。

## 並びと折りたたみ

**要素を選んだ直後に見えるのは、その要素で最もよく触る 2 枚分の欄だけ**にする。
残りは畳んであり、見出しを押せば従来どおり全部ある。

以前は 5 枚のパネルを全部開いたまま 1 本のスクロール列に積んでいて、
見出しを選ぶと**入力欄が 17 行**並んだ([issues](../../issues.md) #20)。
同時に、**目当てのものが上にあるとは限らなかった** — 写真を選んでも余白と角丸が先に来る(#22)。
この 2 つは同じ問題の裏表で、**どちらも「効かない欄を消す」では解けない**。

**この節が前節の請求書を払う。** パネルもコントロールも全部描くようになったぶん
(#55)、列は伸びる — 見出しを選んだ直後に見えている入力行は **10 → 12 行(全 19 行)**
になった(2026-08-25 の実測)。#20 が求めたのは「選んだ直後に列の全部を突き付けない」ことで、
12 / 19 はそれを満たしている。**上限は測り直したが、規則は動かしていない。**

### 表は 1 つ、置き場は `inspectorLayout.ts`

| 種別 | 並び(`*` は既定で開く) |
| --- | --- |
| テキスト | 文字書式\* → 位置とサイズ\* → ボックス → 枠線 |
| 画像 | 画像\* → 位置とサイズ\* → ボックス → 枠線 |
| 図形・その他 | 位置とサイズ\* → ボックス\* → 画像 → 枠線 |

**開くのは 2 枚まで。** 既定幅 280px でスクロールせずに見えるのがおよそその量なので、
「選んだ直後に何が見えているか」を**窓の高さではなくこの表が決める**状態にしておく。

**位置とサイズはどの種別でも開く。** 見た目ではなく物そのものの数値を持つ唯一のパネルだから。
ただし**テキストセッション中だけは無効になる**(前節。[issues](../../issues.md) #37)。
図形だけ 2 枚目がボックスなのは、スライド上の四角は**塗りのために置かれている**のに対し、
テキストと写真は文字か切り取りのために選ばれるため。

**種別の判定に新しい条件を書かない。** `isCroppable` と `isTextEditable` をそのまま使う
([decisions.md](decisions.md) #21 と同じ理由)。3 つ目の「画像とは何か」を書くと、
いずれ既存の 2 つと食い違い、どれが正しいのか言えなくなる。
`isFillable` もこの規則の中にいる —— 既存 2 つの答えを読み合わせるだけで、
**種別は動かさず**、画像パネルを生かすかどうかだけを決める(前節)。

**図形の列で画像が枠線より上にいるのは、そこが写真枠の居場所だから。**
畳んだ状態で置くので「開くのは 2 枚まで」は変わらない。
末尾に流すこともできたが、**探しに行かないと見つからないパネルでは
[issues](../../issues.md) #100 の答えにならない**。

**表に載っていないパネルも必ず描く**(有効なまま、畳んだ状態で、無効な列の手前に)。
表は優先順位の宣言であってホワイトリストではない。想定していない組み合わせの要素が来たとき、
**表の書き漏らしでパネルが使えなくなるほうが、順番がおかしいより悪い**。

**無効なパネルはそのさらに後ろ**に、`ALL_PANELS` の順で並ぶ。
先頭が位置とサイズなのは、**モードで無効になる唯一のパネル**だから — セッションを抜ければ戻るので、
一時的な状態のために列が組み替わらないほうがいい。画像と文字書式は
**要素が何であるか**で決まり、選んでいる間は変わらない。

**「開くのは 2 枚まで」を無効なパネルは使わない。** `summary` 1 行ぶんしか場所を取らず、
決して開かないため。

**モード軸で無効になるのは位置とサイズだけ**(前節)。落とす先は並び(`ordered`)ではなく
**要素が申し出た集合(`enabled`)のほう**で、そうしないとこの「載っていないものは末尾へ」の節が
畳んだ状態で**有効なまま**復活させてしまう。

### 覚えるのは「ユーザーが触ったパネルだけ」

開閉の上書きは `uiStore` の `inspectorPanels` に載り、`hse.inspectorPanels` として
`localStorage` に残る(ペイン幅と同じキューに乗る。[decisions.md](decisions.md) #28)。

**入るのは手で開け閉めしたパネルだけ**で、触っていないものは表の既定に従う。
全パネル分を常に持つと、**誰かが枠線を 1 回畳んだ瞬間に全キーが埋まり、
以後どの要素を選んでも表が引かれなくなる** — 上の並び順が 1 クリックで死ぬ。

**この記憶は生きている列だけのもの。** 無効なパネルは読みも書きもしない(前節)。
読めば「文字書式が使えたころに開いた」記憶が写真の上で復活し、
書ければ使えないパネルから有効時の既定を書き換えられてしまう。

### 開閉は `<details>`。ただし動かすのはクリックだけ

`CollapsiblePanel` は `<details>` / `<summary>` の**制御コンポーネント**。
キーボード操作と `aria-expanded` がネイティブに付いてくるので、`PaneDivider` のような手書きが要らない。

**`toggle` イベントは購読せず、`summary` のクリックを `preventDefault` して外から開閉する。**
`toggle` は属性が変わるたびに飛ぶので、**選択が別種別の要素へ移って React が開閉を描き直しただけでも発火する** —
それを拾うと、ユーザーが触っていないパネルの上書きが次々に記録され、上の「触ったものだけ」が数クリックで崩れる。
`summary` の Enter / Space はクリックとして届くので、`preventDefault` してもキーボードは失われない。

## computed の読み取りには uid を添える

読み取りは effect で行うので、**選択が変わった直後の 1 レンダリングは前の要素の値を持ったまま**になる。
すぐ上書きされるフィールドには無害だが、塗りの色見本のように「与えられた値を覚える」フィールドは
前の要素の色を握ってしまう(実際に、塗りの無い見出しの色見本に直前に選んだ図形の色が出ていた)。
**uid が一致しない読み取り結果は捨て、その 1 レンダリングは空として描く。**

## フォント

**select で選んだ瞬間に適用**する(確定ボタンは無い)。
どちらのスコープに当たるかは「当たる先は『いま何を選んでいるか』で決まる」のとおり。

文字単位のときは `execCommand('fontName')` → `<span style="font-family:…">` へ書き換え、
適用後は生成した span を**選択し直す**(古い選択はノード差し替えで死んでいるため、
これが無いと 2 回目の選び直しが空振りする)。

## 文字色と蛍光は「当てる」と「選ぶ」を分ける

どちらも **分割ボタン**。左はアイコン(文字色は色のバーを敷いた A、蛍光はマーカー)で、
**バーが示す色をそのまま当てる**。右は ▼ で、**押すとその場にパレットが開く**(OS のダイアログではない)。

**分けたのは、色を当てる操作の大半が「もう一度同じ色」だから。**
`<input type="color">` は `change` でしか発火しないので、直前に当てた色を別の範囲へもう一度、という
最も多い操作にジェスチャが無かった([issues](../../issues.md) #36)。文字色は制御入力で、当てた色が
そのまま入力の現在値になるため、**いちばん塗り直したい色がいちばん発火しない**という形をしていた。

- **パレットは固定プリセット 24 色 +「その他の色」。** 表は文字色と蛍光で共用する
  ([decisions.md](decisions.md) #46)
- **選んだ瞬間に当たる。** 値を決めてから確定させる二段構えではない(#25 の原則はそのまま)
- **バーが映すのはドラフトで、要素の現在値ではない。** 範囲に当てても要素の computed は変わらないので、
  要素を映すと 3 語塗った瞬間にバーだけ元へ戻る
- **蛍光は要素から seed しない。** 要素に「今の蛍光色」は無く、`background-color` は箱の塗りなので、
  そこから読むと**マーカーが常に箱と同じ色**になる([decisions.md](decisions.md) #45)
- **パレットは portal しない。** パネルの DOM の中に `position: absolute` で開き、幅は行に合わせる。
  セッションの生死・外側クリックの判定・スクロール追従の 3 つが
  「パレットがボタンの子孫であること」に乗っているため([decisions.md](decisions.md) #43 / #44)

### 塗り・枠線の色も同じ部品を使う

**「色を選ぶ」操作は右ペインに 4 つあり、手触りは 1 つでいい。**
塗りと枠線は素の `<input type="color">` のままだったので、同じことをするのに
**OS のダイアログが開く欄と、その場にパレットが開くボタン**が同居していた
([issues](../../issues.md) #101)。`ColorPicker` は部品として独立しているので、載せ替えるだけで揃う。

- **パレットの表(`colorPalette.ts`)は 4 つで共用する。** 24 色 +「その他の色」は同じもの
- **アイコンは行ごとに変える** —— 塗りは中を斜線で埋めた箱、枠線は同じ箱の輪郭だけ(`icons.tsx`)。
  この 2 つは同じペインの 1 パネル違いに並ぶので、**線の太さの違いだけでは 15px で見分けが付かない**
- **パレットに「透明」は入れない。** 塗りの「透明 / 単色」も枠線の「なし」も**種類の選択**で、
  色の一覧に混ぜると文字色・蛍光のパレットと中身が変わる —— 揃えるための変更で揃わなくなる
  ([ideas](../../ideas.md) #12 が残していた判断点への答え)
- **左半分(適用)は塗りでも意味を持つ。** 透明の箱でバーの色を押せば単色になる ——
  「単色」ボタンと同じ宣言を書くので、2 つが食い違うことはない

## 塗り(背景)

「透明 / 単色」の 2 択と色見本で扱う。**種類を先に置くのは、色入力が「塗りなし」を表現できない**ため
([decisions.md](decisions.md) #4)。

- **色を選んだら「単色」に切り替える。** PowerPoint の色メニューと同じで、色を選ぶことは塗りの要求
- **「透明」と「解除」を分ける。** 「透明」は `background-color: transparent` を**上書きとして書く**、
  「解除」は上書きをやめてデッキ本来の見た目に戻す
- **選んだ色はパネル側で覚える。** 既定は白(デッキの多くが濃い色・写真の上に置かれるため)
- **色を選ぶのは分割ボタン**(前節「塗り・枠線の色も同じ部品を使う」)

## 枠線(PowerPoint の「図形の枠線」に相当)

種類(なし / 実線 / 破線 / 点線)・色・太さ(0〜64px)を GUI 化する。

- **`border` ショートハンドを書かない。** ショートハンドは `border-image` まで初期化するため、
  デッキが使っていた場合にユーザーが触っていないものを壊す。3 つのロングハンドを書く
- **どのフィールドを触っても 3 つとも書く。** `border-style` が `none` のままでは色だけ変えても
  何も見えず、デッキ側に枠線指定が無い要素は幅が 0 に計算される
- **「なし」と「解除」を分ける**(塗りと同じ理由)
- **色・太さを触ったら、枠線が無い箱には `solid` を補う**
- **色を選ぶのは分割ボタン**(前々節)。`Field` に `id` は渡さない ——
  中身が `<input>` 1 つではなく `aria-label` を持つボタン 2 つなので、
  `<label for>` はどちらを指しても間違いになる
- 現在値は `border-top-*` から読む。4 辺が異なると computed のショートハンドは
  4 値のリストになり安全に分解できないため

## 見た目に効く値は入力中に反映する

枠線の太さはスライダーと数値入力を並べ、どちらも **input のたびに適用**する。
太さは「見て決める」値なので、Enter を押すまで結果が見えないのでは判断できない。
`tryMerge` により**ドラッグ 1 回・入力 1 回は 1 undo ステップ**に収まる。

**余白・角丸・文字サイズ・位置とサイズも同じ**(見て決める値)。この「打つそばから当たる数値欄」は
`LiveNumberInput`([../../../src/features/LiveNumberInput.tsx](../../../src/features/LiveNumberInput.tsx))
1 部品で、**インスペクタの数値欄はこれしかない**。
最後まで残っていた遅延コミットの `NumberField`(位置とサイズ)は
[issues](../../issues.md) #38 で廃止した(後述)。

`Inspector` が `TextFormatControls` を import している以上、両方が使う部品はどちらに置いても
循環になるので**独立したファイル**に置く(`Field` / `styleValues` と同じ理由。
[decisions.md](decisions.md) #7 / #20)。`parseNumberDraft` も同じ事情で `styleValues.ts` に移した。

**文字サイズに「適用」ボタンは無い**([decisions.md](decisions.md) #25)。
サイズこそ見て決める値で、Enter や確定ボタンを挟むと 1 打ごとに結果が見えない。
`min` は 8、`max` は 200 で、欄の外に `.unit` の `px` を出す(余白・角丸と同じ形)。

## 余白と角丸は「数字だけ」を入れさせる

単位はコントロールの外(`.unit`)に出し、欄には数値だけを入れさせる。
以前は `type="text"` に CSS 値をそのまま書かせていて、`px` を書き忘れると黙って捨てられ、
表示は `10px 20px 10px 20px` になっていた([issues](../../issues.md) #21)。

**読みは辺ごと、書きは 4 辺まとめて。**
`getComputedStyle` にショートハンドを聞くと、辺が違った瞬間に 4 値のリストが返って
1 つの数値欄に入らない。枠線が `border-top-*` を読んでいるのと**同じ理由**なので、
余白も `padding-top` / `right` / `bottom` / `left` を個別に読む。

書くほうは逆に、**触った 1 辺だけでなく必ず 4 辺とも書く**。
`SetInlineStyleCommand.tryMerge` はプロパティ集合が一致したときだけコマンドを畳むので、
触った辺だけを書くと辺を移った瞬間に undo が分裂する([decisions.md](decisions.md) #71)。

**4 辺が揃っていないデッキは、展開した状態で開く。**
1 つの数値欄しか出ていない状態で確定させると、ユーザーが見ていない 3 辺を巻き添えに平らにしてしまう。
揃っている間だけ「一括 ⇄ 辺ごと」を行き来できる。

角丸は**1 つの数値**で、4 隅は分けて扱わない。
読みは `border-top-left-radius`(ショートハンドは `8px 8px 0px 0px` を返しうる)、
書きは `border-radius` ショートハンド 1 つ。

### 読むものと塗るものは別のリスト

`PAINTABLE_PROPERTIES`([core/editing/format.ts](../../../src/core/editing/format.ts))は
Format Painter が**塗る**白リストで、そこではショートハンドのままが正しい。
インスペクタが**読む**ほうは `READ_PROPERTIES` として**そこから派生**させ、
辺ごとのプロパティを足している([decisions.md](decisions.md) #16)。

**`direction` はどちらの派生でもない読み取り専用の 1 件**として `READ_PROPERTIES` に直接足してある。
行揃えの点灯が `start` を物理の側へ直すのに要るが、ブラシに載せると
**見た目を塗るつもりで文字の流れる向きまで運ぶ**([issues](../../issues.md) #32)。

## X / Y / 幅 / 高さは「回転前のレイアウトボックス」を表示する

`boxOf()`([../../../src/stage/geometry.ts](../../../src/stage/geometry.ts))が返す
中心は回転しても動かないので `getBoundingClientRect` から取り、**寸法は回転が変えない
レイアウトボックスから取る**。X / Y はその 2 つから逆算する(`cx - width / 2`)。

寸法の出所は要素の種類で分かれる。

| 要素 | 出所 | 理由 |
|---|---|---|
| HTML 要素 | `offsetWidth` / `offsetHeight` | 回転を含まない実寸がそのまま取れる |
| SVG 要素(挿入した「直線」「矢印」) | `getComputedStyle().width` / `.height` | `offsetWidth` は `HTMLElement` にしか無い |

**`getBoundingClientRect` にフォールバックしてはいけない。** 回転後のバウンディングボックスが
返るので、パネルは 45° の 360px の矢印を 260px と表示する。書きは `style.width` なので、
**表示された数値をそのまま打ち直すだけで図形が縮む**(260 → 表示 190 → …)。
実際に起きた不具合で、経緯は [issues](../../issues.md) #9。

## 位置とサイズも打つそばから当たる

X / Y / 幅 / 高さ / 回転も 1 打鍵ごとにステージへ当たる。スピナーの上下矢印も同じで、
**1 ずつ増やしながら合わせられる**([issues](../../issues.md) #38)。

以前ここだけ blur / Enter まで待っていたのは「座標を 1 文字ごとに適用すると要素が飛び回る」
と考えたためだが、飛び回るのは**打っている本人が見ている**ので困らない。困るのは逆で、
確定するまで結果が見えないと**数値を決められない**(余白・文字サイズと同じ理由。
[issues](../../issues.md) #21 / #26)。

**待つのをやめると、待っていたぶんの仕掛けが丸ごと不要になる。**
遅延コミットの `NumberField` は「blur を起こすのはたいてい別のボックスをクリックした操作で、
その時点では選択がもう切り替わっている」ため、対象の uid と基準値を **focus の瞬間に ref へ退避**
していた(A に入力した数値が B に適用される、という実際に起きた不具合の対策)。
**書き込みがフォーカスを保ったまま終わるなら、その状況自体が起こらない。**
`LiveNumberInput` が枠線の太さで最初からこの問題と無縁だったのと同じ理由で、
退避もセッションも消えた。

数値にならない draft を弾く経路は変わらない(`parseNumberDraft`)。
`Number('')` は `NaN` ではなく **0** なので、NaN で弾く書き方だと空にした瞬間に本物の 0 が入り、
要素がスライドの左上へ飛ぶ([issues](../../issues.md) #10)。`type="number"` は英字も空文字として
返すので同じ経路。**0 は X / Y / 回転として正当な値**なので、falsy では弾かない。

### 機械的な置き換えでは済まなかった 3 点

| | 何が問題か | どうしたか |
| --- | --- | --- |
| **履歴** | 書き込みは `StyleSnapshotCommand` を `alreadyApplied` で積む形。1 打鍵 1 ステップだと Undo が数十回になる | スナップショット側に**名前付きの畳み込み**を足した([editing-engine](../editing-engine/design.md) の「履歴と保存」) |
| **巻き戻し** | 幅・高さは `element.style.width` を直に書き、切り抜き済み画像なら `placement` も動く | 畳んでも `before` は**最初のもの**を残すので、Undo は run の最初の打鍵より前に戻る([issues](../../issues.md) #24 と同じ焼き付きを作らない) |
| **基準値** | 打鍵のたびに要素が動くので、run の最初に測った値を使うと 2 打鍵目が倍動く | `setGeometry` が**毎回その場で測る**([../../../src/core/editing/geometry.ts](../../../src/core/editing/geometry.ts))。パネルは基準値を渡さない |

**書き込みを `core/editing/geometry.ts` へ出したのはそのため。** 測る・書く・履歴に積むの 3 つが
1 か所に必要で、そこはもうパネルの仕事ではない(「ステージ・コマンド・UI の役割をまたがせない」)。
`core/editing/actions.ts` に置くと、切り抜きの `placement` を読むために `crop.ts` を import することになり、
`crop.ts → actions.ts` と循環する。

### 欄が受け取る数と、欄が握っている文字列

- **X / Y / 回転に上下限は無い。** 要素はスライドの外に置けるし、負の角度は逆回り。
  幅・高さだけが下限 1px(`MIN_SIZE`)を持ち、それは `setGeometry` が最終的に守る
- **この 5 つだけ小数を通す**(`whole={false}`)。ほかの欄は px の整数だが、ここは `round()` が
  小数 2 桁まで残した**実測値**を映しているので、打った 22.5° を 23° に丸めると
  欄が自分で表示している値を拒むことになる
- **フォーカスがある間、欄の文字列はユーザーのもの。** 要素は渡された数にいつも落ち着くとは限らず
  (`box-sizing: content-box` の箱に `width: 150px` を書けば padding のぶん太って返る)、
  その答えで焦点のある欄を上書きすると**打っている最中の桁が消える**。blur で同期し直す



## 値の出所を表示する

「インライン / スタイルシート由来 / 編集による上書き」を区別し、「上書きを解除して元に戻す」操作を提供する
(ADR-0004 の非破壊性を UI でも担保)。

## 書式のコピー & 貼り付け(Format Painter)

⌥⌘C で選択中の要素の**見た目だけ**を覚え、⌥⌘V で別の要素に塗る。右クリックメニューにも同じ項目がある。

運ぶのは `PAINTABLE_PROPERTIES`(文字 6 + ボックス 8)の白リストだけで、
**`left` / `top` / `width` / `height` / `position` / `transform` / `display` / `margin` は入れない。**
これがこの機能の全部で、白リストに位置を足した瞬間に「塗ったら動く」道具になる。

roadmap で取り下げた要素のコピー / ペーストが崩れたのは、
元の親から切り離した要素を絶対値で置き直したから。**書式の貼り付けには貼り先が既に在る**ので、
「どこに置くか」という問題そのものが発生しない。

読むのは computed。継承や外部 CSS で付いている値も「見えているとおり」に塗れる。
Undo は `SetInlineStyleGroupCommand` 1 つ(`apply` が書くので `alreadyApplied` は不要)。
貼り先がリストを含むときの配り方は
[要素スコープの上書きは、リストの中まで届かせる](#要素スコープの上書きはリストの中まで届かせる)と同じ
— 白リストの文字側 6 つはすべて継承プロパティなので、遮られていれば降りる。

覚えた書式は**選択を変えても消えない**。持ち場はモジュール変数で、
描画に関わるのはメニュー項目の活性状態だけ。

## 受け入れ条件(EARS 記法)

- WHEN 要素を選択する THE SYSTEM SHALL その要素の位置・サイズ・塗り・枠線・文字を編集できる状態にする
- WHEN インスペクタで値を変える THE SYSTEM SHALL その変更を 1 つの Undo ステップとして記録する
- WHEN 位置・サイズ・回転に数字を打つ THE SYSTEM SHALL 1 打鍵ごとにステージへ反映する
- WHEN スピナーの矢印を押す THE SYSTEM SHALL その場でステージへ反映する
- WHEN 位置とサイズを打ち続ける THE SYSTEM SHALL その run を 1 つの Undo ステップにする
- WHEN その Undo を実行する THE SYSTEM SHALL 打ち始める前の値と、切り抜き画像の placement を戻す
- WHEN 別の欄・別の要素へ移る THE SYSTEM SHALL 新しい Undo ステップを始める
- WHILE 数値欄にフォーカスがある THE SYSTEM SHALL 打っている途中の文字列を実測値で上書きしない
- WHEN 位置とサイズに小数を打つ THE SYSTEM SHALL 整数に丸めずに適用する
- WHEN 値が継承や外部 CSS 由来である THE SYSTEM SHALL その出所を表示する
- WHEN 文字書式のボタンを押す THE SYSTEM SHALL テキストセッションを閉じずに書式を適用する
- IF テキストセッションが開いていない THEN THE SYSTEM SHALL 文字書式を選択要素へのインライン上書きとして適用する
- WHEN 太さ・行揃えを変える THE SYSTEM SHALL セッションの有無によらず選択要素へ適用する
- WHEN 太さのプルダウンをマウスで押す THE SYSTEM SHALL 選べる太さの一覧を開く
- WHEN 文字書式のボタンを押す THE SYSTEM SHALL `mousedown` の既定動作を止めてフレームのフォーカスを保つ
- WHEN リストを含む要素の行揃えを変える THE SYSTEM SHALL 内包する `ul` / `ol` / `li` にも同じ宣言を書く
- WHEN 中央揃え・右揃えにする THE SYSTEM SHALL 行頭記号も行と一緒に寄せる
- IF リストが継承を遮っている THEN THE SYSTEM SHALL 要素へ書いた文字色・サイズ・フォント・太さ・行間をそのノードにも書く
- IF リストが継承を遮っていない THEN THE SYSTEM SHALL リストへ上書きを書かない
- WHEN リストを含む要素に書式を貼り付ける THE SYSTEM SHALL 行揃えと、遮られている宣言をリストの中まで届かせる
- WHEN 箇条書き・番号が当たっている THE SYSTEM SHALL その段落ボタンを点灯させる
- WHEN 行揃えを誰も指定していない要素を選ぶ THE SYSTEM SHALL 文字が寄っている側の行揃えボタンを点灯させる
- IF 書字方向が右から左である THEN THE SYSTEM SHALL 未指定の行揃えを「右」として点灯させる
- THE SYSTEM SHALL 行揃えとして 左 / 中央 / 右 だけを提示する
- IF デッキ自身が両端揃えを宣言している THEN THE SYSTEM SHALL その値を保ったまま、行揃えをどれも点灯させない
- WHEN 選択が別の要素へ移る THE SYSTEM SHALL サイズ・フォント・文字色をその要素の現在値から始める
- THE SYSTEM SHALL 文字色・蛍光・塗り・枠線の色を同じ分割ボタンとパレットで選ばせる
- WHEN 要素を選択する THE SYSTEM SHALL すべてのパネルを列に並べる
- IF 選択した要素が自分の文字を持たない THEN THE SYSTEM SHALL 文字書式パネルを無効にする
- IF 選択した要素がトリミングできず、画像を入れることもできない THEN THE SYSTEM SHALL 画像パネルを無効にする
- IF 選択した要素が画像でも文字を持つ要素でもない THEN THE SYSTEM SHALL 画像パネルに「画像を入れる」を出す
- WHEN 「画像を入れる」を押す THE SYSTEM SHALL 右クリックメニューの「画像を入れる」と同じことをする
- WHEN パネルを無効にする THE SYSTEM SHALL それを畳んだまま列の末尾に置く
- WHEN パネルを無効にする THE SYSTEM SHALL そのパネルの中身を作らない
- WHEN 無効なパネルの見出しを押す THE SYSTEM SHALL 開かず、折りたたみの記憶にも書かない
- WHILE パネルが無効である THE SYSTEM SHALL 折りたたみの記憶を読まずに畳んだ状態を保つ
- WHEN パネルを無効にする THE SYSTEM SHALL 何をすれば使えるようになるかを見出しに添える
- WHEN パネルを無効にする THE SYSTEM SHALL その見出しをキーボードのフォーカス順に残す
- WHEN 要素を選択する THE SYSTEM SHALL その種別でよく使うパネルを先頭に置く
- WHEN 要素を選択する THE SYSTEM SHALL 開いた状態のパネルを 2 枚までにする
- WHEN パネルの見出しを押す THE SYSTEM SHALL そのパネルを開閉する
- WHEN パネルを手で開閉する THE SYSTEM SHALL その状態を次回の起動まで覚える
- IF ユーザーがそのパネルを開閉していない THEN THE SYSTEM SHALL 種別ごとの既定に従う
- WHEN 選択が別の要素へ移る THE SYSTEM SHALL 触っていないパネルの開閉を上書きとして記録しない
- WHILE テキストセッションが開いている THE SYSTEM SHALL 位置とサイズのパネルを無効にする
- WHILE テキストセッションが開いている THE SYSTEM SHALL X / Y / 幅 / 高さの値を画面に出さない
- WHILE テキストセッションが開いている THE SYSTEM SHALL パネルを無効にしたことを折りたたみの記憶に書かない
- WHEN テキストセッション中に太さ・行揃えを変える THE SYSTEM SHALL それまでに打った文字を先に 1 手として記録する
- IF テキストセッションが開いていない THEN THE SYSTEM SHALL 範囲にしか効かないコントロールを無効にする
- IF テキストセッションが開いていない THEN THE SYSTEM SHALL 蛍光だけを無効にし、文字色は使えるままにする
- IF トリミングの枠が開いていない THEN THE SYSTEM SHALL 縦横比・枠に合わせる・元の画像に戻すを無効にする
- WHILE コントロールを無効にしている THE SYSTEM SHALL その理由をヒントと `title` で示す
- WHILE テキストを編集している THE SYSTEM SHALL 本文の上に浮くツールバーを出さない
- WHEN 書式を貼り付ける THE SYSTEM SHALL 貼り先の位置とサイズを変えない
- WHEN 書式を貼り付ける THE SYSTEM SHALL 1 つの Undo ステップとして記録する
- WHEN 右の境界をドラッグする THE SYSTEM SHALL インスペクタの幅を 240–520px の範囲で追従させる
- WHEN 境界のシェブロンを押す THE SYSTEM SHALL インスペクタを隠し、もう一度で元の幅に戻す
- WHILE インスペクタが隠れている THE SYSTEM SHALL 戻すためのシェブロンを窓の内側に見せ続ける
- WHEN 行のラベルや余白を押す THE SYSTEM SHALL その行のボタン・色見本を押さない
- WHEN コントロールが 1 つの行でラベルを押す THE SYSTEM SHALL そのコントロールへフォーカスを移す
- WHEN 入力欄の右の余白を押す THE SYSTEM SHALL その入力欄からフォーカスを外す
- WHEN 文字色・蛍光の左ボタンを押す THE SYSTEM SHALL パレットを開かずにバーが示す色を適用する
- WHEN 同じ色を続けて別の範囲に当てる THE SYSTEM SHALL 2 回目も適用する
- WHEN ▼ を押す THE SYSTEM SHALL その場にパレットを開き、OS のダイアログを出さない
- WHILE パレットが開いている THE SYSTEM SHALL テキストセッションを閉じない
- WHEN パレットで色を選ぶ THE SYSTEM SHALL 即座に適用し、以後その左ボタンをその色にする
- WHILE インスペクタがどの幅であっても THE SYSTEM SHALL パレットをペインの中に収める
