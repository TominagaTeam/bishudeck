## Phase 3 で取り下げたもの

### 要素のコピー / ペースト(F13 のうち要素分) —— 2026-08-26 に復活させた

貼り付け先をスライドルート直下に固定していたため、元の親から切り離された要素 —
flex / grid のセル、`.container .card` のような子孫セレクタで塗られていた箱 — が
崩れた見た目で現れていた。位置も transform に +16px 足すだけで、元が静的配置なら
まるで違う場所に出る。

**2026-08-26 に、先に決めるべきだった「どこに貼るか」を決めて戻した。**
規則は 2 段で、**選択があればその要素の次の兄弟**(＝同じ親。親に効いていた CSS が
そのまま当たる)、**選択が無ければスライドルート直下**。どちらになるかは押した時点の
選択で決まるので、選ぶのはユーザーになる。ずらすのは**要素が自分で位置を持ち、
かつその場所にまだ何か居るとき**だけ ——
[features/editing-engine/design.md](features/editing-engine/design.md) の
「要素のコピー / 切り取り / 貼り付け」が正、判断の経緯は
[features/editing-engine/decisions.md](features/editing-engine/decisions.md) #106〜#108。

## 主要リスクと対応方針

| リスク | 対応 |
| --- | --- |
| デッキの JS がスライド index で挙動を分岐する(N 枚目だけアニメを回す等) | プレビュー/再生では他スライドの空プレースホルダを並べて index を再現し、デッキ自身のナビ(→ キー)で目的スライドへ移動させる。到達できなければ足場を撤去して単一スライド表示にフォールバック |
| JS が動的生成する DOM は編集モードに現れない(グラフ等) | 編集対象は「静的 HTML」と割り切る。動的要素はプレビューで確認、必要なら「実行結果を静的化して取り込む」機能を将来検討 |
| 拡大表示(100% 超)ではスライドの一部に手が届かない | `.canvas` が `overflow: hidden` なのでパンの導入はスクロール土台の作り直しになる。当面はズーム段階で回避し、[ideas](ideas.md) #1 で追う |
| flex / grid 内要素のドラッグ移動が直感に反する(translate はレイアウトを崩さない代わりに兄弟が動かない) | v1 は translate 方式で統一し、インスペクタに「レイアウト内で移動(DOM 順変更)」を別操作として用意 |
| 巨大 CSS / スライド数での性能劣化 | 編集 iframe は常に 1 枚のみ。サムネイルはスナップショットキャッシュ |
| スライド分割の誤検出 | 検出結果を必ずプレビュー確認 UI に通す。手動セレクタ指定をフォールバックに |
| ランタイムを捨てた Artifacts デッキで、ランタイムが埋めるはずだった箇所が失われる(`{{ 変数 }}`・`<image-slot>` の写真枠) | 取り込み時にランタイムの出力を静的な HTML へ畳む。`{{ 変数 }}` は宣言された既定値に、写真枠は同じ見た目のプレースホルダになり、どちらも普通の要素として編集できる。**写真枠は「空要素として残る」のではなく不可視だった**(ボックスを持たない未知要素)ので、ここは静的化しないと選択すらできない。値を決めるのは引き続きユーザー — 宣言の無い変数は消さずに `{{ }}` のまま見せる |
| WebView 差(macOS WKWebView / Windows WebView2)による表示差 | 忠実性の基準は「実行環境の WebView」と定義。**CI(typecheck / test)は入れたが、Linux の runner では WebView 差を再現できない**ので、スクリーンショット回帰は引き続き将来課題 |
| 実ブラウザでしか見えない不具合(iframe 境界・実マウス操作・レイアウト計算・フォーカス移動)を自動では拾えない | smoke(E2E)を廃止し、その範囲は手で触って確かめる([ADR-0009](adr/0009-drop-smoke-e2e.md))。unit は jsdom なのでここを見ない。ブランチを渡す前に手で触る 1 周を欠かさない([ADR-0008](adr/0008-handoff-before-docs.md))。**2026-08-25 に現実になった** — WKWebView と Chromium でキーイベントの届き方が違う件は**もう起きている**ので [issues](issues.md) #89 に残した(**許容**として決着) |
| 他人のレイアウトから切り離した要素は、貼り付け先では別物になる(flex / grid のセル、`.card` のような子孫セレクタ) | **切り離さない**。貼り付けは選択した要素の次の兄弟に挿し(＝同じ親)、複製(⌘D)と Alt ドラッグも同じ規則。切り離される経路は「選択が無いときのスライドルート直下」だけで、そこはユーザーが選択を外して選ぶ(上記) |

## 一般公開に向けて足りないもの

[01-overview](basic-design/01-overview.md) で**一般公開を目指す**と確定し(2026-08-23)、
**形態をソース公開に確定した**(2026-08-29、[ADR-0012](adr/0012-mirror-to-public-repo.md))
ことで立ち上がったもの。**どれもまだ起きていない**(公開リポをまだ作っていないため)ので、
[issues](issues.md) ではなくここで追う([ADR-0007](adr/0007-issues-md-and-task-file-rule.md))。

| リスク | 対応方針 |
| --- | --- |
| **公開リポに来た PR を直接マージできない** | ミラーは一方向で、次のリリースで作業ツリーごと上書きされる([ADR-0012](adr/0012-mirror-to-public-repo.md))。受け取ったら開発リポ側で取り込み直す。**`CONTRIBUTING.md` にその旨を書くまでは、外から見て理由が分からない** —— 公開直後に書く |
| **ミラーを忘れると公開側が古びる** | `scripts/mirror.sh` は tag を引数に取るので、**リリース tag を打つ手順そのものに組み込む**。ミラー漏れは「公開リポの最新コミット名 = 最新 tag 名」を見れば分かる |
| **未署名のバイナリが OS に弾かれる** | **ソース公開のうちは起きない**(バイナリを配らないため)。配る日に立ち上がる課題として残す。macOS は Gatekeeper、Windows は SmartScreen。証明書の取得(Apple Developer / EV or OV 証明書)と CI での署名・公証のパイプラインがセットで要る |
| **更新を届ける手段が無い** | 同上。`tauri-plugin-updater` は未設定で、署名鍵の管理が前提になるので、署名と同時に決める |
| **取り込んだ HTML に機密が含まれうる** | 公開ツールになるほど効く。**外部送信の経路を作らない**という現状の方針([rules/development](rules/development.md) §7)を維持する。クラッシュレポートや利用統計を入れたくなったときが分岐点で、入れるなら「デッキの中身は絶対に載せない」を設計条件にする。報告用に実 HTML を送ってもらうときの注意は [SECURITY.md](../SECURITY.md) にも書いた |
| **UI 文言がすべて日本語** | [issues](issues.md) #15 で追う(**もう起きている**ため、こちらではない)。README・docs も日本語のみで、英語の入口はまだ無い |
