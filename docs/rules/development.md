# 開発ルール

Bishudeck の開発における取り決め。**コードを変更する前に必ずこのファイルを読むこと。**

ドキュメントの地図は [../INDEX.md](../INDEX.md)。
関連文書: [README.md](../../README.md)(使い方) / [../basic-design/](../basic-design/)(基本設計) / [../roadmap.md](../roadmap.md)(Phase 進捗)

---

## 0. 最優先の 3 原則

1. **他人の HTML を壊さない** — このアプリの価値は「エディタが解釈できない CSS・JS・要素も、触らなければ壊れない」こと。迷ったら手を加えない側に倒す
2. **変更したら検証する** — 「動くはず」で終わらせない。数値かスクリーンショットで確認する
3. **変更したらドキュメントも直す** — 実装とドキュメントの食い違いは不具合として扱う

---

## 1. 作業フロー

**単位は課題 1 件ではなくブランチ 1 本。** 関連する課題(同じ画面・同じ機能)を**最大 5 件**まとめて 1 本にし、
手で触ってもらうのを 1 周にまとめる([ADR-0008](../adr/0008-handoff-before-docs.md))。

| # | 手順 | 内容 |
|---|---|---|
| 1 | ルール確認 | [../INDEX.md](../INDEX.md) から関連ドキュメントを開く。このファイルと [ADR-0001〜0004](../adr/) は必ず読む(0005 は保留) |
| 2 | 設計書の用意 | 触る機能の `docs/features/<機能名>/` が無ければ**先に作る**(`_template/` から。§3) |
| 3 | 実装 | §4 の不変条件を壊していないか意識しながら書く。**コミットは課題ごとに分ける**(束ねるのはブランチだけ。1 件だけ差し戻せるように) |
| 4 | 検証 | §2 の必須コマンドを通す。振る舞いが変わる変更には回帰テストを追加する。UI を触ったなら §2 の表を引いて該当箇所を手で確認する |
| 5 | 設計書の更新 | 触る前に必要な分 —— 触った機能の `design.md` —— を実装コミットに含める |
| 6 | **手で触ってもらう** | dev server を**起動した状態**で、触る箇所と手順を添えて渡す |
| 7 | 記録の更新 | OK が出てから [../issues.md](../issues.md) / [../roadmap.md](../roadmap.md) / `decisions.md` をまとめて 1 コミット |
| 8 | マージ | 7 まで終わってから |

**手順 7 を飛ばしてマージしない。** 緩めたのは**タイミングだけ**で、マージの条件からは外していない。
master に入る時点で、設計書・issues・roadmap が実態に合っていること。
1 件だけ差し戻すときは、**その課題の issues.md の行も戻す**。

## 2. 検証

### 必須コマンド

```bash
npm run typecheck                   # 型。必ず通す
npm test                            # Vitest。必ず通す
cd src-tauri && cargo test          # Rust 側を触ったら必ず
```

**自動で見えるのはここまで。** E2E(smoke)は **2026-08-25 に廃止した**
([ADR-0009](../adr/0009-drop-smoke-e2e.md))。結局は手で触って合否を決めていたため。
引き換えに、**実ブラウザでしか見えない範囲 —— iframe 境界の実挙動・実マウスのジェスチャ・
レイアウトの実寸・フォーカスの移動 —— が自動検証から外れた**。
Vitest は jsdom なので矩形はすべて 0 で、クリックしてもフォーカスは動かない。
そこは**手で確認するしかない**。

### 手で確認する

UI を触ったら `npm run tauri dev` で起動し、下の表から該当する行を引いて自分で触る。
「HTML を取り込む」で `samples/generic-deck.html` を読み込めば一通り試せる。

この表は**廃止した E2E が実際に見ていた対象**を移したもの。
何を見るべきかの**チェックリスト**として使う。

| 触ったもの | 手で確かめること |
|---|---|
| 位置・サイズ・回転・吸着 | ドラッグでの移動・リサイズ・回転ハンドル・他要素への吸着。**重なった要素は Alt+クリック(と右クリックの「この位置にあるもの」)で選べるか**、**要素をカードやスライドの外へドラッグしても端で止まって見えたままか**、**選んだあと選択枠の辺を掴んで動かせるか**、**Alt ドラッグは従来どおり複製するか** |
| 文字色・蛍光 | 範囲を選んで当てる。**パレットを開かずに 2 つ目の範囲へ同じ色を当てる**経路も通す |
| フォント・太さ・行揃え・箇条書き | 要素全体(「テキスト」)と選択範囲(「文字書式」)の両方。この環境に無い書体が一覧に出ていないか |
| 枠線・背景・余白・角丸・文字サイズ | スライダーと数値入力がその場で反映されるか。打っているあいだの変更がまとめて 1 回の Undo で戻るか |
| ペイン・スライド一覧 | 幅のドラッグ・シェブロンでの開閉・次回起動時に幅と開閉が残るか |
| インスペクタのパネル | 並びと折りたたみ。畳んだ状態が次回に残るか |
| 画像のトリミング | グリップの操作。書き出して読み直すと同じ状態に戻るか |
| 箱への画像挿入 | 写真枠(取り込んだデッキの破線の箱)を**クリック 1 回で選べるか**、**右クリックの「画像を入れる」でファイル選択が開くか**(**ダブルクリックでは開かないこと**も見る)、**画像ファイルを落として入るか**。**ドロップは Tauri のネイティブイベントなので、ブラウザでは動かない**([ADR-0011](../adr/0011-native-file-drop.md))——`npm run tauri dev` でしか確かめられない |
| ショートカット・ダイアログ | キー操作・ショートカット一覧・Mac / Windows のタブ切替。**⌘C / ⌘X / ⌘V が WebView のネイティブ動作に食われず要素に効くか**、**文字編集中は従来どおり文字のコピー / 貼り付けのままか** |
| 再生 | ページ送り(←/→・クリック)・Esc での終了・キーが効き続けるか |
| 背景レイヤーのあるデッキ | 背景の合成とパンくず。`inset:0` の空 `div` や四辺からわずかに内側のラッパーを掴まずに、中身が選べるか |
| 取り込み・分割・保存・サムネイル | **基本パス。どこを触っても最後に 1 周する** |
| 実 HTML | 手元の実デッキを取り込んで、検出・分割・可視性・サムネイル収まりを見る。**厄介なパターンは実物にしか出てこない** |

2 つ以上の行にまたがる変更なら、**両方とも触る**。片方に寄せると見ていない経路ができる。
もっと細かい粒度は、その機能の `test.md` の **`手動` の行**にある
([08-test-policy](../basic-design/08-test-policy.md))。

**必ず実ウィンドウ(`npm run tauri dev`)で見る。** Chrome で動くことは
WKWebView で動くことを意味しない —— WebKit はスクリプト無効の document では
親フレームから張ったリスナすら発火させないので、**ブラウザで通って実アプリで壊れる**経路がある
([features/editing-engine](../features/editing-engine/design.md) の「インライン編集の抜け方」)。
`slides://` を WKWebView が sandbox iframe で読めるかも、実ウィンドウでしか確認できない。

**typecheck / test / cargo test は省略できない。** そのうえで、
**手で確認した範囲と、していない範囲を報告に書く。**
自動テストが緑なことは、実ブラウザで壊れていないことの証明にならない。

### テストを追加する基準

**正は [../basic-design/08-test-policy.md](../basic-design/08-test-policy.md)**(何をどこまでテストするか)。
座標計算・文字列の生成解析・外部由来データ・Undo/Redo・**一度でも不具合を出した箇所**には
必ず回帰テストを追加する。

### 目視だけで終わらせない

「画面を見て正しそう」で判断しない。**数値で表明する**こと。

このプロジェクトで実際に起きた例(smoke があった頃の記録も含む。手で確認する今も教訓は同じ):

- 削除を Undo すると要素は戻るが**選択が戻っていなかった**。オーバーレイが出ないので気付きにくく、
  後続の smoke(回転ハンドル・選択枠)がまとめて落ちて初めて分かった
  → `HtmlSnapshotCommand` が選択も復元するようにし、Vitest と smoke の両方で検証
- smoke の吸着テストが **shift を押しながらドラッグ**していた。当時の shift は「吸着オフ」かつ
  「押下時は追加選択」だったので、そもそも移動していないのに「ずれ 400px」としか出ていなかった
  → テストの意図と実装の意味が食い違っていた例。**落ちたら実装を疑う前にテストの前提を疑う**
    (追加選択はその後廃止し、shift はジェスチャ中の修飾キーだけになった)
- スライドサイズ変更後の選択テストが、見出しの中央 = 図形が重なる座標をクリックしていて、
  実際には「クリックしたものが選択されている」ことを検証できていなかった
  → 選択枠の矩形と対象要素の矩形を突き合わせる形に変え、意味のある検証にした
- 4 枚目だけアニメが出ないデッキ。原因は**デッキの JS が自分のスライド index で分岐**していたこと
  → 合成結果を headless Chrome で実描画してスクリーンショットで確認する、が唯一の判定手段だった

### 新機能・未文書化機能に着手するとき

**AI が自律的に `docs/features/<機能名>/` を作る**(ユーザーのコマンド実行を待たない)。

1. `docs/features/_template/` をコピーして機能名で展開し、プレースホルダを置換する
2. 会話・既存ドキュメント・コードから分かる範囲を埋め、決めきれない点(受け入れ条件など)だけユーザーに確認する。
   **推測のまま実装に進まない**
3. `docs/INDEX.md` の機能一覧に行を追加する(「📋 未文書化」だった行はここで置き換える)

既存機能の実装に手を入れるときも、対応する `docs/features/<機能名>/` が無ければ同じ手順で先に作る。

### ズレを見つけたら、黙って直さず報告する

**ドキュメントと実装が食い違っていたら、どちらが正かをユーザーに確認する**
([ADR-0006](../adr/0006-docs-driven-migration.md) 裁定 4)。

自分で設計書のほうを直してはいけない。**実装側のバグを設計書に追認してしまう**ため。
「実装のバグ」なのか「設計の変更が反映されていないだけ」なのかは、コードからは決まらない。

### SSOT — 同じ事実を 2 箇所に書かない

記載場所に迷ったら [../INDEX.md](../INDEX.md) の分類に従い、他の場所からは参照リンクにする。
重複を見つけたら「正の場所」を決めて片方をリンク化する。

### アイデアは捨てない

会話で出た「いつかやりたい」「こうできたら」は [../ideas.md](../ideas.md) に書き留める。
やる / やらないが決まったら状態を更新する。

### 実装が積み重なったら doctor を提案する

機能追加や大きめの変更が数回続いたら、ユーザーに `/docs-init doctor`(ドリフト検査)の実行を提案する。

### 書き方の原則

- **何をしたか だけでなく なぜそうしたか を書く。** 特に「他の選択肢を採らなかった理由」は将来の自分と他人を救う
- 数値・上限・既定値は具体的に書く(「しばらく待つ」ではなく「アイドル 2 秒」「250ms 後に判定」)
- ドキュメントを更新したら frontmatter の `updated:` も直す

## 4. 設計上の不変条件(壊してはいけない約束)

変更時にこれらを壊していないか必ず確認する。根拠は [ADR-0001〜0004](../adr/)。

| # | 約束 | 破ると何が起きるか |
|---|---|---|
| 1 | **スライドの正データは HTML 文字列**。独自 JSON モデルに変換しない([ADR-0001](../adr/0001-html-as-source-of-truth.md)) | エディタが解釈できない CSS・JS・要素が往復で消える |
| 2 | **書き出した HTML を壊さない**。エディタ由来のものが残ること自体は許すが、①見た目と挙動を変えない ②読み直すと同じプロジェクトに戻る(往復が固定点。開くたびに増えるものは不可) ③デッキ自身の CSS / JS の当たり方を変えない、の 3 つを満たすこと([import-pipeline](../features/import-pipeline/design.md)) | 書き出した HTML が別物になる、または保存のたびに太る |
| 3 | **編集モードで JS を実行しない**(`sandbox` に `allow-scripts` を付けない)([ADR-0002](../adr/0002-edit-preview-separation.md)) | 自分で書き換わる DOM を手で編集することになり、編集結果が壊れる |
| 4 | **プレビューに `allow-same-origin` を付けない**。`slides://` の別オリジンで配信する | デッキの JS からアプリ本体・Tauri IPC に到達できてしまう |
| 5 | **すべての変更は Command 経由**。DOM を先に触るジェスチャも `alreadyApplied: true` で履歴に載せる([ADR-0003](../adr/0003-all-edits-as-commands.md)) | Undo で戻せない操作ができる。プラグイン・AI 連携の継ぎ目も失われる |
| 6 | **要素は uid で指す**。DOM 参照を保持しない | Undo 後・再読込後に対象を見失う |
| 7 | **iframe の DOM に触るのは StageBridge だけ** | 触り方が散らばり、シリアライズ時の掃除漏れが起きる |
| 8 | **スタイル編集はインラインの上書き**。元の CSS を書き換えない([ADR-0004](../adr/0004-style-edits-as-overrides.md)) | flex / grid / absolute が混在した AI 生成レイアウトが崩れる |
| 9 | **Rust 側は HTML を解釈しない** | HTML の知識が二重実装になり、WebView 側とズレる |
| 10 | **自作 Rust コマンドの `invoke` は `src/shared/backend.ts` に集約する** | バックエンド境界が曖昧になり、どこから Rust を呼んでいるか追えなくなる(境界ごと差し替えることもできなくなる) |
| 11 | **プラグイン API(dialog / window)を直接使う場合は Tauri の外で動かないケースを塞ぐ** — `getCurrentWindow()` は素のブラウザでは例外になる | Tauri ウィンドウの外で開いた瞬間、アプリ本体の初期化ごと落ちる |
| 12 | **保存は一時ファイル経由の atomic rename**。自動保存も同じ経路 | 書き込み中の中断で直前の版まで失う |
| 13 | **連続ジェスチャは 1 undo ステップ**(`tryMerge` / gesture 終了時に 1 コマンド) | ドラッグ 1 回で履歴が埋まる |
| 14 | **プレビュー合成の足場(プレースホルダ・ナビ注入)は preview モード限定** | 編集ステージや書き出し HTML に空スライドとスクリプトが混入する |
| 15 | **エディタが描く選択枠・ハンドルはステージの外(ホスト側)に描く** | オーバーレイが書き出し HTML に混ざる |
| 16 | **再生ウィンドウを `close()` しない**。終了は simple fullscreen 解除 + hide、再生は show + `present:start` イベント([04-architecture](../basic-design/04-architecture.md)) | WebView 破棄のレースでアプリごと SIGSEGV で落ちる。ネイティブ fullscreen だと退出アニメーションの途中で hide が滑り、空のウィンドウが残る |
| 17 | **simple fullscreen のあとに webview へ first responder を返す**。再生ウィンドウ自身が `focus_presentation_webview` を invoke する([04-architecture](../basic-design/04-architecture.md)) | styleMask の切り替えで first responder が tao の `ns_view` に移り、再生ウィンドウが `keydown` を受け取らなくなる。←/→/Esc が全部無反応になり警告音が鳴る |
| 18 | **再生中はステージの上にクリックシールドを敷く**([04-architecture](../basic-design/04-architecture.md)) | クリックでフォーカスが別オリジンの iframe に落ち、そこから先はキーがホストに届かない(不変条件 17 と同じ症状) |
| 19 | **デッキ自身のプレゼンランタイム(`shared.deckRuntime`)は書き出しにだけ戻す**([import-pipeline](../features/import-pipeline/design.md)) | 編集・プレビューで動かすと、キャンバスの上にデッキ側のサムネイルレールと 1 枚表示が重なる |
| 20 | **ウィンドウ / webview を触る Rust コマンドは `async fn` にする**([04-architecture](../basic-design/04-architecture.md)) | Windows では invoke が WebView2 のイベントハンドラで走り、同期コマンドがそこから WebView2 を呼び直して再入・停止する。再生ボタンでデッキが固まり、キーもマウスも効かなくなる。**macOS では同期でも動くので気づけない** |

不変条件 2 の判定は「エディタ由来かどうか」ではなく上の 3 条件で行う。

- **スライド markup の中身はこれまでどおり完全除去**。`data-hse-uid` は要素の数だけ増えるうえ
  `[data-*]` セレクタや `:nth-child` の当たり方を変え、`contenteditable` は開いた人の
  ブラウザでページが編集できてしまい、ステージが足したクラスは全スライドを同時に表示させる。
  ①③ を満たさないので `cleanElement`(`stage/bridge.ts`)を必ず通す
- **共有 head に差し込む足場は残してよい**。ランタイムを持たない deck-stage デッキでは
  この CSS が無いとスライドが潰れるので、そもそも消せない。②のために
  `data-hse-injected` の印を付け、取り込み時に前回分を外してから書き直す([import-pipeline](../features/import-pipeline/design.md))

## 5. コーディング規約

- **ソースコードのコメントは英語**、**ドキュメント・コミットメッセージは日本語**。既存ファイルがそうなっている
- **UI 文言はコードに直接書かない。** `t('key')` でカタログから引く
  ([features/i18n](../features/i18n/design.md))。日本語の文面は `src/shared/i18n/ja.ts` に集める。
  **カタログに無いキーはコンパイルが通らない**ので、綴りの保証はそこでしている。
  例外は**固有名詞**(書体名)と**測定用の文字列**(`PROBE_TEXT` / `TYPING_HEADROOM`)で、
  訳すと意味を失うか機能が壊れる
- **文面を `+` や テンプレートリテラルで組み立てない。** `{name}` の補間を使う。
  `` `${label}を挿入` `` のような連結は語順を日本語に固定してしまう
- コメントは「何をしているか」ではなく**「なぜそうしているか」**を書く。特に**他の実装を選ばなかった理由**
- 既存ファイルの書き方(命名、コメント密度、構造)に合わせる。自分の好みを持ち込まない
- 型は `strict` 前提。`any` を使わない。`as` での握りつぶしを避ける
- 定数はマジックナンバーにせず名前を付け、ファイル先頭にまとめる(`AUTOSAVE_IDLE_MS`、`NAVIGATION_SETTLE_MS` など)
- 1 ファイル 1 責務。ステージ・コマンド・UI の役割をまたがせない

### ファイルの置き場所

**正は [../basic-design/05-directory.md](../basic-design/05-directory.md)。**
新しいファイルは「配置ルール」表に従って置き、import の向きは同じ章の「依存方向」に従う。

## 6. 依存関係の追加基準

依存は簡単に増やさない。現状はフロントが React + zustand + Tauri プラグインのみで足りている。

1. **本当に必要か** — 数十行で自作できるなら自作する
2. **サイズを確認する** — `npm view <pkg> dist.unpackedSize`
3. **保守されているか** — 最終更新、Issue の状況
4. **ライセンス** — 商用配布可能か
5. **HTML を解釈するライブラリは特に慎重に** — AD-1 の「解釈しないものは壊さない」を破りやすい

## 7. セキュリティ

- **プレビュー/再生は `slides://` の別オリジン**で配信し、`sandbox="allow-scripts"` のみを与える。`allow-same-origin` を足さない
- **編集ステージは `srcdoc` + `allow-same-origin`** で、`allow-scripts` を**与えない**。この 2 つの組み合わせを入れ替えない
- CSP は `src-tauri/tauri.conf.json` に定義する。`frame-src` に `slides:` が要る。緩めるときは理由を [../basic-design/10-security.md](../basic-design/10-security.md) に残す
- 取り込んだ HTML は**信用しない**。編集モードではスクリプトを無効化した状態で扱う
- 秘密情報はこのアプリでは扱わない。将来 AI 連携で API キーを持つ場合は**レンダラに置かず Rust 側で保持する**
- 不具合報告用に実 HTML を共有するときは、中身に機密が入っていないか確認する

## 8. バージョン管理

- 着手前に **`git pull` してからブランチを切る**(main/master の上に直接積まない)
- コミットは意味のある単位で。**実装・テスト・ドキュメントは同じコミットに含める**(§3)
- メッセージは**日本語 50 字以内の要約**を 1 行目に書く(例: `画像のトリミングを PowerPoint 風に追加した`)。
  `feat:` のような **prefix は付けない**([ADR-0006](../adr/0006-docs-driven-migration.md) 裁定 6)
- 本文には**なぜその変更が必要だったか**を書く。何をしたかは diff が語る
- コミットしてはいけないもの: `node_modules/` `dist/` `src-tauri/target/`、
  手で確認したときのスクリーンショット、ビルドが通らない中途半端な状態、機密情報
- バージョンは `package.json` / `src-tauri/Cargo.toml` / `src-tauri/tauri.conf.json` の 3 箇所にある。**上げるときは 3 つとも変える**
- **リリース tag を打ったら公開リポへ写すまでが 1 セット。** `git tag -a vX.Y.Z` の直後に
  `./scripts/mirror.sh vX.Y.Z ../bishudeck` を走らせ、できたコミットの中身を確かめてから
  公開リポで `git push origin main` する。写すのは `git archive` の出力(その tag で追跡されて
  いるファイルだけ)なので、`.gitignore` が効いた結果がそのまま公開側になる。
  **スクリプトは push しない** —— 公開は取り消せないので、押す判断は人が握る
  ([ADR-0012](../adr/0012-mirror-to-public-repo.md))
- **写し忘れは外からしか見えない。** 公開側の最新コミット名は tag 名そのものなので、
  [TominagaTeam/bishudeck](https://github.com/TominagaTeam/bishudeck) の最新コミットと
  手元の最新 tag を突き合わせれば分かる
- 公開リポに来た PR は**直接マージできない**(次のミラーで作業ツリーごと上書きされる)。
  受け取ったらこちらで取り込み直す
